# Qdrant, 벡터 데이터베이스 소개

벡터 데이터베이스는 딥러닝 아키텍처와 같은 불투명한 머신러닝 모델에서 파생된 추상적 데이터 표현과 상호작용하는 비교적 새로운 방식
- 이러한 표현은 종종 벡터 또는 임베딩이라고 불리며, 감정 분석, 음성 인식, 객체 감지 등의 작업을 수행하기 위해 머신러닝 모델을 훈련시키는 데 사용된 데이터의 압축 버전입니다.
- 이러한 새로운 데이터베이스는 시맨틱 검색 및 추천 시스템과 같은 많은 응용 분야에서 빛을 발하며, 
- 여기서는 시장에서 가장 인기 있고 빠르게 성장하는 벡터 데이터베이스 중 하나인 Qdrant에 대해 알아보겠습니다.

## Qdrant란 무엇인가?

- Qdrant는 "추가 페이로드가 있는 포인트(즉, 벡터)를 저장, 검색 및 관리할 수 있는 편리한 API를 제공하는 프로덕션 준비가 된 서비스를 제공하는 벡터 유사성 검색 엔진"입니다. 
- Qdrant의 추가 페이로드(Payload)란?
  - 벡터 데이터와 함께 저장할 수 있는 메타데이터예요.  

```json
{
    "id": 1,
    "vector": [0.1, 0.2, 0.3, ...],
    "payload": {
        "title": "제품명",
        "category": "전자기기",
        "price": 50000,
        "tags": ["스마트폰", "가전"]
    }
}
```

- Python qdrant-client를 사용하거나, 최신 qdrant 도커 이미지를 가져와 로컬에서 연결하거나, 전체 전환을 준비할 때까지 Qdrant의 클라우드 무료 티어 옵션을 시도하여 Qdrant를 시작할 수 있습니다.

## 벡터 데이터베이스란 무엇인가?

- 벡터 데이터베이스(Vector Database)는 고차원 벡터 데이터를 저장하고 유사한 벡터를 빠르게 검색하는 데이터베이스예요. AI, 머신러닝, 추천 시스템, 검색 엔진 등에서 사용돼요.

1.벡터 데이터베이스가 필요한 이유
- 기존 관계형 데이터베이스(SQL)나 NoSQL은 텍스트나 숫자 기반 검색에 최적화되어 있지만, 이미지, 오디오, 자연어 데이터 같은 비정형 데이터를 빠르게 검색하는 데는 한계가 있어요.
- ✅ 벡터 데이터베이스는 이런 비정형 데이터를 벡터(고차원 수치)로 변환하고, 유사한 벡터를 빠르게 찾는 데 특화돼 있어요.
- 예제
  - 텍스트 검색 → “강아지”와 비슷한 의미의 단어(예: “귀여운 반려견”) 검색
  - 이미지 검색 → 특정 사진과 유사한 이미지 찾기
  - 추천 시스템 → 사용자의 취향과 유사한 상품 추천


벡터 데이터베이스는 고차원 벡터를 효율적으로 저장하고 쿼리하도록 설계된 데이터베이스 유형입니다. 
- 전통적인 OLTP 및 OLAP 데이터베이스(위 이미지 참조)에서는 데이터가 행과 열(이를 테이블이라고 함)로 구성되며, 쿼리는 해당 열의 값을 기반으로 수행됩니다. 
- 그러나 이미지 인식, 자연어 처리, 추천 시스템 등의 특정 응용 프로그램에서 데이터는 종종 고차원 공간의 벡터로 표현되며, 
- 이러한 벡터와 ID 및 페이로드는 Qdrant와 같은 벡터 데이터베이스 내에서 컬렉션이라고 불리는 것에 저장되는 요소입니다.

이 맥락에서 벡터는 객체 또는 데이터 포인트의 수학적 표현으로, 벡터의 요소는 암시적으로 또는 명시적으로 해당 객체의 특정 특징이나 속성에 해당합니다. 
- 예를 들어, 이미지 인식 시스템에서 벡터는 이미지를 나타낼 수 있으며, 벡터의 각 요소는 픽셀 값이나 해당 픽셀의 설명자/특성을 나타냅니다. 
- 음악 추천 시스템에서는 각 벡터가 노래를 나타내고, 벡터의 요소는 템포, 장르, 가사 등과 같은 노래 특성을 캡처합니다.

벡터 데이터베이스는 이러한 고차원 벡터를 효율적으로 저장하고 쿼리하는 데 최적화되어 있으며,
- 종종 계층적 탐색 가능한 작은 세계(HNSW) - 근사 최근접 이웃을 구현하는 데 사용됨 - 및 제품 양자화와 같은 특수 데이터 구조 및 색인 기술을 사용합니다.  
- 이러한 데이터베이스는 빠른 유사성 및 의미 검색을 가능하게 하는 동시에 사용자가 일부 거리 측정을 기반으로 주어진 쿼리 벡터에 가장 가까운 벡터를 찾을 수 있게 합니다. 가
- 장 일반적으로 사용되는 거리 측정은 유클리드 거리, 코사인 유사도 및 닷 프로덕트이며, 이 세 가지는 Qdrant에서 완전히 지원됩니다.

세 가지에 대한 간략한 개요는 다음과 같습니다:

- **코사인 유사도** - 코사인 유사도는 두 벡터가 얼마나 유사한지 측정하는 방법입니다. 
- 간단히 말해, 벡터가 동일한 방향(유사)을 가지고 있는지 또는 정반대인지를 반영합니다. 
- 코사인 유사도는 종종 텍스트 표현과 함께 사용되어 두 문서나 문장이 서로 얼마나 유사한지 비교합니다. 
- 코사인 유사도의 출력 범위는 -1에서 1까지로, -1은 두 벡터가 완전히 다름을 의미하고, 1은 최대 유사성을 나타냅니다.

- **닷 프로덕트** - 닷 프로덕트 유사도 측정은 두 벡터가 얼마나 유사한지 측정하는 또 다른 방법입니다. 
- 코사인 유사도와 달리, 벡터의 길이도 고려합니다. 예를 들어, 문서의 벡터 표현이 용어(단어) 빈도를 기반으로 구축된 경우 이것이 중요할 수 있습니다. 
- 닷 프로덕트 유사도는 두 벡터의 각 값을 곱한 다음 그 곱의 합을 계산하여 계산됩니다. 합이 높을수록 두 벡터는 더 유사합니다. 
- 벡터를 정규화하면(벡터 내의 숫자 합이 1이 되도록), 닷 프로덕트 유사도는 코사인 유사도가 됩니다.

- **유클리드 거리** 
- 유클리드 거리는 우리가 지도에서 두 장소 사이의 거리를 측정하는 방식과 유사하게, 공간에서 두 점 사이의 거리를 측정하는 방법입니다. 
- 이는 두 점의 좌표 간의 제곱된 차이의 합의 제곱근을 구하여 계산됩니다. 
- 이 거리 측정은 또한 머신러닝에서 두 벡터가 얼마나 유사하거나 다른지 측정하는 데 일반적으로 사용됩니다.

이제 벡터 데이터베이스가 무엇이고 구조적으로 다른 데이터베이스와 어떻게 다른지 알았으니, 왜 중요한지 살펴보겠습니다.  


📌 이해하기 쉽게 생각하면, 코사인 유사도는 "방향만 보는 것"이고, 닷 프로덕트는 "방향과 크기 모두 보는 것"이라고 기억하시면 됩니다.    
- 코사인 유사도 : 텍스트 문서 유사도 비교, 단어 의미 유사도 측정, 방향성이 중요한 경우     
- 닷 프로덕트 : 추천 시스템에서 사용자-아이템 관련도, 벡터의 크기도 중요한 의미를 가질 때, 절대적인 유사도 값이 필요할 때    

📌 피처 스토어와 벡터 데이터베이스의 차이점
- 피처 스토어
  - 데이터는 일반적으로 표 형식으로 저장되며, 각 피처는 특정 속성을 나타내는 열(column)로 구성됨.
  - 예를 들어, 고객 예측 모델의 피처는 나이, 성별, 구매 이력 등이 될 수 있어요.
- 벡터 데이터베이스
  - 데이터는 벡터(고차원 수치 배열) 형식으로 저장됨.
  - 예를 들어, “강아지”라는 텍스트는 고차원 벡터로 변환되어 저장되고, 비슷한 의미의 텍스트를 찾을 수 있어요.

## 왜 벡터 데이터베이스가 필요한가?

벡터 데이터베이스는 추천 시스템, 콘텐츠 기반 이미지 검색, 개인화된 검색과 같은 유사성 검색이 필요한 다양한 응용 프로그램에서 중요한 역할을 합니다.  
- 효율적인 인덱싱 및 검색 기술을 활용함으로써, 벡터 데이터베이스는 이미 벡터로 표현된 비정형 데이터의 더 빠르고 정확한 검색을 가능하게 하며, 
- 이는 사용자에게 쿼리에 가장 관련성 높은 결과를 제공하는 데 도움이 될 수 있습니다.  

또한, 벡터 데이터베이스 사용의 다른 이점은 다음과 같습니다:  
- 고차원 데이터의 효율적인 저장 및 인덱싱  
- 수십억 개의 데이터 포인트가 있는 대규모 데이터셋 처리 능력  
- 실시간 분석 및 쿼리 지원  
- 이미지, 비디오, 자연어 텍스트와 같은 복잡한 데이터 유형에서 파생된 벡터 처리 능력  
- 머신러닝 및 AI 애플리케이션에서의 성능 향상 및 지연 시간 감소  
- 사용자 정의 솔루션을 구축하는 것과 비교하여 개발 및 배포 시간과 비용 감소  


## High-Level Overview of Qdrant’s Architecture

![img](https://raw.githubusercontent.com/ramonpzg/mlops-sydney-2023/main/images/qdrant_overview_high_level.png)
위 다이어그램은 Qdrant의 주요 구성 요소 일부에 대한 고수준 개요를 나타냅니다. 익숙해져야 할 용어는 다음과 같습니다.

**컬렉션(Collections)**: 
- 컬렉션은 검색할 수 있는 포인트(페이로드가 있는 벡터)의 명명된 집합입니다. 
- 동일한 컬렉션 내의 각 포인트의 벡터는 동일한 차원을 가져야 하며 단일 측정 기준으로 비교되어야 합니다. 
- 명명된 벡터는 단일 포인트에 여러 벡터를 가질 수 있으며, 각 벡터는 자체 차원 및 측정 기준 요구 사항을 가질 수 있습니다.

**거리 측정(Distance Metrics)**: 
- 이는 벡터 간의 유사성을 측정하는 데 사용되며 컬렉션을 생성할 때 동시에 선택해야 합니다. 
- 측정 기준의 선택은 벡터를 얻는 방식과 특히 새 쿼리를 인코딩하는 데 사용될 신경망에 따라 달라집니다.

**포인트(Points)**: 포인트는 Qdrant가 작동하는 중심 엔티티이며 벡터와 선택적 ID 및 페이로드로 구성됩니다.
- **id**: 벡터의 고유 식별자입니다.
- **벡터(Vector)**: 이미지, 소리, 문서, 비디오 등과 같은 데이터의 고차원 표현입니다.
- **페이로드(Payload)**: 페이로드는 벡터에 추가할 수 있는 추가 데이터가 있는 JSON 객체입니다.

**스토리지(Storage)**: Qdrant는 스토리지에 두 가지 옵션 중 하나를 사용할 수 있습니다. 인메모리 스토리지(모든 벡터를 RAM에 저장하며, 디스크 액세스가 지속성에만 필요하기 때문에 가장 높은 속도를 가짐) 또는 Memmap 스토리지(디스크의 파일과 연결된 가상 주소 공간을 생성함).

**클라이언트(Clients)**: Qdrant에 연결하는 데 사용할 수 있는 프로그래밍 언어입니다.
