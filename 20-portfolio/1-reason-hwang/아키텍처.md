## 2-bff-apps 앱
- 디렉터리 : 2-bff-apps 는 nest.js typescript로 초기화 한다.  
- 2-bff-apps/remotes/template 은 마이크로 리모트 앱 1
- 2-bff-apps/remotes/todo 은 마이크로 리모트 앱 2 이다.  

마이크로 리모트 앱은 module federation runtime을 이용한다.  
- 빌드 의존성이 아닌 런타임의존성만 사용한다. shared 리액트 없이 진행한다.   
- remote들이 React를 shared singleton으로 공유하지 말라는 뜻  (React 버전 충돌이나 중복 로딩을 감수하는 구조)  

## 마이크로 앱 환경 구축 테스트하기  
*create-next-app, create-vite, nest new를 실제로 실행  
- Host에서 remote를 동적으로 불러오기: @module-federation/runtime만으로 가능
- Vite remote가 federation remoteEntry를 빌드해서 노출하기: 보통 @module-federation/vite 필요
- remote가 무엇을 expose할지 정해야 합니다. = 추천은 ./mount를 expose해서 mount(el) / unmount() 방식으로 붙이는 것.  
- BFF 정적 파일 제공 URL 구조 
      - http://localhost:3001/remotes/template/remoteEntry.js
      - http://localhost:3001/remotes/todo/remoteEntry.js
- 포트 규칙
     명시하면 구현과 Playwright 테스트가 깔끔  
      - host Next: 2800
      - BFF Nest: 2801
      - template remote: 2802
      - todo remote: 2803 ... 

-  BFF configure 상수 위치/형태
     “configure 상수로 remotes 등록/삭제”는 좋은데, 파일과 구조가 필요합니다.
     예: 2-bff-apps/src/remotes.config.ts

     export const remotes = [
       { name: 'template', path: 'remotes/template/dist' },
       { name: 'todo', path: 'remotes/todo/dist' },
     ];
- workspace 패턴
     현재 루트 pnpm-workspace.yaml의 20-reason-hwang/*만으로는 2-bff-apps/remotes/template, 2-bff-apps/remotes/todo가
     workspace package로 안 잡힐 수 있습니다.
     20-reason-hwang/2-bff-apps/remotes/*를 추가하는 게 필요해 보입니다.

- 1, fe host next.js에서도 module federation runtime을 설치한다. 
  - next.js = App Router, 
- 2, remotes/template, remotes/todo 은 vite + react + ts로 프로젝트는 초기화 한다.  
- 3, (중요) 호스트 앱은 left nav (shadcn)으로 초기화 한다. 그리고 각 경로마다 remote app을 연동시킨다.  
  - shadcn의 sidebar 컴포넌트 사용하기  
- 4, 2개의 리모트 앱이 host앱에 랜더링 잘 되는지 테스트를 진행한다.  
  - template 프로젝트는 간단한 react app   
  - todo 프로젝트는 간단한 todo app    
  - /apps/template, /apps/todo로 /app/** 라는 접두사 사용.  
- 5, 2-bff-apps 는 nest.js 인데 나중에 remotes/** 의 리액트앱들을 빌드해서 정적파일 제공해주는 micro app static 제공자야. 
- 6, 2-bff-apps 는 손쉽게 configure 상수로 remotes/** 앱을 등록하고 지우고 할 수 있다. 즉 2-bff-apps는 공통 Nest BFF 하나를 두는거지   
- 7, 개발환경/빌드 환경 end point config 구축 
  - 개발 환경 : remote app vite dev server는 bff를 엔드포인트로 바라본다. (host가 remote를 로드할 때도 BFF를 통해 proxy한다.)
  - 빌드 환경 : remote app이 빌드되면 이는 bff에서 정적파일이 제공되고, bff를 여전히 엔드포인트로 바라본다.
