# Repository Guidelines

## Scope

`20-reason-hwang` is a toy project folder inside the larger `red-blood-brain-docs` workspace. Treat this directory as an isolated project unit when making changes. Keep implementation, docs, tests, and task notes under this folder unless a workspace-level change is required, such as updating `pnpm-workspace.yaml`.

## Project Structure

Planned structure:

```txt
20-reason-hwang/
  1-fe-host/                  # Next.js host app
  2-bff-apps/                 # Nest.js BFF/static remote provider
    remotes/
      template/               # Vite React remote app
      todo/                   # Vite React remote app
  tasks/                      # Implementation task documents
  아키텍처.md                  # Architecture notes
```

Use `tasks/1-init.md` as the source of truth for the initial micro-frontend setup.

## Build, Test, and Development Commands

Use `pnpm` only. Run package-specific commands from the relevant app folder or with workspace filters after package names exist.

Expected ports:

```txt
1-fe-host: 2800
2-bff-apps: 2801
remotes/template: 2802
remotes/todo: 2803
```

Expected validation:

```sh
pnpm lint
pnpm build
pnpm test
```

Add Playwright checks for host routes `/apps/template` and `/apps/todo` when the apps are implemented.

## Architecture Rules

The host app loads remotes through the BFF URL, not directly from remote dev servers. In development, the BFF proxies `/remotes/:name/*` to the Vite dev server. In production/build mode, the BFF serves each remote app's `dist` files.

Use Module Federation as follows:

- Host: `@module-federation/runtime`
- Vite remotes: `@module-federation/vite`
- Remote expose: `./mount`
- React sharing: disabled; do not configure React as a shared singleton

## Coding Style

Follow the style generated by each framework. Use TypeScript for all apps. Keep names explicit and consistent with the project:

- Host routes: `/apps/template`, `/apps/todo`
- Remote config: `2-bff-apps/src/remotes.config.ts`
- Remote names: `template`, `todo`

Prefer small, local changes. Do not refactor unrelated workspace folders.

## Documentation

Keep design decisions in `아키텍처.md` and implementation steps in `tasks/*.md`. When behavior changes, update the closest relevant document in this folder.
