# 기술적 분석 비즈니스 설계

## TA-001 진입과 범위

Host의 `/technical-analysis`(인라인)와 `/technical-analysis/canvas`(Canvas)는 각 전용 FastAPI 그래프를 실행한다. 그래프는 `/fastapi-chat`과 `/langgraph-dev-chat`의 목록에서도 선택할 수 있다. Yahoo ticker의 일봉(`1d`) 또는 주봉(`1wk`) OHLCV를 분석한다. 기본은 최근 완료 일봉 120개다. Yahoo가 인식하는 `.KS`, `.KQ` 등의 ticker도 조회할 수 있다. 공급자별 실제 데이터 가용성은 조회 결과로 판단한다.

## TA-002 계산

SMA, EMA, MACD, PSAR, CCI, STOCH, RSI, STOCHRSI, WILLIAMS_R, AO, TSI, UO, TRIX, BBANDS, KELTNER, DONCHIAN, OBV, PVT, AD, CMF의 20종을 지원한다(TA-INDICATORS-020). 기본은 RSI14·SMA20·MACD12/26/9다. 같은 지표의 다른 설정을 서로 다른 인스턴스로 함께 분석하며 최대 40개, 표시 봉 수는 2~200이다. 지표별 매개변수 범위와 기본값은 서버 카탈로그가 정한다. 명시적으로 잘못된 설정은 거부하며 조용히 기본값으로 바꾸지 않는다. 백테스트·주문·통합 매매 점수는 범위 밖이다.

수정 OHLC를 사용한다. 현재 진행 중인 일봉은 제외한다. 주봉은 거래소 현지 다음 월요일부터 완료로 간주하는 보수적 정책이다. 휴일별 주간 조기 종료 판정은 하지 않는다. 일반 지표는 표시 범위 앞에 지표별 준비 이력을 추가 조회한다. OBV/PVT/AD는 2000-01-01 이후 확보 가능한 최초 봉을 고정 계산 시작점으로 삼고 표시 count만 자른다. 실제 origin·이력 개수·기준값 정책을 응답에 명시하며 전체 상장 이력의 누적값으로 표현하지 않는다. 이력 부족과 null은 숨기지 않고 판단 불가/제한을 표시한다.

## TA-003 지표별 시그널

- RSI: 70 이상 과매수, 30 이하 과매도, 나머지 중립.
- SMA: 종가-SMA의 부호로 위/아래/동일. 직전 차이 ≤0이고 현재 >0이면 상향 교차, 직전 ≥0이고 현재 <0이면 하향 교차.
- MACD: MACD-Signal에 같은 위치/교차 규칙을 적용하고 histogram을 표시한다.

신규 지표의 임계치·교차·밴드 위치·누적 흐름 판정과 null/분모0 규칙은 [20종 계산 계약](../tech-shared/3-langgraph-fast/ta20.md)에 명시한다. TSI/TRIX는 기본 주 지표만 출력하고 signal은 선택 시 기본9로 추가한다.

최신 완료 봉과 직전 봉을 사용한다. 두 유효값이 없으면 교차 판단 불가다. LLM은 결정적 계산 결과를 설명하며 과매수/과매도를 자동 매수·매도 명령으로 해석하지 않는다.

## TA-004 표현과 오류

Lightweight Charts의 캔들·거래량과 지표별 overlay/밴드/PSAR 점·oscillator pane을 공통 시간축으로 제공한다. 기본 RSI(30/70), MACD/Signal·histogram 표현을 유지한다. 모든 선택 인스턴스의 데이터를 반환하고, 화면의 동시 표시 oscillator pane 한도4는 명시적으로 조절하며 데이터를 잘라내지 않는다. 날짜 범위·통화·수정주가 여부·기준일·조회 시각·Yahoo 출처를 함께 표시한다. 최초 값은 서버의 TA-Lib 스냅샷이며 OpenUI `Query`가 같은 계산 API에서 갱신한다. 공급자 실패 시 기존 분석을 최신 결과로 재출력하지 않는다. UI 검증 실패 시 계산 시그널을 텍스트로 제공한다. Canvas 전용 에이전트는 TA-CANVAS-003에 따라 해석을 채팅에 남기고, 가격·지표별 차트를 선택 가능한 UI로 제공한다.

## TA-005 대화 격리

같은 thread의 후속 요청은 이전 ticker·주기·기간·지표 설정을 유지한다. 그래프 변경은 새 thread를 시작하며 실행 중에는 선택을 비활성화한다. 기존 메시지 차트는 새 분석으로 덮어쓰지 않는다. 기록은 런타임별로 격리한다. FastAPI 저장 thread를 다시 열면 메시지·그래프 상태를 복원하며, 실행 중 기록은 최종 상태를 API로 확인한다. 개발 서버의 기록을 FastAPI로 자동 이관하지 않는다.

## TA-QUERY-001 모델 없는 차트 조회

차트의 Yahoo ticker 입력, 일봉/주봉 선택과 표시 봉 수 선택은 모델 실행 없이 가격·지표 HTTP API를 재조회한다. 지표 선택·인스턴스 추가/삭제·기간·선택 signal도 같은 패널에서 편집할 수 있다. Query 변경은 숫자 재조회이며 모델 해석을 다시 생성하지 않는다. 최신 답변에서만 30초 갱신을 선택할 수 있고 기본은 꺼짐이다. 완료 봉 정책과 서버 가격 캐시가 유지되므로 매 polling마다 새 봉이 생기는 것은 아니다.

차트 metadata는 조회 결과 기준으로 바뀌며 분석 본문·시그널·근거는 최초 답변 시점의 스냅샷임을 명시한다. 이전 답변은 자동 polling하지 않는다. 차트 조건 변경은 대화의 에이전트 상태를 수정하지 않으며, 새 분석 해석이 필요하면 대화로 요청한다.

## TA-QUERY-002 수동 새로고침

Query 차트는 조회 조건 패널에 ticker·주기·봉 수 편집과 새로고침 아이콘을 함께 제공한다. `데이터 새로고침` 아이콘은 현재 조건을 유지해 다시 조회하며 모델을 실행하지 않는다. 조회 중에는 상태와 회전 아이콘을 표시하고 버튼을 비활성화해 중복 요청을 막는다. 오류가 발생하면 조건 수정 또는 같은 조건의 수동 재시도로 복구할 수 있다. 기존 완료 봉·서버 캐시와 분석 스냅샷 정책을 유지한다.

## TA-CANVAS-003 선택형 Canvas

`기술적 분석 · Canvas`는 해석을 채팅에 표시하고 가격·지표별 차트를 `CanvasItem`으로 제공한다. 사용자가 **Canvas에 추가**를 누른 요소만 옆 Canvas에 들어간다. 보고서 전체가 자동으로 열리지 않는다. 각 차트의 조회 조건·지표·새로고침은 해당 요소와 함께 이동하며 추가 이후 채팅과 Canvas의 상태는 독립적이다.

같은 요소를 여러 개 추가해 조회 조건과 배치를 독립적으로 편집할 수 있다. 각 패널은 제거·이동·크기 조절·위치 고정을 지원한다. 키보드로 이동·크기를 조절할 수 있으며 좁은 화면에서는 한 열로 표시한다. localStorage에 런타임·thread별 배치와 상태를 저장하고 같은 브라우저에서 대화를 열면 복원한다. 서버는 근거 보고서를 별도로 저장한다.

요소의 텍스트를 선택해 **채팅에 물어보기**를 누르면 같은 thread에 저장된 원래 보고서와 요소 ID를 근거로 설명한다. 차트 조건 변경은 모델 재분석이 아니므로 기존 해석은 원래 분석 시점 기준임을 표시한다. 새 분석 결과도 채팅에 표시하고 사용자가 추가 여부를 결정한다.

분할선 크기 저장·접기·다시 열기와 브라우저 인쇄를 통한 PDF 저장을 지원한다. 가격 Query가 로딩 중이거나 실패한 요소가 있으면 PDF 버튼을 비활성화한다. PDF는 현재 Canvas 화면을 인쇄하며 서버에 고정된 스냅샷을 발행하는 기능은 아니다. 공유 링크와 기기 간 저장은 후속 범위다.

## TA-CANVAS-002 기존 분석과 Canvas 분석 분리

`technical_analysis_agent`는 인라인 출력으로 제공한다. `technical_analysis_canvas_agent`는 사용자가 선택해 추가하는 wrapper 요소와 원본 요소 인용을 제공한다. TA-Lib·SEC 채팅에는 Canvas 추가 버튼이 없다.

## TALIB-AGENT-001: 전체 함수 탐색과 자유 계산

별도 `/talib-chat`는 설치된 TA-Lib 0.8.3의 237개 함수를 탐색·설명·계산한다. 사용자는 기존 20종
지표에 제한되지 않고 수학·통계·변환·패턴·다중 입력·이전 결과 조합을 요청할 수 있다. 모호한 입력은
확인하고 설치되지 않은 함수를 임의로 대체하지 않는다. 모든 함수를 매 턴 계산하지 않는다.
한 번에 최대 40개를 실행하고 큰 요청은 순차 호출로 나눈다. 다른 티커와 이전 계산을 후속 대화에서
재사용하며, 설명 질문은 재조회 없이 답할 수 있다. 결정적 계산 결과·출처·경고를 표와 선택형 차트로
검토하고 후속 질문으로 이어간다. 패턴 코드를 매매 확률이나 확정 추천으로 표현하지 않는다.
기존 TA20·Canvas의 기능 범위는 바꾸지 않는다. 상세 계약은 [시스템 설계](system-design.md#talib-agent-001-전체-네이티브-ta-lib-에이전트)를 따른다.
