# UI 구현 명세 — 기능과 상태

> 새 remote 내부 UI의 구현 기준. 색·인물·그림은 [visual-design](visual-design.md)이 소유한다. 모델이 화면 구조·CTA·라우트를 생성하지 않는다.

## 1. 여정과 라우트

독립 실행 및 mount 모두 hash router 사용, 호스트 경로를 점유하지 않는다. 브라우저 뒤로가기와 새로고침을 지원한다.

| 화면 ID / 경로 | 사용자 목적 | 내용과 CTA |
| --- | --- | --- |
| UI-01 #/ | 풀이 선택 | 사주/타로 소개 2개, 차이·지원 범위·임시 보관 안내, 시작 |
| UI-S01 #/saju/new | 출생·질문 입력 | 달력/날짜/시간/시간 모름, 주제·질문·상황, 확인 체크, 입력 확인 |
| UI-S02 #/reading/:id/review | 계산 입력 확인 | 양력 변환값·시간 유무·기준·질문, 정보 수정 / 풀이 시작 |
| UI-T01 #/tarot/new | 질문 정리 | 주제·질문·상황, 관계 조건부 필드, 확인 체크, 카드 고르기 |
| UI-T02 #/reading/:id/draw | 3장 선택 | 위치 3슬롯·선택 수·78장 뒷면, 다시 고르기 / 풀이 시작 |
| UI-G01 #/reading/:id/progress | 안전하게 기다리기 | 서버 stage 문구, 확정된 카드(타로), 상태 확인 |
| UI-R01 #/reading/:id/result | 답·근거 읽기 | 고정 결과 구조, 근거 펼치기, 피드백, 새 풀이 / 삭제 |

result가 아직 없는 ID를 직접 열면 Snapshot 상태에 해당하는 화면으로 replace 이동한다. completed를 progress로 열어도 result로 이동한다. 다른 domain의 입력을 공유 전역 폼으로 덮어쓰지 않는다.

## 2. 입력 화면

- 상단 제목·진행 단계, 본문 폼, 하단 CTA. 실명/연락처/상대 생일 수집 없음.
- 사주 양력/음력은 라디오. 음력 선택 시 윤달 체크가 아닌 평달/윤달 필수 라디오를 보인다. 양력 전환 시 leapMonth를 null로 정리한다.
- 날짜는 숫자 입력과 명시 라벨; 자동 포맷은 하되 잘못된 날짜를 몰래 다음 달로 고치지 않는다. YYYY-MM-DD로 전송한다.
- 시간 모름 선택 시 시간을 지우고 비활성화한다. 해제 시 사용자가 다시 입력한다. 시주 제외 안내를 바로 보인다.
- 관계 주제 선택 시 relationship을 필수 노출. 다른 주제로 바꾸면 null. 추가 맥락은 1000자 카운터, “상대의 실명·연락처는 적지 마세요.”
- 동의 3개는 모두 기본 미체크. 서비스 성격/성인 본인/24시간 임시 보관을 각각 설명한다.
- 사주 기본 질문: “요즘 제 선택에서 살펴볼 성향과 균형을 알려주세요.” 타로 기본 질문: “지금 고민하는 선택에서 무엇을 살펴보면 좋을까요?” 버튼으로 넣되 사용자가 구체화하도록 예시를 표시한다. 질문 제출 없이 빈 풀이 생성 금지.
- CTA의 필수값 부족은 비활성+누락 안내, 제출 후 서버 오류는 필드 가까이 노출하고 첫 오류에 focus. 알림창만으로 이유를 전달하지 않는다.

클라이언트 초안은 메모리 + sessionStorage, 30분 TTL이며 이 탭에서만 복구한다. 입력 원문을 localStorage에 영구 저장하지 않는다. 서버 초안 생성 뒤에는 server Snapshot이 기준이다. 탭 닫음/삭제/서버 만료 시 로컬 초안도 삭제한다.

## 3. 카드 선택 화면

선택 슬롯 3개에 “현재 상황 / 주의할 점 / 선택과 조언”을 항상 표시한다. 덱은 모바일에서 13장 단위 6페이지의 같은 크기 뒷면 버튼으로 제공한다(총 78장). 겹쳐진 장식 이미지를 실제 선택 가능한 DOM 카드 수와 혼동하지 않는다.

- token별 버튼 aria-label은 “카드 1 선택”처럼 ordinal만 사용한다. 선택 전 카드 이름/asset URL을 DOM·네트워크·alt에 노출하지 않는다.
- 첫 선택은 situation, 둘째 caution, 셋째 action. 선택된 뒷면은 비활성, 선택 순서 1/2/3 표시.
- 선택 API 응답 전에는 추가 선택을 잠깐 막는다. 클릭을 낙관적으로 중첩 전송해 순서가 바뀌지 않게 한다.
- 세 장 미만은 풀이 시작 비활성. 세 장이어도 generate 수락 전에는 앞면을 공개하지 않는다.
- 다시 고르기 → “선택한 카드를 모두 내려놓고 다시 섞을까요?” 취소/다시 고르기. 취소는 그대로, 확인은 reset API 완료 뒤 0장·첫 페이지.
- 뒤로가기/새로고침은 서버 선택을 복구한다. 질문 수정은 “질문을 바꾸면 선택한 카드가 초기화돼요” 확인 후 PATCH.
- generate 202 뒤 확정 앞면과 이름·위치를 공개한다. 동일 카드 애니메이션은 이동·회전만 표현하며 실제 재추첨하지 않는다.

## 4. 생성과 결과

생성 문구는 stage와 대응: prepare “입력과 근거를 확인하고 있어요”, compose “질문에 맞춰 해석하고 있어요”, check “해석의 일관성을 확인하고 있어요”, persist “결과를 정리하고 있어요”. 가짜 퍼센트·고정 카운트다운 없음. 10초 이상 지연 안내, polling 60초 이후 수동 확인. 페이지 이탈은 작업 취소가 아니며 돌아오면 복구한다.

결과 레이아웃:
1. 도메인·질문·닉네임(있는 경우), 생성일·만료 시각.
2. headline → summary. 캐릭터 이미지는 보조이며 텍스트에 공간 우선.
3. 사주: 원국 요약과 시주 “시간 모름”; 타로: 3장 앞면·이름·위치.
4. sections 3개, 각 “해석 근거” 버튼. 근거는 canonical label/value/meaning을 패널로 열고 결과 위치로 돌아오기 가능.
5. synthesis, actions 2개, limits, 고정 안내.
6. 도움이 됨/보통/아님, 새 풀이, 이 결과 삭제. 결제·잠금 영역 없음.

오행은 값과 합계를 텍스트로 항상 표시하고 단순 분포라는 캡션을 붙인다. 0은 missing과 다르다. 그래프가 있더라도 행운 점수처럼 보이는 게이지로 표현하지 않는다. 모델 평문만 렌더링하며 HTML 삽입 금지. 긴 결과의 목차 이동은 기능상 지원하되 핵심 답을 접힘 안에 숨기지 않는다.

## 5. 상태·오류 UI

| 상태 | 사용자에게 보일 것 | 허용 행동 |
| --- | --- | --- |
| 초기 로딩 | 폼/결과 skeleton, 설명 라벨 | 중복 요청 방지 |
| 필드 422 | 입력 인접 오류·입력 유지 | 수정 |
| BIRTH_TIME_REQUIRED | “이 날짜는 기준이 바뀌는 시각을 확인해야 해요.” | 출생시간 확인/입력 수정; 정오 자동 보정 없음 |
| 생성 failed/retryable | 실패 안내, “같은 정보/카드로 다시 시도” | retry 1회 |
| CONTENT_INVALID/refusal | “안정적인 풀이를 제공하지 못했어요.” 또는 질문 범위 안내 | 질문 바꾸기, 삭제; 무한 재생성 없음 |
| 409 | “다른 화면에서 변경됐어요. 최신 상태를 확인해요.” | 서버 상태 갱신 |
| 429 | 제한·재시도 가능 시각 | 기다리기; 자동 생성 금지 |
| 404/401 | 접근 불가·새 세션 안내 | 새 풀이 |
| 410 | “임시 보관 시간이 끝났어요.” | 새 풀이 |
| 이미지 실패 | 이름·위치·텍스트 카드 | 풀이 읽기 지속 |
| 오프라인 | 연결 확인·마지막 상태 표시 | 연결 후 같은 요청 키로 재전송 |
| 삭제 확인 | 복구 불가·삭제 범위 설명 | 취소/삭제; 완료 후 홈 |

“다시 풀이”는 기존 결과 재생성 버튼이 아니다. 새 초안 만들기이며 생일·상황 복사 여부를 확인한다. 토큰/카드는 복사하지 않는다.

## 6. 구현 구조와 접근성

UI 컴포넌트: DomainChoice, BirthForm, QuestionForm, ConsentFields, InputReview, CardDeck, SelectedSlots, GenerationStatus, ReadingSummary, SajuFactsPanel, TarotSpread, InterpretationSection, EvidenceDrawer, ActionList, LimitNotice, Feedback, ErrorPanel, ConfirmDialog.

Views는 props/events만 받아 Storybook에서 모든 상태를 테스트한다. controller/hooks는 API·idempotency·polling·폼 상태를 담당한다. API DTO에서 view model로 변환하고 컴포넌트가 직접 원국 계산/카드 선택을 하지 않는다. 모델의 자유 문자열로 컴포넌트 종류를 결정하지 않는다.

360/390/768/1280px 검증, 200% 글자 확대, 가로 넘침 없음. 본문 16px 이상, 줄간격 1.6–1.8 기본안. 터치 영역 44px 이상, 본문 대비 4.5:1 이상 실제 측정. 색만으로 선택/오류 구분 금지. 키보드로 입력→카드→모달→결과 완주 가능. 모달 focus trap/복원, 진행 상태 aria-live polite, 오류 alert, reduced-motion에서 뒤집기/부유 효과 제거. 장식 인물은 빈 alt, 카드 앞면 alt는 이름+정방향+위치.

이미지가 준비되지 않아도 고정 샘플 데이터로 전 UI를 구현·검증할 수 있다. 실제 서비스 완료는 [비주얼 게이트](quality-acceptance.md)까지 통과해야 한다.
