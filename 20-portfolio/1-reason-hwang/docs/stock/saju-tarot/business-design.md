# 사주·타로 비즈니스 요구사항

> 신규 제품 설계 v1. 관찰 사실이 아닌 제품 정책은 BR/FR로 표시한다. 전체 방향은 사용자 요청이며, 구체적인 v1 제한은 구현을 위한 설계 기본안이다.

## 1. 사용자 문제와 제공 가치

사용자는 긴 운세 문장보다 “내 질문에 무엇이 연결되는지, 어디까지 믿어도 되는지, 지금 무엇을 해볼지”를 알고 싶다. **사주**는 출생 정보를 바탕으로 성향과 선택 경향을 성찰하는 경험, **타로**는 현재의 구체적인 고민을 카드 상징으로 다른 관점에서 살펴보는 경험으로 구분한다. 미래 사실의 적중이나 상대방 마음을 알아내는 능력을 약속하지 않는다.

핵심 품질은 분량·신비로운 이미지·정밀해 보이는 숫자가 아니라 **입력 맥락 반영, 근거 일치, 해석 간 일관성, 선택 가능한 조언**이다. 결과를 읽은 사용자가 자신의 질문에 대한 요약과 다음 행동을 설명할 수 있어야 한다.

## 2. 관찰에서 채택한 것과 채택하지 않은 것

아래는 조사 당시의 관찰 요약이다. 원본 팩트북은 이 문서 묶음에 포함하지 않으므로 독립적인 재검증 근거로 취급하지 않는다.

| 실제 관찰 | 설계에 반영할 점 | 원 서비스에서 확인하지 못한 점 |
| --- | --- | --- |
| 사주 날짜·시간 모름·검증 (FACT-S-6003) | 출생시간 모름을 정상 입력으로 취급하고 해석 한계를 노출 | 시간 모름의 실제 계산 방식 |
| 사주 무료 미리보기 (FACT-S-6005) | 짧은 요약에서 상세 해석으로 읽기 구조 제공 | 점수·직업·시기 예측의 타당성, 유료 전문 |
| 타로 3장과 초기화 (FACT-T-3001), 확인 모달 (FACT-T-3002) | 선택 순서와 초기화 책임을 명확히 함 | 원 서비스의 난수·배열·중복 방지 방식 |
| 관계별 후속 질문 (FACT-T-3021) | 질문에 필요한 맥락을 해석에 전달 | 맥락별 원본 프롬프트 |
| 81% 표시 (FACT-T-3014) | 근거 없는 정밀 수치는 v1에 넣지 않음 | 확률의 산식·검증 |
| 상품 이동 후 화면 차이 (FACT-C-2504) | 사주·타로 입력과 결과를 readingId별로 격리 | 원인이나 실제 청구 영향 |

## 3. v1 범위

포함: 한국어, 성인 자신의 정보에 대한 1인 사주, 질문형 3장 타로, 입력 검증, 근거 펼쳐보기, 결과 품질 검수, 같은 브라우저 임시 재열람, 삭제, 오류 복구.

제외: 대화형 무제한 상담, 타인 개인정보·두 사람 궁합, 미성년자 분석, 대운/세운/일진, 건강·투자·법률 예측, 확률·행운 점수, 결제·광고·상품 추천, 계정·기기 간 동기화·공개 공유. 생년 기반 오늘의 운세와 날짜별 타로는 이 핵심을 검증한 뒤 별도 상품으로 설계한다.

v1은 무료 핵심 경험 검증 단계다. 유료 전환율을 성공 지표로 삼지 않는다. 하루 10회 생성 제한은 비용·남용 통제 기본값이며 보상 구매나 유료 이용권으로 연결하지 않는다.

## 4. 요구사항과 이유

| ID | 요구사항 | 이유 / 성공 조건 |
| --- | --- | --- |
| FR-S01 | 달력 종류·윤달·날짜·시간 모름을 구별해 입력 | 같은 생일을 다른 달력으로 오인하지 않음 |
| FR-S02 | 코드가 원국과 명시된 파생 근거를 계산 | 모델이 간지·달력·오행 값을 지어내지 않음 |
| FR-S03 | 질문에 연결한 성향·주의점·행동을 해석 | 일반적인 덕담이 아니라 질문 맥락에 답함 |
| FR-T01 | 주제·질문·선택적 상황/관계 입력 | 개인화는 이름 치환이 아닌 상황 해석 |
| FR-T02 | 78장 중 중복 없는 3장 선택, 순서 고정 | 사용자의 선택과 공개된 카드가 일치 |
| FR-T03 | 각 카드와 3장의 종합을 모두 설명 | 카드 뜻 3개를 나열하는 데 그치지 않음 |
| FR-C01 | 검수를 통과한 구조화 결과만 화면에 공개 | 불완전·모순된 내용을 완료로 보여주지 않음 |
| FR-C02 | 통신 재시도·새로고침으로 재계산/재추첨하지 않음 | 결과 신뢰와 사용자의 입력 노력 보존 |
| FR-C03 | 한계와 근거를 읽기 쉽게 제공 | 전통 해석을 검증된 미래 사실처럼 오인하지 않음 |
| FR-C04 | 삭제·24시간 만료·권한 격리 | 계정 없는 핵심 기능에서도 사적 질문 보호 |
| FR-V01 | 캐릭터·일러스트를 기능 계약과 분리 | 그림 교체가 해석·API 변경으로 번지지 않음 |

## 5. 사주 정책

- BR-S01: 입력은 본인의 출생정보로 제한한다. v1은 한국 출생, 시간대 `Asia/Seoul`, 변환된 양력 생일 1900-01-01 이후·오늘 이전, 만 19세 이상을 지원한다. 해외 출생은 미지원 안내; 브라우저 시간대로 자동 변환하지 않는다.
- BR-S02: 달력은 양력/음력, 음력만 윤달 여부 필수. 음력 유효성과 성인 여부는 양력 변환 후 서버에서 최종 판정한다. 닉네임은 선택, 성별·실명·주소는 수집하지 않는다.
- BR-S03: 명리 계산 기준은 **입춘의 정확한 시각으로 연주, 12절의 정확한 시각으로 월주, 현지 민간시 00:00으로 일주, 진태양시 보정 없음**을 기본안으로 고정한다. 23:00–00:59는 자시 지지이나 일간은 00:00에서 바뀌므로 시간 천간도 해당 일간 기준이다. 이를 명리학의 유일한 정답이라 하지 않는다.
- BR-S04: 역사적 UTC 오프셋/DST는 버전 고정된 시간대 자료를 적용한다. 존재하지 않거나 두 번 나타나는 출생시각은 거절하고 확인을 요청한다. 시간 모름은 시주를 만들지 않는다. 같은 현지 날짜 안에 연주·월주가 바뀌어 확정할 수 없으면 `BIRTH_TIME_REQUIRED`로 시간 확인을 요청한다. 임의로 정오를 넣지 않는다.
- BR-S05: 공개 근거는 연·월·일·시주, 일간, **천간·지지의 대표 오행을 각각 1개로 센 단순 분포**다. 지장간·가중치·신강/신약·용신·대운을 산출하지 않는다. 시간 미상은 6개, 시간 확인은 8개 합계이며 이를 건강·행운·강약 점수로 바꾸지 않는다.
- BR-S06: 계산된 사실만으로 성격이 입증됐다고 말하지 않는다. 승인된 해석 규칙과 질문을 결합해 가능성·균형·행동을 설명한다. 사주 원국이 같아도 고민에 대한 조언은 달라질 수 있으나 원국은 달라지면 안 된다.

## 6. 타로 정책

- BR-T01: 주제는 `general / relationship / work / self`. 관계 주제에서만 `single / crush / dating / separated / other`를 입력한다. 상대 실명·생일은 받지 않는다.
- BR-T02: 78장, 정방향만 사용한다. 3개 위치는 **현재 상황 / 주의할 점 / 선택과 조언**이다. 역방향·다른 스프레드는 후속 버전이며 숨겨서 무작위 적용하지 않는다.
- BR-T03: 서버가 덱을 암호학적 난수로 섞고 뒷면 토큰만 공개한다. 선택한 순서가 위치 순서다. 생성 시작 전까지 전체 초기화 가능, 한 장만 골라 유리한 카드로 바꾸는 동작은 제공하지 않는다.
- BR-T04: 3장을 확정하면 조합을 동결한다. 실패 후 재시도는 같은 카드다. 완료 결과도 재생성하지 않는다. 새 질문/다시 뽑기는 새 readingId이며 이전 결과를 덮어쓰지 않는다.
- BR-T05: 카드 의미 원문은 편집·검수한 버전형 카탈로그가 제공한다. 모델은 카드 종류·방향·선택 결과를 결정하지 않는다.
- BR-T06: “상대는 반드시 당신을 사랑한다”, 정확한 재회일·성공 확률처럼 확인 불가능한 사실을 단정하지 않는다. 카드의 상징적 관점과 관찰/대화로 확인할 수 있는 행동을 구분한다.

## 7. 공통 결과·보관 정책

BR-C01: 결과 순서는 질문 → 한 줄 결론 → 핵심 해석 → 종합 → 실천 2개 → 해석 한계 → 근거다. 사주는 성향/질문 연결/주의점을, 타로는 위치별 3장과 조합의 상충·보완을 다룬다. 모델의 내부 사고 과정 대신 사용자가 이해할 수 있는 짧은 근거 설명만 제공한다.

BR-C02: 생성된 결과는 읽기 전용이다. 입력 변경은 새 초안으로 복사하고 명시적 확인 후 새 풀이를 만든다. 이름만 바꿔 운명이 달라지는 식의 개인화는 금지한다.

BR-C03: 초안·입력·카드·결과·체크포인트는 생성 시각부터 24시간 보관한다. 자동 연장하지 않는다. 같은 브라우저 익명 쿠키로만 접근하며 기기 간 보관함이 아니다. 만료 시 즉시 접근 차단, 1시간 이내 삭제 작업. 즉시 삭제 요청은 접근 차단 후 같은 삭제 절차를 적용한다. 정확한 저장/백업 정책은 시스템 명세를 따른다.

BR-C04: 서비스 고정 안내: “사주와 타로는 자기성찰을 위한 전통·상징 해석입니다. 미래나 타인의 마음을 사실로 보장하지 않습니다.” 의료·재무·법률 결정을 운세로 확정하라는 요청은 풀이하지 않고 질문 변경을 안내한다. 안전 거절을 프롬프트 수정으로 우회하지 않는다.

## 8. 측정과 구현 우선순위

핵심 퍼널은 유효 초안 생성 → 생성 요청 → 검수 통과 결과 → 첫 결과 열람이다. 이벤트는 `draft_created / generation_requested / reading_completed / reading_failed / result_viewed / feedback_submitted`. 사용자 질문·생일·결과 원문은 분석 로그에 넣지 않는다.

지표: 생성 성공률(완료/생성 요청), 첫 열람률(읽힌 완료 결과/완료 결과), 지연 p50/p95, 품질 오류율, “질문에 도움이 됨/보통/아님” 피드백. 목표 기준은 [품질 명세](quality-acceptance.md)이며 아직 측정치가 아니다.

순서: 계약·계산/카드 단위 테스트 → 고정 결과로 UI → 실제 해석 그래프 → 회귀 평가 → 독립 remote 통합 → 인물·카드 최종 에셋 적용. 수익 기능보다 핵심 풀이의 검증을 먼저 한다.
