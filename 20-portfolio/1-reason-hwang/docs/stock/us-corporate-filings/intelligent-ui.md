# SEC Intelligent UI 채팅

## SEC-IUI-001 목표와 계약

사용자가 선택한 기업의 최신 SEC 10-K 원문을 기존 BFF 수집 API로 다운로드하고, Python LangGraph 에이전트에 질문한다. 프런트는 `1-fe-host`, 에이전트는 `3-langgraph-fast`가 소유한다. **A2UI는 사용하지 않는다.** AG-UI SSE의 텍스트 메시지로 OpenUI 프로그램을 전달하고 6-3 Intelligent UI 카탈로그로 렌더링한다. 기존 A2UI 기능은 이 기능의 의존성이 아니다.

## SEC-IUI-002 근거와 대화

Item 1 소제목 추출 → 소제목별 요약을 연속 대화로 지원하고 Item 1, 1A, 3, 7, 8을 가치평가 기반 자료로 정리한다. 내부 추론 대신 원문 근거와 요약을 제공한다. 회사·접수번호·공시일·원문 URL·수집 시점을 답변에 보존한다. 보고서 내용은 지시가 아닌 비신뢰 데이터이며 확인되지 않은 숫자나 전망을 만들지 않는다. 원문에 없거나 검색 범위 밖인 정보는 한계를 표시한다.

최신성은 저장된 문서 중 최신이라는 사실과 SEC 동기화 완료를 구분한다. 원문 다운로드 오류나 최신 확인 실패를 성공으로 처리하지 않는다. 이전 회사의 대화 근거를 다른 회사에 섞지 않는다.

법인 재편으로 새 CIK에 자체 10-K가 없으면 SEC 공시로 확인한 이전 법인 관계만 사용할 수 있다. 이 경우 이전 법인의 최신 10-K를 분석한다는 사실과 실제 원문 식별자를 표시한다. Item이 같은 파일의 다른 페이지에 있는 MD&A나 재무제표를 참조하면 확인 가능한 본문을 포함한다.

## SEC-IUI-003 완료 검증

최소 10개 기업 각각에 최신 10-K 식별/다운로드, Item 1 소제목 추출, 후속 소제목별 요약, Item 1A·3·7·8 질문과 전체 보고서 질문을 실제 provider와 채팅 UI로 검증한다. AG-UI 종료 이벤트뿐 아니라 parser 오류 없음, 화면에 근거와 내용이 표시되는지 확인한다. Bruno API E2E, Storybook, MCP 브라우저, 정적 검사 및 작업 소유 자원 정리가 모두 필요하다.

## 구현 상태

2026-10-21: `/sec-chat`과 Python LangGraph/API 구현 완료. AAPL·MSFT·NVDA·AMZN·GOOGL·META·TSLA·JPM·WMT·XOM의 최신 10-K로 70개 질문 시나리오를 실제 모델/채팅 UI에서 검증했다. 본실행 9기업 통과 후 JPM의 근거 Item 불일치를 수정하고 전체 7턴을 재검증했다. API E2E·Storybook·MCP와 작업 소유 자원 정리도 완료했다. [최종 검증 기록](../../flow/2026-10-21-sec-intelligent-ui-validation.md)에 원문 식별자, 명령, 결과, 실패 이력과 한계를 보존한다.

이 기능은 로컬 단일 사용자 메모리 대화다. 큰 Item은 약 18만 자 입력 예산 안에서 발췌하며 인용문 일치와 요약의 완전한 사실 검증은 구분한다. 기존 다른 Python 파일의 workspace lint/type 오류는 남아 있다. [실행 안내](../tech-shared/1-fe-host/sec-intelligent-ui.md#로컬-실행)를 따른다.
