시작하기: 왜 그래프가 필요할까?

간단한 질문은 모델 한 번 호출로 답할 수 있습니다. 반면 “엔비디아의 공시를 근거로 분석해줘”라는 요청은 기업 식별, 공시 준비, 원문 조회, 근거 검증과 답변 생성이라는 여러 단계를 거칩니다. 그래프는 이 단계의 순서와 분기, 공유 데이터를 명시합니다.

사용자 질문 → 작업 선택 → 데이터·도구 → 결과 검증 → 답변

노드는 하나의 작업, 엣지는 다음 작업으로 이어지는 연결, 상태는 단계 사이에 전달되는 메시지·데이터입니다. 도구는 가격 조회처럼 모델이 호출할 수 있는 기능입니다. 에이전트는 모델이 도구 선택과 다음 행동을 판단할 수 있도록 구성된 경우를 뜻합니다.

11개는 langgraph.json의 등록 그래프 수입니다. SEC Research Chat의 전용 대화 그래프와 공통 OpenUI 출력 서브그래프처럼 API 내부에서 별도로 구성하는 그래프는 이 숫자에 포함하지 않습니다.

01 · 가장 기본적인 LLM 그래프

복잡한 업무를 다루기 전에, 상태를 받아 모델을 호출하고 결과를 돌려주는 최소 구조를 살펴봅니다.

1. main_graph

일반 메시지와 provider를 상태로 전달하고 call_llm 노드에서 답변을 생성합니다. 질문·provider·응답을 개별 상태 필드로 다루는 기본 예제입니다.

START → call_llm → END

예: “PER이 뭐야?” → 모델이 개념을 설명합니다. 외부 가격 조회나 공시 검색은 이 workflow에 없습니다.

2. simple_llm

같은 단일 호출 흐름을 사용하지만, 질문과 답변을 messages 목록의 대화 메시지로 관리합니다. 보조 함수가 마지막 AI 메시지를 추출합니다.

START → call_llm → END

차이: main_graph는 message/provider/response 필드, simple_llm은 메시지 목록 중심입니다. 둘 다 현재 workflow에서는 도구 호출 루프가 없습니다.

02 · 도구 호출과 가격·분석의 기초

모델이 외부 정보나 계산이 필요하다고 판단하면, 도구를 호출하고 그 결과를 확인한 뒤 답변할 수 있습니다.

3. starter_graph

도구 사용을 익히는 기본 ReAct 에이전트입니다. 바깥 그래프의 react_agent 노드 안에서 모델이 get_weather 도구를 사용할 수 있습니다.

START → react_agent [모델 ↔ 날씨 도구] → END

예: 날씨 질문을 받으면 날씨 도구를 선택하고 결과를 바탕으로 답변합니다. 도구 호출 가능성과 실제 외부 데이터 정확성은 별도로 확인해야 합니다.

4. price_agent

가격 요청을 해석하고 필요한 경우 Yahoo Finance 가격 도구를 호출합니다. 도구 결과를 수집해 응답을 구성하며, 요청 해석에 실패하거나 도구 호출이 필요 없는 경우 응답 구성으로 분기합니다.

요청 해석 ─→ 가격 도구 → 가격 데이터 수집 ─→ 응답 구성
          └────────────────────────────→ 응답 구성

예: 특정 종목의 최근 일봉을 요청할 때 시세 수집 흐름을 담당합니다. 기본 상태는 일봉과 10개 데이터입니다.

5. technical_analysis_graph

호출자가 전달한 가격 데이터의 유효성을 먼저 검사합니다. 유효하면 모델이 분석 도구를 사용할 수 있고, 도구 실행 후 모델로 돌아갑니다. 유효하지 않은 입력은 오류 응답으로 분기합니다.

가격 검증 → 모델 ↔ 분석 도구 → 답변
       └→ 입력 오류 안내

주의: 이 그래프는 입력으로 전달된 가격을 분석하는 경계입니다. 가격을 조회하는 price_agent와 역할이 다릅니다.

03 · 기술적 분석 에이전트와 화면 출력

이 그룹은 시세 수집, 지표 계산, 설명, 시각화를 연결합니다. 수치 계산과 모델의 설명을 구분하는 것이 핵심입니다.

6. technical_analysis_agent

Deep Agent와 업무 도구를 사용해 Yahoo 일봉·주봉을 가져오고 지표를 분석합니다. 기본은 RSI·SMA·MACD이며, 요청에 따라 지원 지표와 설정을 바꿀 수 있습니다. 분석 결과는 서버가 작성한 OpenUI 프로그램으로 인라인 표시합니다.

prepare → analyze [가격 조회 → 지표 계산] → present → END

시각화 검증에 실패하면 계산 결과의 텍스트 요약으로 대체합니다. 지표 신호는 설명을 위한 정보이며 자동 매매 판단을 보장하지 않습니다.

7. technical_analysis_canvas_agent

위 분석의 가격·지표 도구를 공유하면서 결과를 별도의 Canvas 항목으로 다룹니다. 분석 요청은 새 보고서를 만들고, 선택한 보고서에 대한 설명 요청은 저장된 문맥을 활용하는 별도 경로를 사용합니다.

prepare → analyze → present → Canvas 보고서
        └→ explain → 기존 보고서 설명

언제 유용할까? 여러 분석 결과를 탭이나 개별 요소로 비교하고, 특정 요소를 선택해 후속 질문할 때입니다. 서버가 계산 데이터와 차트 요소를 소유하고 생성 영역은 제한합니다.

8. talib_agent

설치된 TA-Lib 함수 카탈로그를 탐색하고 여러 함수·입력·결과를 조합하는 별도 에이전트입니다. 데이터와 계산 배열은 상태에 보관하고, 사용자에게는 검증된 설명과 선택한 결과의 인라인 시각화를 제공합니다.

prepare → analyze [함수 탐색 · 가격 조회 · 계산] → present → follow_up

일봉·주봉 비교처럼 여러 계산이 필요하면 요청된 조합이 완료됐는지 확인합니다. 함수별 입력 조건과 충분한 가격 이력이 필요하며, 지원하지 않는 함수를 임의로 대체하지 않습니다.

세 그래프 비교: 일반 기술적 분석은 채팅 안의 결과, Canvas는 선택·배치할 보고서 요소, TA-Lib 에이전트는 보다 넓은 함수 탐색과 계산 조합에 초점을 둡니다.

04 · SEC 공시 검색과 리서치

기업에 관한 답변은 어떤 공시를 사용했는지, 어떤 원문이 근거인지 함께 살펴봐야 합니다.

9. tenk_subgraph

질문과 선택적 공시 정보를 받아 RetrievalService로 검색·답변을 수행합니다. 결과 상태에는 답변과 함께 의도, 근거 목록이 담깁니다.

START → retrieve_and_answer → END

예: 선택한 공시에서 질문에 관련된 내용을 검색하고 근거와 함께 답변합니다. 외부에서 등록 그래프로도 실행할 수 있는 단일 노드 구성입니다.

10. sec_deep_agent

기업·공시·원문 조회 도구와 게시된 SEC 모델링 조회 도구를 사용하는 리서치 및 수집 Deep Agent입니다. 복잡한 요청에 계획을 세우고 필요할 때 도구를 선택해 Markdown 보고서를 작성합니다.

질문 → 계획 → 기업·공시 검색 → 원문·모델링 근거 확인 → 보고서

기본적으로 저장된 자료부터 확인하며, 최신 확인이나 수집 요청은 해당 도구로 수행합니다. 도구 결과의 CIK·접수번호를 사용하고, 보고서에서 출처·기간·한계를 구분하도록 지시합니다. 가상 파일은 그래프 상태에 속합니다.

SEC Research Chat과의 관계: /sec-chat은 별도의 대화·공시 분석·OpenUI 흐름을 사용합니다. 기업이 확정된 뒤 저장된 10-K 준비는 실제 도구를 서버가 정해진 순서로 실행합니다. 따라서 화면 이름과 등록 그래프 ID를 같은 것으로 취급하면 안 됩니다.

05 · SEC 모델링과 전체 비교

11. sec_modeling_agent

SEC 모델링 관련 도구를 사용하는 Deep Agent를 채팅 상태에 연결합니다. 먼저 표시 상태를 준비하고, 모델링 에이전트가 도구를 통해 요청을 처리합니다.

START → prepare → inspect_modeling [Deep Agent · 모델링 도구] → END

예: 모델링 도구와 그 결과를 살펴보는 요청에 사용합니다. 실제 가능한 작업 범위는 연결된 도구와 권한, 데이터 상태에 따라 달라집니다.

용어와 코드 탐색

ToolNode: 모델이 요청한 도구를 실행하는 그래프 노드입니다. Deep Agent: 도구와 계획 등 복잡한 작업을 위한 기능을 갖춘 에이전트 구성입니다. OpenUI: 결과를 화면의 표·차트·텍스트 등으로 표현하는 출력 경로입니다. 근거: 답변을 뒷받침하는 원문이나 계산 결과입니다.

등록 목록은 langgraph.json, 각 구현은 graph 디렉터리, 런타임과 설계 문서는 LangGraph 기술 문서 지도에서 확인할 수 있습니다.

이 문서는 등록된 workflow와 현재 설계 문서를 설명하기 위한 학습 자료입니다. 실제 가용 데이터·모델·도구와 실행 결과는 환경과 요청에 따라 달라집니다.
