# 청월당 사주·타로 통합 시스템·개발 설계

> 상태: 작성 대기. 대상 서비스 내부 구현을 복원했다고 주장하지 않는다. 개발 구조는 제안 또는 합의 상태로 표시한다.

## 제품 책임과 시스템 경계

{탐색, 프로필, 사주 계산, 타로 선택, 콘텐츠 생성, 결제, 이용권, 보관 각각의 책임과 경계. 제품 흐름과 책임을 연결한다.}

## 도메인별 처리 연결

{입력 검증 → 결과를 만드는 처리 → 저장 → 열람까지의 단계와 결제·권리 부여의 실제 또는 제안 순서. 외부 서비스가 필요한 지점을 표시한다.}

## 상태와 실패

| 대상 | 상태·전이 소유 문서 | 완료 조건 | 실패·재시도 | 사용자 화면 |
| --- | --- | --- | --- | --- |
| {주문/이용권/결과 작업/프로필/카드 선택} | {BR·계약 링크} | {조건} | {정책} | {SC/UI 링크} |

## 계약과 데이터

{[데이터·서비스 계약](06-data-service-contracts.md)의 엔터티, 필수 필드, 관계, 검증, 오류, 멱등성과 수명 주기를 요약한다. 기술 스택은 근거 또는 선택 결정이 있을 때만 적는다.}

## 화면·콘텐츠·에셋

{[화면 계약](04-ux-screen-contracts.md), [생성·콘텐츠](05-generation-content-operations.md), [시각 자산](09-design-system-assets.md)의 핵심 버전과 의존성을 연결한다.}

## 운영·측정·품질

{결과 생성 지연·실패, 결제와 이용권 불일치, 고객 재열람 문제의 탐지·복구를 정의한다. [지표](07-events-metrics.md), 비기능 요구사항·인수 기준을 연결한다.}

## 개발 착수와 검증

{FR → BR/UI/데이터/API → AC 추적표와 차단 이슈. 합의되지 않은 계산·카드 결정·유료 이용권 정책이 무엇인지 명시한다.}

## 완료 기준

개발자가 정상·실패 흐름과 저장·권한·비용 영향을 설명할 수 있으며, 구현 시 추가로 결정해야 할 항목이 명시되어 있어야 한다.
