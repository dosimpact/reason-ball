# 청월당 역기획 프로젝트 계약

## 목적

청월당의 화면을 복제하는 데 그치지 않고, 사용자의 탐색과 입력부터 결과 생성, 결제, 결과 보관과 재방문까지 서비스가 작동하는 구조와 의도를 재구성한다. 최종 문서는 제품·디자인·프런트엔드·백엔드·콘텐츠 담당자가 추가 해석 없이 개발 논의를 시작할 수 있어야 한다.

## 현재 단계와 문서 성격

현재는 문서 골격 정의 단계다. 각 파일의 질문·예시 행·후보 엔터티는 관찰 사실이 아니다. 실제 탐색에서는 팩트북만 채우고, 조사 완료 판정 후 분석 본문과 제안 명세를 작성한다. 이 디렉터리는 외부 서비스 연구 자료이며 현재 저장소에 구현된 기능을 설명하는 stock 문서를 대체하지 않는다.

분석 범위는 앞서 확정한 사주·운세와 타로 두 도메인이다. 후속 요청에 인용된 초기 사주 전용 계획은 사주 트랙의 상세 기준으로 반영한다.

- 상품·화면·여정·기능이 복잡하면 [개별 기록 틀](templates/INDEX.md)로 하위 파일을 추가한다. 파일 수에 제한을 두지 않는다.
- 새 파일은 목적, 적용 범위·상태, 읽어야 할 상위 문서, 상세 내용, 증거, 미결정, 다음 연결을 갖춘다.
- 공통 규칙은 한 원본에서 관리하고 각 상품에는 실제로 확인한 차이를 적는다.
- 실제 기록에 고정 ID·앵커를 부여하고 다른 문서는 파일·앵커 링크를 사용한다.
- 많은 표만으로 맥락을 대신하지 않는다. 분석 파일은 문제·원인·대안·선택 이유·영향을 문장으로 설명한다.
- 완성된 단일 문서 템플릿은 참조용이며 실제 하위 문서와 중복 갱신하지 않는다.

## 분석 범위

### 사주·운세

- 오늘의 운세
- 무료·유료 사주 콘텐츠
- 사주 상품 탐색과 추천
- 생년월일시 등 사주정보 입력
- 결과 생성·열람·보관
- 결제와 구매 완료 전후 흐름
- 회원·비회원 및 구매 상태별 흐름

### 타로

- 무료·유료 타로 콘텐츠
- 질문·주제 선택
- 카드 선택과 스프레드
- 카드 공개와 조합 해석
- 결과 생성·열람·보관
- 상품 탐색·추천·결제·재방문

### 공통 플랫폼

- 홈, 카테고리, 검색, 상품 상세, 로그인, 결제, 보관함
- 개인화 추천, 리뷰, 순위, 시즌성 노출
- UI, 이미지, 일러스트, 캐릭터, 모션과 반응형 배치
- 데이터·상태·이벤트·오류·운영 요구사항

### 제외

- 자미두수, 꿈해몽, 관상, 손금, 풍수, 작명, 이름풀이, 부적, 심리테스트
- 매거진과 SEO 전략
- 운영자 백오피스의 상세 화면 설계

제외 기능이 로그인, 결제, 보관, 상품 카탈로그 등 공통 기능을 공유하면 해당 공통 동작만 조사한다.

## 증거 우선순위

1. 실제 화면에서 실행한 동작과 전후 캡처
2. 실제 화면의 DOM·접근성 정보와 표시 문구
3. 사이트의 공개 정책·약관·안내
4. 복수 관찰을 기반으로 한 추론
5. 내부 구조를 설명하기 위한 가설

## 작성 단계

```text
화면·행동 전수 조사
  -> 팩트북 작성
  -> 커버리지 감사
  -> 사실 기반 분석
  -> 비즈니스·시스템 가설
  -> 기능·데이터·화면 요구사항
  -> 인수 기준과 구현 우선순위
```

## 조사 완료 게이트

전수 조사의 단위는 발견한 상품 × 화면 × 조작 요소 × 적용 가능한 사용자·뷰포트 상태다. 대표 사례 조사와 상품별 직접 확인을 구분하고, 공통 UI라고 다른 상품의 확인으로 대체하지 않는다. 등록되지 않은 화면·행동이 새로 발견되면 범위를 추가하고 커버리지를 다시 계산한다.

일부러 실서비스 결제 오류를 만들거나 서버 장애를 유발하지 않는다. 안전한 방법으로 실행할 수 없는 상태는 차단으로 남긴다. 실결제와 개인정보 입력은 기존 합의대로 실행 전에 별도로 확인한다.

- [ ] 공통, 사주, 타로의 모든 발견 화면이 등록되었다.
- [ ] 조작 가능한 요소가 확인·차단·범위 제외 중 하나로 분류되었다.
- [ ] 정상, 로딩, 완료, 오류, 중단, 재진입 상태를 확인했다.
- [ ] 비회원·회원·구매 상태와 주요 뷰포트 차이를 확인했다.
- [ ] 모든 Fact ID가 화면 캡처 또는 동작 기록과 연결되었다.
- [ ] 남은 차단 사항과 분석 영향이 명시되었다.
- [ ] 남은 차단 항목이 없거나 사용자가 구체적인 조사 제한을 수용했다.

차단을 수용해도 해당 동작을 확인 완료로 바꾸지 않는다. 보고 시 확인 비율과 수용된 제한을 별도로 표시한다. 내부 알고리즘은 화면 조사 완료 이후에도 가설로 남을 수 있다.

## 개발 착수 완료 기준

- [ ] 핵심 사용자와 JTBD가 정의되었다.
- [ ] 공통·사주·타로의 경계와 전체 사용자 여정이 정의되었다.
- [ ] 화면별 데이터, 상태, CTA, 권한, 오류 처리가 명세되었다.
- [ ] 입력·결과 콘텐츠 계약과 데이터 모델이 명세되었다.
- [ ] 가격·결제·환불·보관·재열람 정책이 정리되었다.
- [ ] UI·이미지·캐릭터 방향이 최신 트렌드 조사와 연결되었다.
- [ ] 분석 이벤트, KPI, 비기능 요구사항이 정의되었다.
- [ ] 모든 MVP 요구사항에 검증 가능한 인수 기준이 있다.
