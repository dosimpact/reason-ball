# 구현 검증 원칙

변경 내용을 아래 기준으로 분류하고 해당하는 검증을 모두 수행한다. 이 디렉토리는 검증 절차의 원본이며, 공통 적용 정책과 패키지별 명령은 [공통 검증 설계](../stock/shared/test-design.md)에서 연결한다.

| ID | 변경 유형 | 필수 검증 |
| --- | --- | --- |
| VAL-API-001 | 서버 API 계약 또는 동작 변경 | [Bruno API 수준 E2E](server-api.md) |
| VAL-VIEW-001 | 순수 View 컴포넌트 변경 | [Storybook 테스트](pure-view.md) |
| VAL-BROWSER-001 | 비즈니스 로직이 포함된 변경 | [MCP를 통한 사용자 관점 브라우저 검증](business-behavior.md) |

설치와 연결 확인은 [workspace README의 MCP 가이드](../../README.md#검증용-mcp-설치-및-연결)를 따른다.

## 적용과 완료 기준

- API와 화면을 함께 변경하면 해당 검증을 누적 적용한다. 단위 테스트, lint, typecheck, build는 필수 검증을 대체하지 않는다.
- 검증 전에 요구사항 또는 결정 ID와 Given/When/Then 시나리오, 예상 결과를 정한다.
- 필수 검증을 실제로 실행하고 실패를 수정한 후 영향받는 시나리오를 다시 검증한다.
- 환경·인증·MCP 도구가 없어 수행하지 못하면 사유와 후속 조치를 기록하고 검증 미완료로 보고한다. SKIP을 PASS나 완료로 간주하지 않는다. 사용자에게 명시적으로 승인받은 예외만 예외로 기록한다.
- 브라우저로 접근할 경로가 없는 서버 전용 비즈니스 로직은 API E2E를 수행하고, 브라우저 검증의 적용 경로 부재를 기록한다. 임의로 면제하지 말고 사용자에게 적용 범위 확인을 요청한다.
- 문서만 변경한 경우 링크·구조·diff를 검사한다. API·View·비즈니스 동작의 변경이 없으면 세 실행 검증은 적용 대상이 아니다.
- 관련 없는 개발 서버를 재사용하거나 종료하지 않는다. 테스트가 소유한 서버와 임시 데이터는 정리하고 기존 사용자 데이터는 보존한다. DB 통합 테스트의 opt-in 정책은 유지하되 필수 E2E 생략 근거로 사용하지 않는다.

## 검증 증거

날짜별 [flow](../flow/) 기록에 변경 범위, 적용한 VAL ID, 시나리오, 실행 명령 또는 MCP 도구, 대상 환경, 예상/실제 결과, PASS/FAIL/SKIP 수, 로그·스크린샷·리포트 위치, 미해결 사항을 남긴다. 토큰·개인정보는 증거에 포함하지 않는다. 상세 실행 산출물은 프로젝트의 기존 저장·제외 규칙을 따른다.
