# VAL-API-001: 서버 API E2E

## 적용 범위

엔드포인트, 요청·응답, 인증·권한, 오류 처리, 저장·조회 또는 API가 노출하는 업무 동작이 변경되면 API 수준 E2E를 반드시 수행한다.

## 기준 스킬

[apb-bruno-api-tests SKILL.md](../../../../.agentic-playbook-rc/apb-bruno-api-tests/SKILL.md)를 읽고 Inspect → Scaffold → Author → Run 원칙을 적용한다. 링크는 이 문서 기준 상대경로이며, 프로젝트 루트에서는 `../../.agentic-playbook-rc/apb-bruno-api-tests/SKILL.md`이다.

## 절차

1. 관련 stock과 요구사항에서 Given/When/Then 시나리오를 도출하고 기존 서비스의 Bruno 컬렉션과 실행 환경을 확인한다. 기존 컬렉션 경로를 우선 사용한다.
2. 변경에 필요한 `.bru` 시나리오를 작성·수정한다. 스킬의 컬렉션·번호 폴더·환경 변수·`assert` 및 `tests` 구조를 따르고 요구사항 ID를 연결한다. 비밀값을 파일에 직접 넣지 않는다.
3. 정상 동작과 변경에 관련된 오류·경계 조건을 검증한다. 상태 코드뿐 아니라 응답 내용과 저장 후 조회 등 관찰 가능한 결과도 확인한다.
4. 실행 중인 테스트 대상 서버에 실제 HTTP 요청을 보내 E2E를 실행한다. 내부 함수 호출이나 전체 서버를 대체한 mock 테스트만으로 완료하지 않는다.
5. 커밋된 패키지 실행 스크립트를 우선 사용한다. 스크립트가 없으면 스킬의 Bruno CLI 실행 방법을 해당 컬렉션과 환경에 맞게 적용한다. 필요한 DB·인증·fixture를 준비하고 데이터 변경 범위를 명확히 한다.
6. 실행 로그와 시나리오별 결과를 [공통 증거 규칙](README.md)에 따라 flow에 남긴다. 요청 파일 작성이나 Bruno 앱 실행만으로 검증 완료를 선언하지 않는다.

패키지별 컬렉션과 명령은 [공통 검증 설계](../stock/shared/test-design.md) 및 해당 도메인 stock을 따른다.
