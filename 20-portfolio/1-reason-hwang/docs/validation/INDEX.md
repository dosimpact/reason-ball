# 구현 검증 원칙

변경 내용을 아래 기준으로 분류하고 해당하는 검증을 모두 수행한다. 이 디렉토리는 검증 절차의 원본이며, 공통 적용 정책과 패키지별 명령은 [공통 검증 설계](../stock/tech-shared/test-design.md)에서 연결한다.

| ID | 변경 유형 | 필수 검증 |
| --- | --- | --- |
| VAL-API-001 | 서버 API 계약 또는 동작 변경 | [Bruno API 수준 E2E](server-api.md) |
| VAL-VIEW-001 | 순수 View 컴포넌트 변경 | [Storybook 테스트](pure-view.md) |
| VAL-BROWSER-001 | 비즈니스 로직이 포함된 변경 | [MCP를 통한 사용자 관점 브라우저 검증](business-behavior.md) |

설치와 연결 확인은 [workspace README의 MCP 가이드](../../README.md#검증용-mcp-설치-및-연결)를 따른다.

## 적용과 완료 기준

- API와 화면을 함께 변경하면 해당 검증을 누적 적용한다. 단위 테스트, lint, typecheck, build는 필수 검증을 대체하지 않는다.
- 검증 전에 요구사항 또는 결정 ID와 Given/When/Then 시나리오, 예상 결과를 정한다.
- 필수 검증을 실제로 실행하고 실패를 수정한 후 영향받는 시나리오를 다시 검증한다.
- 환경·인증·MCP 도구가 없어 수행하지 못하면 사유와 후속 조치를 기록하고 검증 미완료로 보고한다. SKIP을 PASS나 완료로 간주하지 않는다. 사용자에게 명시적으로 승인받은 예외만 예외로 기록한다.
- 브라우저로 접근할 경로가 없는 서버 전용 비즈니스 로직은 API E2E를 수행하고, 브라우저 검증의 적용 경로 부재를 기록한다. 임의로 면제하지 말고 사용자에게 적용 범위 확인을 요청한다.
- 문서만 변경한 경우 링크·구조·diff를 검사한다. API·View·비즈니스 동작의 변경이 없으면 세 실행 검증은 적용 대상이 아니다.
- 관련 없는 개발 서버를 재사용하거나 종료하지 않는다. 테스트가 소유한 서버와 임시 데이터는 정리하고 기존 사용자 데이터는 보존한다. DB 통합 테스트의 opt-in 정책은 유지하되 필수 E2E 생략 근거로 사용하지 않는다.

## VAL-CLEANUP-001: 검증 자원 정리

모든 실행 검증에 적용한다. 성공·실패·시간 초과·중단 시에도 정리하며, 자동화 코드는 `finally` 또는 종료 trap으로 정리를 보장한다. 강제 종료로 정리하지 못했다면 작업 재개 시 잔존 자원부터 확인한다.

1. **소유 범위 기록**: 실행 전에 기존 서버·브라우저와 작업이 새로 생성하는 자원을 구분한다. 생성한 자원의 PID/부모 PID, 실행 명령, 포트, 도구 세션·탭 식별자, 임시 프로필·데이터 경로 중 해당 항목을 기록한다. 명령이나 URL에 포함된 인증 정보는 기록하지 않는다.
2. **정상 종료 우선**: 필요한 로그·스크린샷을 저장하고 진행 중인 검증을 중지한 뒤 도구의 공식 종료·연결 해제 기능을 사용한다. 브라우저는 [MCP/CDP 정리 절차](business-behavior.md#browser-cleanup)를 따른다. 직접 시작한 개발·Storybook·테스트 서버와 작업 전용 MCP 프로세스도 종료한다. 공유 또는 도구 호스트가 관리하는 MCP 서버는 임의로 종료하지 않는다.
3. **잔존 프로세스 처리**: 정상 종료 후에도 남으면 기록한 PID와 현재 명령·부모 관계를 다시 확인하고 소유한 프로세스에만 TERM을 보낸다. 제한 시간 내 종료되지 않을 때만 소유권을 재확인한 PID에 KILL을 사용한다. 포트 점유만으로 소유권을 판단하지 않는다. `pkill chrome`, `killall node`, 이름 패턴 기반 일괄 종료는 금지한다.
4. **임시 자원 정리**: 프로세스 종료 후 이번 작업이 만든 임시 프로필·데이터만 삭제한다. 사용자 Chrome 프로필·탭·로그인 정보·기존 데이터와 검증 증거는 보존한다.
5. **종료 확인**: 도구 세션 상태와 `ps -p <PID> -o pid,ppid,command`, `lsof -nP -iTCP:<PORT> -sTCP:LISTEN` 등으로 해당 프로세스·자식 프로세스·리스닝 포트의 잔존 여부를 확인한다. 기존 사용자/공유 자원은 유지 대상임을 구분한다. 도구의 성공 응답이나 탭이 닫힌 것만으로 프로세스 종료를 단정하지 않는다.
6. **완료 증거**: flow에 생성/유지 대상, 정리 방법, 종료 확인 결과, 잔존 자원과 사유를 기록한다. 도구 제약으로 정리 또는 종료 확인이 불가능하면 기능 검증 결과와 별도로 **정리 미완료** 및 후속 조치를 보고하며 작업 전체를 완료로 처리하지 않는다.

## 검증 증거

날짜별 [flow](../flow/) 기록에 변경 범위, 적용한 VAL ID, 시나리오, 실행 명령 또는 MCP 도구, 대상 환경, 예상/실제 결과, PASS/FAIL/SKIP 수, 로그·스크린샷·리포트 위치, 미해결 사항을 남긴다. 토큰·개인정보는 증거에 포함하지 않는다. 상세 실행 산출물은 프로젝트의 기존 저장·제외 규칙을 따른다.
