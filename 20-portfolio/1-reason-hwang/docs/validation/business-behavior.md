# VAL-BROWSER-001: 사용자 관점 브라우저 검증

## 적용 범위

업무 계산, 입력 검증, 저장·조회, 인증·권한, 화면 간 이동, API 연동 등 비즈니스 로직이 포함된 변경은 사용자 관점에서 브라우저 수준 동작을 반드시 검증한다.

## 필수 도구

Playwright MCP 또는 Chrome DevTools MCP로 실제 브라우저를 제어한다. 도구 제공 환경의 사용 지침을 먼저 읽는다. Playwright CLI 테스트나 단위 테스트만으로 이 MCP 검증을 대신하지 않는다. 두 MCP가 모두 없으면 [공통 완료 기준](README.md)에 따라 미완료와 필요한 도구를 보고한다.

## 절차

1. 관련 요구사항에서 사용자의 시작 화면, 사전 데이터·권한, 입력·행동, 최종 결과를 Given/When/Then으로 정한다.
2. 테스트 환경의 실제 애플리케이션을 브라우저로 열고 사용자가 하는 클릭·입력·이동을 수행한다. 내부 함수를 직접 호출해 화면 동작을 우회하지 않는다.
3. 정상 흐름과 변경에 관련된 실패·경계 조건을 검증한다. 화면 결과와 상태 변화를 확인하고, 저장 기능이면 새로고침 또는 재조회 후 유지 여부도 확인한다.
4. 관련 콘솔 오류와 네트워크 실패를 점검한다. 실제 연동 검증인지 통제된 fixture 검증인지 기록하며, 실제 연동을 검증하지 않은 결과를 연동 성공으로 보고하지 않는다.
5. 사용한 MCP 도구, URL, 시나리오별 실제 결과와 필요한 스크린샷·로그를 [공통 증거 규칙](README.md)에 따라 기록한다. 실패 수정 후 관련 사용자 흐름을 다시 실행한다.

API도 변경되면 [API E2E](server-api.md)를 함께 수행한다. 회귀 자동화가 필요하면 기존 `1-fe-host/tests/e2e/` 관례를 따라 Playwright 테스트를 보강하되 MCP 사용자 검증 증거도 남긴다.
