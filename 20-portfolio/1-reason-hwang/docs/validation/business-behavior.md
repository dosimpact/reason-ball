# VAL-BROWSER-001: 사용자 관점 브라우저 검증

## 적용 범위

업무 계산, 입력 검증, 저장·조회, 인증·권한, 화면 간 이동, API 연동 등 비즈니스 로직이 포함된 변경은 사용자 관점에서 브라우저 수준 동작을 반드시 검증한다.

## 필수 도구

Playwright MCP 또는 Chrome DevTools MCP로 실제 브라우저를 제어한다. 도구 제공 환경의 사용 지침을 먼저 읽는다. Playwright CLI 테스트나 단위 테스트만으로 이 MCP 검증을 대신하지 않는다. 두 MCP가 모두 없으면 [공통 완료 기준](INDEX.md)에 따라 미완료와 필요한 도구를 보고한다.

## 절차

1. [VAL-CLEANUP-001](INDEX.md#val-cleanup-001)에 따라 기존 자원과 이번 검증의 소유 자원을 구분하고 종료 방법을 확인한다. 관련 요구사항에서 사용자의 시작 화면, 사전 데이터·권한, 입력·행동, 최종 결과를 Given/When/Then으로 정한다.
2. 테스트 환경의 실제 애플리케이션을 브라우저로 열고 사용자가 하는 클릭·입력·이동을 수행한다. 내부 함수를 직접 호출해 화면 동작을 우회하지 않는다.
3. 정상 흐름과 변경에 관련된 실패·경계 조건을 검증한다. 화면 결과와 상태 변화를 확인하고, 저장 기능이면 새로고침 또는 재조회 후 유지 여부도 확인한다.
4. 관련 콘솔 오류와 네트워크 실패를 점검한다. 실제 연동 검증인지 통제된 fixture 검증인지 기록하며, 실제 연동을 검증하지 않은 결과를 연동 성공으로 보고하지 않는다.
5. 사용한 MCP 도구, URL, 시나리오별 실제 결과와 필요한 스크린샷·로그를 [공통 증거 규칙](INDEX.md)에 따라 기록한다. 실패 수정 후 관련 사용자 흐름을 다시 실행한다.
6. 성공·실패·중단 시 아래 MCP/CDP 정리 절차를 수행하고 잔존 여부와 정리 결과를 flow에 기록한다.

API도 변경되면 [API E2E](server-api.md)를 함께 수행한다. 회귀 자동화가 필요하면 기존 `1-fe-host/tests/e2e/` 관례를 따라 Playwright 테스트를 보강하되 MCP 사용자 검증 증거도 남긴다.

## MCP/CDP 정리 절차

- **Playwright MCP**: 현재 제공되는 도구 설명을 확인하고 작업이 만든 페이지·컨텍스트·브라우저를 지원되는 종료 도구로 정리한다. 종료 도구가 공유 브라우저 전체에 영향을 주는지 먼저 확인한다. 도구에 없는 명령을 가정하지 말고, 연결 종료와 실제 브라우저 프로세스 종료를 각각 확인한다.
- **Chrome DevTools MCP / CDP**: 기존 사용자 브라우저에 연결했다면 작업이 만든 탭만 닫고 지원되는 방식으로 자동화 연결을 해제한다. 사용자 브라우저 전체를 닫거나 기존 디버깅 포트를 강제로 해제하지 않는다. 작업이 직접 실행한 전용 Chrome이라면 연결 정리와 함께 해당 Chrome 및 자식 프로세스를 종료하고 전용 CDP 포트가 해제됐는지 확인한다.
- **MCP 수명 구분**: 작업 전용으로 직접 실행한 MCP 서버는 브라우저 정리 후 종료한다. 공유 또는 도구 호스트가 관리하는 MCP 서버는 유지하며, 작업의 브라우저 자원만 정리한다. 연결 해제 기능이 없거나 소유권이 불명확하면 임의의 프로세스를 종료하지 말고 잔존 항목·제약을 기록한다.
- **공통 종료 확인**: 서버·임시 프로필을 포함한 잔존 검사와 미완료 보고는 [VAL-CLEANUP-001](INDEX.md#val-cleanup-001)을 따른다. MCP 연결 해제만으로 Chrome 자식 프로세스까지 종료됐다고 간주하지 않는다.
