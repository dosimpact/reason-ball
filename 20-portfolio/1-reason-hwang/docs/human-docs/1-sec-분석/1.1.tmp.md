AWS GraphRAG Toolkit 논의 정리

1. 최종 목표

여러 기업의 사업보고서(10-K)를 분석해, 기업 간 관계와 재무·사업 변화를 추적하는 Knowledge Graph 기반 투자 분석 Agent 구축

예시 질문:

* 삼성전자와 SK하이닉스의 HBM 경쟁력은 어떻게 변화했는가?
* 엔비디아의 AI 투자 확대가 메모리 기업에 미치는 영향은?
* 특정 기업의 매출 성장 원인과 주요 리스크는 무엇인가?

2. 검토한 기술

기술	핵심 역할	판단
Lexical Graph	문서에서 지식 그래프 자동 생성	채택 검토
BYOKG-RAG	기존 지식 그래프 검색	보조적으로 검토
Ontology	엔티티·관계 타입 표준화	필요
Entity Resolution	동일 개념 식별 및 중복 해결	핵심 과제
XBRL	정확한 재무 수치 추출	필요
LangGraph	Agent 오케스트레이션	활용 가능

3. 제안 아키텍처

10-K / 사업보고서 수집

SEC EDGAR · DART · HTML · XBRL

① 문서 파싱

Item 1, 1A, 7, 8 등 섹션별 분리

② 정량 추출

XBRL 기반 재무지표

③ 정성 추출

LLM 기반 엔티티·관계·근거

④ Entity Resolution

표준 ID → Alias → 유사도 검색 → LLM 판별

⑤ Knowledge Graph 구축

기존 엔티티 재사용 · 관계 및 출처 연결

Neo4j

지식 그래프

PostgreSQL

정형 재무 데이터

⑥ LangGraph 투자 분석 Agent

기업 간 비교 · 성장 원인 · 리스크 · 근거 추적

제안 아키텍처이며, AWS GraphRAG Toolkit이 전체 파이프라인을 자동 제공한다는 뜻은 아닙니다.

4. 가장 중요한 기술적 쟁점

Entity Resolution: 서로 다른 보고서의 개념을 어떻게 연결할 것인가?

추출된 용어	처리
HBM / High Bandwidth Memory	동일 엔티티로 통합
HBM3E / HBM4	별도 엔티티, 공통 상위 개념에 연결
DRAM / HBM	상위·하위 관계
Memory Solutions / Memory Products	문맥 분석 후 결정

단순 문자열 매칭만으로 해결할 수 없습니다.

권장 순서는 정확한 식별자 매칭 → Alias → Embedding 후보 검색 → LLM 판별 → 불확실한 경우 병합 보류입니다.

또한 원본 보고서, 해당 연도, 근거 문장을 반드시 보존해야 합니다.

5. AWS Toolkit의 지원 범위

기능	Toolkit 활용
비정형 문서에서 엔티티·관계 추출	Lexical Graph
원본 문서와 사실 연결	Lexical Graph
엔티티·관계 타입 제어	Ontology-Guided Extraction
기존 그래프 검색	BYOKG-RAG
전문 용어의 의미적 동일성 판단	별도 구현·검증 필요
XBRL 재무 수치 정규화	별도 구현 필요

6. 권장 POC

처음부터 전체 기업을 처리하기보다 다음 범위로 검증합니다.

* 문서: NVIDIA, 삼성전자, SK하이닉스의 최근 2~3개년 보고서
* 범위: 사업 설명, 성장 요인, 위험 요인
* 추출: Lexical Graph와 커스텀 Structured Output 비교
* 연결: HBM·DRAM·AI 서버 등 공통 엔티티 식별
* 평가: 추출 정확도, 잘못된 병합률, 근거 추적률, 비용

최종 결론

현재는 Lexical Graph를 무조건 채택하기보다, 10-K의 표준화된 구조를 활용하는 커스텀 추출 방식과 비교하는 것이 합리적입니다.

이 프로젝트의 핵심 기술은 세 가지입니다.

* Extraction: 보고서에서 정확한 사실 추출
* Entity Resolution: 여러 기업의 공통 개념 연결
* Provenance: 추출된 사실의 출처·기간·근거 보존

이 세 가지가 검증되면, 보고서가 추가될수록 기업 간 관계와 시간에 따른 변화를 분석할 수 있는 Knowledge Graph를 구축할 수 있습니다.
