데이터 경계

  • 원본 HTML 전체는 PostgreSQL에 보존합니다.
  • Neo4j에는 가공된 Item HTML·텍스트와 추출 결과를 저장합니다.
  • 검색과 근거 화면은 PostgreSQL 원문을 다시 읽지 않고 동작합니다.
  • 모델링 2는 게시된 Item을 입력으로 사용하고, 모델링 3은 원본 XBRL을 독립 처리합니다.

선택한 구성

  • SEC 전용 스키마와 Lexical Graph를 함께 사용합니다.
  • Neo4j 5.26 내장 벡터 인덱스를 사용합니다.
  • Qdrant·pgvector·Redis는 추가하지 않았습니다.
  • 임베딩은 text-embedding-3-small, 1,536차원입니다.
  • 추출 OAuth proxy와 임베딩 API 자격 증명을 분리했습니다.

02. 모델링별 구현 내용

모델링 1 · 공시의 문서 구조

Company ──FILED──▶ Filing ──HAS_ITEM──▶ Item

CIK로 기업을, accession number로 공시를 식별합니다. 목차와 본문을 구분해 Item 경계를 찾고 제목·문단·목록·표 구조를 보존한 displayHtml과 검색용 text를 저장합니다.

  • 본문 XBRL 태그는 벗기고 표시값을 유지합니다.
  • 스크립트·숨겨진 메타데이터·외부 자원은 제거합니다.
  • 원본 해시·가공 결과 해시·파서 버전으로 변경을 추적합니다.
  • 원본 위치 재조회는 필수 의존성이 아닙니다.

모델링 2 · 본문 검색과 근거

Item ↔ Source
        └─ Chunk → Topic · Statement · Fact · Entity
              └─ Chunk / Statement 임베딩 → Neo4j 벡터 검색

6종은 지원하는 개념입니다. 모든 노드를 위 순서의 단일 직렬 관계로 연결한다는 뜻은 아닙니다.

  • Item 하나를 Source 하나에 명시적으로 연결합니다.
  • 문서 순서·소제목·문단 경계를 따르고 표 헤더·단위·설명을 함께 유지합니다. 청킹 기본 목표는 800토큰, 문장 overlap은 최대 80토큰입니다.
  • 고정 버전 graphrag-lexical-graph==3.21.0을 사용합니다. 추출 모델은 OAuth proxy의 sol 기본, luna 선택 방식입니다.
  • 청크마다 중요 진술 최대 20개를 추출하도록 요청하고, 전체 Chunk 원문은 별도로 보존합니다.
  • Chunk와 Statement를 임베딩하고 두 검색 순위를 결합합니다. Fact와 Entity까지 전부 임베딩하지 않습니다.
  • 공백·줄바꿈 보존을 보완했으며, 변경되지 않은 입력은 추출·임베딩 캐시를 재사용합니다.

모델링 3 · SEC/XBRL 재무 지식

Filing ──HAS_XBRL_FACT──▶ XbrlFact
                           ├─ OF_CONCEPT ──▶ Concept
                           ├─ IN_UNIT ────▶ Unit
                           └─ IN_CONTEXT ─▶ Context ──FOR_ENTITY──▶ Company
                                                └─ DimensionValue
                                                     ├─ Dimension
                                                     └─ Member (explicit 차원)
  • arelle-release==2.47.5와 SEC transformation을 사용해 원본 Inline XBRL·taxonomy를 해석합니다.
  • 지표 namespace, 기간, 단위, explicit/typed 차원, scale·sign·format·nil을 처리합니다.
  • 원래 표시값과 정규화한 값을 함께 보존하며 수치는 decimal 문자열로 저장합니다.
  • 중복 출현과 값 차이를 구분합니다. 같은 지표·기간이라는 이유로 덮어쓰지 않습니다.
쿠팡 실제 예: f-57
표시값 26,312 × 106 → 26,312,000,000 USD
2025년 기간, 상품 분류의 매출 사실입니다. c-7은 해당 문서의 Context 식별자이며 고정된 정보 카테고리가 아닙니다.

현재 conflict 표시는 동일 지표·맥락·차원·단위에서 정규화한 값이 다름을 뜻합니다. 반올림 허용 구간까지 판단한 회계 오류 확정값은 아닙니다.

03. 작업 관리 · Admin · 검색

영속 작업 관리

  • PostgreSQL sec_modeling 스키마의 jobs / runs / work_units / events
  • 중복 활성 실행 방지, 단일 실행기, lease·heartbeat
  • execution token으로 오래된 실행기의 갱신·게시 차단
  • 취소·재시도·실행 이력·게시 후 상태 복구
  • 실패·취소 시 기존 성공 결과 유지

Admin /sec-modeling

  • CIK 필터와 공시별 모델링 상태
  • 각 단계 실행, 추출 모델 선택, 취소·재시도
  • 진행 이벤트와 작업 단위 조회
  • Item HTML·텍스트, lexical 결과, XBRL 사실 조회
  • 검색 → 근거 보기 → 연결된 Chunk와 sandbox Item HTML

결과는 generation별로 생성한 뒤 검증을 거쳐 게시합니다. 검색·결과 목록은 활성 결과를 사용합니다. 과거에 게시된 evidence ID도 인용 재현을 위해 조회할 수 있고 isActive로 현재 결과 여부를 표시합니다. 처리 중 초안은 공개하지 않습니다.

인터페이스책임

LangGraph에는 search_sec_evidence, query_sec_xbrl_facts, get_sec_evidence 도구를 연결했습니다. 검색 API는 근거를 반환하며 최종 답변 작성은 Agent가 담당합니다. 기존 mock pipeline·extractor·graph mapper·/api/tenk/* 경로는 제거하고 기존 그래프 데이터는 보존했습니다.

구현 커밋에는 100개 파일의 코드·문서·테스트 변경이 포함됩니다. 이 HTML은 해당 커밋 이후 요청받아 작성한 보고서입니다. 기존 사용자 변경과 원본 보고서·런타임 산출물은 구현 커밋에 포함하지 않았습니다.
