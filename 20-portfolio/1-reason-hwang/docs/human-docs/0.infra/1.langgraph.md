## LangGraph 런타임 관리  

GraphRegistry : 
- langgraph.json에 정의된 그래프 목록을 읽어 실제 StateGraph 빌더를 실행 시점에 컴파일
- 각 그래프마다 고유한 UUID의 기본 Assistant를 자동 등록  
- 한 쓰레드(thread_id)에는 반드시 하나의 그래프만 매핑되도록 보장  

실행과 HTTP 생명주기 분리
- 클라이언트가 브라우저 창을 닫아 SSE 연결이 끊겨도 백그라운드 LangGraph 실행은 asyncio.shield로 보호  
- 완료 시점까지 DB에 체크포인트를 안전하게 기록함.  


Redis 없는 PostgreSQL 기반 Multi-Worker 런타임  
- 글로벌 용량 제어 (Global Cap): runtime_capacity 테이블 행을 잠가 전체 워커 합산 동시 실행(Active) 및 대기(Queued) 한도를 제어합니다(초과 시 429 Too Many Requests).  
- FOR UPDATE SKIP LOCKED 기반 FIFO 큐: 동일 쓰레드의 요청은 순서대로(FIFO) 실행하되, 다른 쓰레드의 요청은 락 대기 없이 즉시 다른 워커가 가져가 병렬 처리합니다.
- Fencing Token (FencedAsyncPostgresSaver): 워커마다 Heartbeat(5초)와 Lease(30초)를 둡니다. 일시 정지되었다가 깨어난 구형 워커(Stale Worker)가 최신 체크포인트를 오염시키지 못하도록 트랜잭션 레벨에서 Owner/Epoch를 검증하여 쓰기를 차단(Rollback)합니다.
- Durable Event & SSE: 워커가 이벤트를 DB에 커밋하고, PostgreSQL LISTEN/NOTIFY 힌트와 1초 폴링을 조합하여 클라이언트로 안전하게 SSE 스트리밍을 전달합니다.

## 상태관리 

### AgentState  

- AgentState는 MessagesState에 에이전트 루프 제어를 위한 remaining_steps 필드가 추가된 형태  
- *remaining_steps란? 에이전트가 LLM 호출 ↔ 도구(Tool) 실행을 반복할 때 무한 루프(무한 재귀)에 빠지는 것을 방지하기 위해, 남은 단계 수를 카운트다운하여 관리하는 내부 제어용 변수  

```py
class AgentState(TypedDict):
    messages: Annotated[Sequence[BaseMessage], add_messages]
    remaining_steps: NotRequired[RemainingSteps]  # <-- 차이점!

# ---
class MessagesState(TypedDict):
    messages: Annotated[list[AnyMessage], add_messages]
```

### 컨텍스트 엔지니어링 - Public, Private, Tool State 분리  

질문 
- ReAct 루프 내에서 추론 컨텍스트와 외부에게 보여줄 전용 상태는 어떻게 분리 및 관리해야하는가? 
- 커다란 데이터 조회 후 보관은 어디에 해야 LLM이 컨텍스트 폭팔 없이 이를 관리할 수 있는가?   
- Context compact 과정에서 무엇을 압축하고 무엇을 제외해야하는가?  

3가지 레이어로 분리해서 생각한다.  
- Public Messages : 사용자에게 보여줄 생각/답변 텍스트 (가벼움)  
- Private Tool State : 모델 추론에 필요한 대용량 원본 데이터 (LLM 프롬프트 차단)  
- Result Contract : ReAct패턴에서 추론이 끝나면 최종 결과(결론)만 말아서 상위/다음 노드로 전달한다.  

ToolMessage.artifact 패턴
- artifact 필드에는 큰 데이터 셋을 저장하고
- content 필드에는 이 데이터에 대한 요약 설명을 저장한다.  

DATA_KEYS 분리 패턴  
- content 필드에는 이 데이터에 대한 요약 설명을 저장한다.  
- artifact 필드 대신, 3,600개의 진짜 숫자 배열 원본은 state["datasets"]라는 별도 키에 넣는다.  
- 약속된 데이터 정의들은 DATA_KEYS=("priceDatasets", "currentTicker", ) 등에 있으며, 이는 functional level에서만 읽도록 정의한다.

## Tool message 

### 원리

1. model을 호출할때 bind tool함수로 호출 가능한 tool list를 보낸다.(내부적으로 JSON Schema로 전달됨)  
2. 모델이 AIMessage 응답에 tool call요청을 보내온다.
```py
  AIMessage(
      content="",
      tool_calls=[{
          "name": "get_historical_prices",
          "args": {
              "symbol": "AAPL",
              "interval": "1d",
              "count": 3,
          },
          "id": "call_123",
      }],
  )
```
3. 그래프가 툴 요청을 확인하고 ToolNode로 이동한다.  
- 물론 일반노드로 분기해서 직접 실행도 가능, 

### 애러핸들링

handle_tool_errors=True일 때 동작
- 그래프를 중단시키지 않고, 에러 내용(str(e))을 본문(content)으로 담은 ToolMessage(content=..., status="error")를 생성합니다.


### tool_message 구조  

- ToolMessage : LLM이 요청한 도구(Function/Tool Calling)를 실행한 뒤, 그 실행 결과 데이터를 담아 메시지 히스토리에 추가하는 전용 메시지 객체.

1. `ToolMessage`의 핵심 필드 구조

- id : 메시지 자체의 고유 ID (UUID 등)
- type : 메시지 유형 식별자 (항상 `"tool"`)
- tool_call_id(str): 앞서 LLM(`AIMessage`)이 발급한 호출 고유 ID와 매핑되는 키 
- name : 실행된 도구 이름 (예: `"get_historical_prices"`) 
- content : LLM에게 전달될 텍스트 결과값  
- status : 도구 실행 성공/실패 상태 (기본값: `"success"`)
- artifact: LLM에는 숨기고 그래프 노드 내부 로직에서만 쓰는 원본 데이터 객체   
- additional_kwargs : 공급자별 추가 메타데이터

---
2, 실제 데이터 예시 (Price Agent 기준)

```python
ToolMessage(
    tool_call_id="call_abc123xyz",
    name="get_historical_prices",
    content='{"symbol": "AAPL", "interval": "1d", "count": 10, ...}',  # LLM이 읽는 텍스트
    artifact=PriceToolArtifact(                                          # 파이썬 코드가 읽는 객체
        symbol="AAPL",
        prices=(PriceData(trading_date=..., close=225.5), ...),
        cache_hit=False,
        error_code=None,
    ),
    status="success",
    type="tool"
)
```

3, response_format="content" (기본값)
- 옵션을 아예 지정하지 않거나 "content"로 두면 기본값으로 동작합니다.
- 동작 방식: 함수가 반환한 값 전체가 문자열로 직렬화되어 ToolMessage.content 하나에만 들어갑니다. ( artifact 필드: None )


4, response_format="content_and_artifact"  
- LangChain에서 도구를 등록할 때 response_format="content_and_artifact" 옵션을 지정
- 도구 함수는 (content, artifact) 형태의 튜플을 반환  
  - content: LLM에게 보여줄 텍스트(요약본 또는 간략한 JSON). LLM의 컨텍스트 창(토큰)을 절약하고 환각을 줄이기 위한 용도입. 
  - artifact: LLM 프롬프트에는 포함되지 않고, 파이썬 코드(다운스트림 노드)에서 타입 안전하게 직접 쓰기 위한 순수 데이터 객체.  

```py
# tools/yahoo_finance.py
@tool("get_historical_prices", response_format="content_and_artifact")
def _get_historical_prices(...) -> tuple[str, PriceToolArtifact]:
    ...
    return content, artifact
```

### Tool call depth & Tool budget middleware

tool calling으로 리서치를 무한정 한다고 답변의 정확도가 비례해서 올라가지 않는다.   
무한정 tool calling은 제어해야한다.   
- GraphRecursionError : 답을 못 찾거나 헤매서 계속 조사를 돌다 보면 LangGraph의 재귀 제한(기본 25스텝)에 걸려 Crash  
- deepagents에서 남은 tool call budget을 인지하면서 early return하는 기능이 가능하다.
- 예, Tool Budget Middleware

```py
class ToolBudgetMiddleware(AgentMiddleware):
    def __init__(self, max_tool_calls: int = 10, warning_threshold: int = 2):
        super().__init__()
        self.max_tool_calls = max_tool_calls
        self.warning_threshold = warning_threshold

    def wrap_model_call(self, request: ModelRequest, handler):
        # 1. 지금까지 실행된 툴 호출 수 계산
        messages = request.state.get("messages", [])
        tool_call_count = sum(1 for m in messages if isinstance(m, ToolMessage))
        remaining = max(0, self.max_tool_calls - tool_call_count)

        # 2. 예산이 모두 소진되었을 때 -> 도구를 박탈하여 강제 Early Return 유도
        if remaining == 0:
            notice = SystemMessage(
                content="[시스템 알림: 도구 호출 예산이 모두 소진되었습니다. 더 이상 도구를 사용할 수 없으니 지금까지 수집한 정보로 최종 결론을 작성하세요.]"
            )
            # tools를 비우고 알림 메시지를 주입하여 호출
            stripped_request = request.override(
                tools=[], 
                messages=[*request.messages, notice]
            )
            return handler(stripped_request)

        # 3. 예산이 얼마 안 남았을 때 -> LLM에게 잔여 예산 경고 주입 (인지)
        if remaining <= self.warning_threshold:
            warning = SystemMessage(
                content=f"[시스템 알림: 남은 도구 호출 예산은 {remaining}회입니다. 조사를 곧 마무리하고 보고서를 작성할 준비를 하세요.]"
            )
            aware_request = request.override(messages=[*request.messages, warning])
            return handler(aware_request)

        # 4. 정상 진행
        return handler(request)
```
