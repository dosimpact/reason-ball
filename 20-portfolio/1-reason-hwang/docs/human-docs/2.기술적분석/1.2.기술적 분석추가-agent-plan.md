# 기술적 분석 20개 지표 확장 계획

작성 기준: 2026-11-16. **이 문서는 구현 전 계획이며, 아래 기능·수식·기본값이 모두 구현되거나 검증된 상태는 아니다.** FastAPI와 LangGraph 개발 런타임의 호환 작업과는 별도 범위다.

## 1. 무엇을 만들 것인가

기존 인라인 `technical_analysis_agent`와 별도 보고서 화면인 `technical_analysis_canvas_agent`에서 같은 20개 지표를 계산하고 조회할 수 있게 한다. 사용자는 필요한 지표만 선택할 수도 있고, 20개 전체 요약을 본 뒤 원하는 지표를 펼쳐 확인할 수도 있다.

같은 지표의 설정도 동시에 비교한다. 예를 들어 SMA20·SMA60·SMA120은 한 분석 안에 존재하는 서로 다른 지표 인스턴스다. 단순히 `SMA=true`로 표시하는 모델로는 이 요구를 표현할 수 없다.

가격·거래량·지표 수치는 서버가 계산하고 소유한다. AI는 검증된 수치를 바탕으로 배치와 설명을 구성한다. 자동 주문, 매수·매도 자동 판단, 여러 지표를 합친 새로운 종합 점수는 이번 범위에 넣지 않는다.

## 2. 현재 구현과 확장의 경계

현재 도메인 엔진에는 SMA, EMA, BBANDS, RSI, MACD, ADX, ATR, OBV **8개**가 등록되어 있다. 이번 20개 목록 중 SMA·EMA·MACD·RSI·BBANDS·OBV의 **6개는 계산 구현을 재사용할 수 있다**. 다만 현재 에이전트의 요청 스키마와 FinancialChart/Query는 SMA·RSI·MACD 3개를 중심으로 설계되어 있다.

따라서 기존 6개도 에이전트·조회 계약·화면까지 연결하는 작업이 필요하다. 반대로 기존 ADX와 ATR은 새 20개 목록에 없다는 이유로 삭제하지 않는다. ATR은 Keltner Channel 계산의 내부 구성 요소로도 사용할 수 있다.

## 3. 먼저 공통 지표 카탈로그를 만든다

지표별로 이름, 별칭, 공식 버전, 입력 가격, 매개변수, 반환 series, 단위, 준비 구간, 표시 방법과 해석 규칙을 한곳에서 정의한다. 백엔드 검증·계산·API schema와 프런트엔드 설정 폼·라벨이 같은 카탈로그를 기준으로 움직이게 한다.

**아래 표의 제안 기본값은 구현 기준으로 수용되었다.** 다만 기존 지표의 동작·사용자 설정을 우선 보존하며, 정확한 seed·예외 처리·설치 함수 대응까지 검증 완료되었다는 뜻은 아니다. 허용 범위와 세부 수치 규칙은 구현자가 근거와 수치 검증으로 정한다. TradingView와 픽셀 단위 또는 모든 숫자가 완전히 같아야 한다는 목표는 없다.

공통 기호: C=종가, H=고가, L=저가, V=거래량, HH/LL=해당 기간 최고/최저, TP=(H+L+C)/3, EMA/SMA=해당 이동평균. 가격 단위는 원본 종목 통화를 따르고, 배수·비율·거래량 단위를 가격과 혼동하지 않는다.

| --- | --- | --- |
| SMA | C의 n기간 단순평균. n=20 제안 | sma, 가격 / 가격 위 선 |
| EMA | C의 지수이동평균. n=20 제안. 초기 seed 방식 명시 | ema, 가격 / 가격 위 선 |
| MACD | EMA(C,fast)−EMA(C,slow), signal=MACD의 EMA, histogram=MACD−signal. 12/26/9 제안 | macd·signal·histogram, 가격 차이 / 선+히스토그램 패널 |
| PSAR | Parabolic SAR 추세 전환·가속계수 방식. acceleration=0.02, maximum=0.2 제안. TA-Lib SAR 대응 여부 확인 | sar, 가격 / 가격 위 점 |
| CCI | (TP−SMA(TP,n))/(0.015×평균절대편차). n=20 제안 | cci, 무차원 / 패널 |
| STOCH | raw %K=100×(C−LL)/(HH−LL), 이를 slowK·slowD로 평활. 14/3/3, 두 평활 SMA 제안 | slow_k·slow_d, 0~100 / 패널 |
| RSI | 상승·하락 변화량의 Wilder 평활 비율. n=14 제안. 0/0 처리도 공식 계약에 포함 | rsi, 0~100 / 패널 |
| STOCHRSI | RSI를 기간 내 최저·최고로 정규화한 뒤 K/D 평활. RSI14·stoch14·K3·D3 및 0~100 표현 제안 | k·d, 0~100 / 패널 |
| WILLIAMS_R | −100×(HH−C)/(HH−LL). n=14 제안 | williams_r, −100~0 / 패널 |
| AO | SMA((H+L)/2,fast)−SMA((H+L)/2,slow). 5/34 제안 | ao, 가격 차이 / 히스토그램 |
| TSI | 100×EMA(EMA(ΔC,long),short)/EMA(EMA(abs(ΔC),long),short). 25/13 제안. signal9는 선택 출력이며 기본은 주 지표만 | tsi·선택 signal, 비율 / 패널 |
| UO | BP=C−min(L,C이전), TR=max(H,C이전)−min(L,C이전). 기간별 sum(BP)/sum(TR)을 4:2:1로 가중해 100배. 7/14/28 제안 | uo, 0~100 / 패널 |
| TRIX | C에 EMA를 세 번 적용한 값의 1기간 변화율×100. n=15 제안. signal9는 선택 출력이며 기본은 주 지표만 | trix·선택 signal, 변화율 % / 패널 |
| BBANDS | middle=이동평균, upper/lower=middle±각 배수×표준편차. C·SMA20·배수2/2 제안. 표준편차 정의 확인 | upper·middle·lower, 가격 / 가격 위 밴드 |
| KELTNER | middle=EMA(입력,n), upper/lower=middle±배수×ATR(atrPeriod). C·EMA20·ATR10·배수2 제안. ATR은 Wilder 방식 제안 | upper·middle·lower, 가격 / 가격 위 밴드 |
| DONCHIAN | 기간 내 H의 최댓값·L의 최솟값, middle=(upper+lower)/2. n=20 제안. 현재 봉 포함 여부를 명시 | upper·middle·lower, 가격 / 가격 위 밴드 |
| OBV | C가 오르면 +V, 내리면 −V, 같으면 0을 누적. 첫 봉 기준값 명시 | obv, 누적 거래량 / 별도 패널 |
| PVT | V×(C−C이전)/C이전을 누적. 첫 유효 변화 이전 기준값과 C이전=0 처리 명시 | pvt, 거래량 가중 누적값 / 패널 |
| AD | money flow multiplier=(2C−H−L)/(H−L), multiplier×V를 누적 | ad, 거래량 가중 누적값 / 패널 |
| CMF | sum(multiplier×V,n)/sum(V,n). n=20 제안. AD와 같은 multiplier 정의 사용 | cmf, 비율(일반적으로 −1~1) / 패널 |

### TA-Lib 재사용 여부를 먼저 확인한다

설치된 Python wrapper와 실제 TA-Lib core 버전, 사용 가능한 함수, lookback과 기본 매개변수를 구현 전에 확인한다. 공식 최신 문서와 로컬 설치 버전이 다를 수 있다. **AO·TSI가 TA-Lib에 반드시 없다고 단정하지 않는다.** 설치 버전에서 적합한 함수가 있으면 정의를 비교해 재사용하고, 없거나 목표 정의와 다르면 독립 계산기를 작성한다.

이 확인에는 함수 이름이 비슷하다는 사실만으로 충분하지 않다. 예를 들어 일반적인 StochRSI의 별도 RSI/stochastic 길이와 K/D 평활을 라이브러리 함수가 그대로 표현하는지 확인해야 한다. AD는 누적 Accumulation/Distribution이며, 그 이동평균 차이를 계산하는 ADOSC와 다르다.

## 4. 숫자의 의미를 먼저 고정한다

### 준비 구간과 null

지표마다 필요한 lookback이 다르다. 합성 지표는 내부 평활·변화율까지 포함해 준비 구간을 계산하고, 조회한 공통 OHLCV 구간에서 계산한 다음 마지막 표시 봉만 잘라낸다.

초기 계산 불가, 분모 0, 부족한 이력은 정상값 0으로 덮지 않는다. 해당 값은 null 또는 정의된 특수 규칙으로 반환하고 이유를 구분한다. 모든 지표를 기존의 고정 warmup 하나로 처리하면 충분하다고 가정하지 않는다. EMA 계열은 초기값 의존성과 충분한 이력 여부도 표시한다.

### 예외 처리 규칙

- H=L인 봉의 AD/CMF multiplier는 0으로 두는 안을 제안한다. 이는 가격 변동이 없는 봉의 계산 규칙이며, CMF 기간 전체 거래량 합이 0인 경우와 다르다.
- CMF의 거래량 합이 0이면 null과 사유를 반환하는 안을 제안한다. 음수 거래량 등 비정상 원본은 입력 검증에서 구분한다.
- STOCH·STOCHRSI·Williams %R의 최고=최저, CCI의 편차=0, TSI의 평활 절댓값=0, UO의 TR합=0에 대한 규칙을 각각 확정한다. 무조건 0이라는 공통 처리는 하지 않는다.
- PVT는 이전 종가가 0이면 해당 변화량을 유효 수치로 만들지 않는다.
- RSI의 상승·하락 변화량이 모두 0인 구간, 한쪽만 0인 구간은 선택한 라이브러리의 정의와 호환 규칙을 명시한다.
- Donchian의 현재 봉 포함 채널과 직전 n개 봉의 돌파 판단 기준을 분리한다. 현재 봉을 포함한 상단에 현재 고가를 비교해 새 돌파라고 단정하지 않는다.

### 누적 지표의 기준점

OBV·PVT·AD는 계산을 시작한 과거 구간과 초기 기준값에 따라 절대 수준이 달라진다. 표시 봉 수를 바꿨다는 이유만으로 기준점이 조용히 바뀌면 비교가 어려워진다.

symbol·interval별 고정 계산 시작점에서 누적하고 표시 count만 잘라내어, count가 달라도 겹치는 날짜 값이 일관되게 한다. 실제 시작일은 확보 가능한 이력을 조사해 구현자가 정하며 임의의 날짜를 확정된 값처럼 적지 않는다. 원본 이력 수정·추가로 기준 구간이 달라질 때는 버전과 정책을 명시한다. 응답에 계산 시작일·사용 이력·기준값 정책을 기록하고, 캐시도 이 정책을 포함한다. 모든 조회에서 임의로 0을 맞춰 서로 같은 절대값이라고 주장하지 않는다. 제한된 Yahoo 이력으로 계산했다면 전체 상장 이력의 누적값처럼 표현하지 않는다.

### 시그널은 지표별로 정의한다

위/아래, 증가/감소, 범위 안/밖, 교차 발생을 구분한다. 교차는 직전 유효 봉과 현재 유효 봉의 차이로 계산하고, 경계값과 정확히 같을 때의 포함 규칙을 문서화한다. RSI 70/30 같은 기준도 설정과 해석 계약에 포함한다. 모든 지표에 임의의 “매수/매도” 규칙을 붙이지 않는다.

## 5. 같은 지표 여러 설정을 표현하는 계약

각 요청을 이름 하나가 아닌 **지표 인스턴스**로 표현한다.

```text
instanceId: 서버가 검증하는 안정적인 식별자
name: SMA
parameters: {timeperiod:20}
label: SMA(20)
series: [{key:"value", unit:"price", display:"line", ...}]
```

위 내용은 구조 설명용이며 최종 JSON schema는 아니다. SMA20과 SMA60은 서로 다른 instanceId를 가지고, 요청 순서가 바뀌어도 기존 인스턴스를 혼동하지 않아야 한다. 완전히 같은 설정을 두 번 추가할 때 합칠지 독립 비교 항목으로 허용할지는 결정이 필요하다. 이름만 key로 삼는 기존 구조는 이 요구에 충분하지 않다.

응답에는 schemaVersion·catalogVersion·공식 버전과 원본 ticker/통화/주기/asOf/조정 여부·사용 이력 정보를 포함하는 방향을 제안한다. 모든 series는 같은 bars/time 축에 정렬하고 null gap을 유지한다.

차트에는 지표별 boolean prop을 20개 추가하지 않는다. `series descriptors`로 인스턴스별 출력 key, 단위, panel, line/histogram/marker/band, 기준선 등을 표현한다. PSAR 점, MACD 히스토그램, 가격 밴드를 같은 일반 구조로 확장한다.

## 6. 화면과 사용자 조작

### 공통 컴포넌트

| 구성 | 역할 |
| --- | --- |
| FinancialChart 확장 | 가격·거래량, overlay 선/밴드/PSAR 점과 선택한 하위 패널 표시 |
| IndicatorControls | 지표 추가·제거, 같은 지표 복수 설정, 매개변수 편집 |
| IndicatorSummary | 전체 결과의 최신값·단위·시그널·준비 부족/오류를 요약하고 상세 열기 |
| 기존 QueryPanel | ticker·주기·봉 수·지표 설정과 수동 Refresh를 같은 조회 영역에 제공 |
| 기존 Card/Table/Markdown 등 | 요약·근거·설명을 기존 OpenUI 구성 요소로 표현 |

지표를 지정하지 않은 일반 분석은 기존 SMA·RSI·MACD를 기본으로 유지한다. “전체 20개”를 명시하면 전체 분석을 수행한다. 전체 20개 분석에서도 처음부터 20개 하위 차트를 모두 펼치지 않는다. 가격·거래량과 요약을 먼저 보여주고 사용자가 선택한 지표만 패널로 연다. 서로 다른 단위의 series를 같은 축에 임의로 겹치지 않는다.

### 조회와 재분석을 구분한다

- **Query 변경·Refresh**: ticker, interval, count, 지표와 복수 설정을 직접 편집하고 서버 조회만 한다. LLM을 호출하지 않는다.
- **명시적 재분석**: 마지막으로 성공한 조회 조건을 검증해 에이전트에 전달하고 새 해석을 생성한다. Canvas에서는 새 보고서를 만든다.

기존 설명과 근거는 최초 분석 snapshot 기준이다. 차트를 다른 조건으로 조회했다고 과거 AI 해석까지 그 조건을 분석한 것처럼 바꾸지 않는다. 설정 편집 중인 값과 실제 성공한 조회 조건도 분리한다.

인라인과 Canvas는 같은 요청·계산·Query 계약을 공유한다. 인라인은 기존 presentation으로, Canvas는 기존 custom event와 report ID로 표시하되 계산 결과는 달라지지 않아야 한다.

## 7. 호환성과 크기 제한

현재 API의 SMA/RSI/MACD 매개변수와 기존 OpenUI snapshot을 갑자기 해석 불가능하게 만들지 않는다. 새 멀티 인스턴스 계약에는 버전을 두고 기존 요청·응답을 읽는 adapter 또는 명시적 구버전 경로를 마련한다. 기존 snapshot에 schemaVersion이 없을 때의 판별 규칙도 필요하다.

현재 표시 봉 수 상한은 200개이고 OpenUI parser 프로그램 크기 제한은 60000자다. 20개 지표와 복수 설정의 전체 숫자 배열을 모델 프롬프트나 DSL에 그대로 복사하면 이 제한을 쉽게 압박한다.

숫자는 서버 Query 응답으로 전달하고, 초기 DSL에는 필요한 최소 snapshot 또는 조회 참조만 두는 방식을 설계한다. parser 제한을 피하려고 수치를 조용히 누락하거나 마지막 몇 봉만 남기지 않는다. API 응답 크기·초기 snapshot 크기·최대 인스턴스 수·동시에 열린 패널 수·warmup 최대 길이의 한도를 측정 후 정한다. **새 제한 수치는 아직 확정하지 않았다.** 기존 200봉 지원도 확장 후 실제 payload로 회귀 확인한다.

## 8. 구현 단계와 역할

| 단계 | 주요 작업 | 완료 판단 |
| --- | --- | --- |
| 1. 카탈로그 | 20개 공식·기본값·매개변수·단위·lookback·예외·시그널 확정, 설치 TA-Lib 확인 | 이름은 같지만 다른 공식을 쓰는 모호함 제거 |
| 2. 계약 | instanceId, 버전, 공통 시간축, series descriptor, Query·재분석 요청과 구버전 adapter | 복수 SMA와 기존 3지표 snapshot을 함께 표현 |
| 3. 기존 6개 연결 | SMA·EMA·MACD·RSI·BBANDS·OBV를 공통 계약·두 agent·Query·UI에 연결 | 계산 재사용과 전체 흐름을 먼저 검증 |
| 4. 나머지 14개 | 라이브러리 재사용 또는 정의가 명시된 계산기 추가 | 지표별 수치 fixture와 준비 구간 통과 |
| 5. 전체 요약·회귀 | 20개 요약, drilldown, 성능·크기 제한, 호환성·실패 처리 | 전체·선택·복수 설정 모두 안정적으로 동작 |

Sol backend 에이전트는 카탈로그·계산·요청 검증·조회와 두 graph 연결을 담당한다. Sol frontend 에이전트는 공통 설정·요약·차트와 인라인/Canvas 표시를 담당한다. QA 에이전트는 수치 fixture와 API 검증 시나리오·실행 증거를 담당한다. 구현 시 해당 stock을 현재 동작으로 갱신하고 날짜 있는 flow에 결정과 검증을 기록한다. 이번 문서 작성 단계에서는 다른 stock/flow나 코드를 변경하지 않는다.

## 9. 구현 후 필요한 검증

수치 정확성은 API 화면이 뜨는 것만으로 확인할 수 없으므로 계산 단위 검증도 필요하다.

- 알려진 수치 fixture와 기준 구현 대조: 단일·복합 평활, 표준편차, 변화율, 누적 기준값.
- lookback 직전/직후, 부족한 이력, null gap과 전체 시간축 길이 일치.
- 0거래량, 전체 0거래량, flat 가격, H=L, 분모 0, 이전 종가 0, 경계값과 정확히 같은 값.
- 직전 유효값이 없는 교차, Donchian 현재 포함/직전 기준, 누적 지표의 조회 구간 변경.
- 동일 분석에 SMA20·SMA60·SMA120, 요청 순서 변경·설정 수정 후 instanceId와 series 매핑.
- 두 agent의 동일 입력 결과 일치, 전체20 요약·선택 지표·복수 설정, 일부 지표 실패 처리.
- Query 편집·Refresh에서 새 모델 run이 생기지 않는지, 명시적 재분석만 새 해석을 만드는지.
- 구버전 요청·OpenUI snapshot·기존 ADX/ATR·200봉·60000자 제한의 회귀.

서버 통합 검증은 Bruno 원칙의 API E2E로 수행한다. 실제 공급자 호출은 제한된 대표 사례로 구분하고, 안정적인 수치 대조는 고정 fixture를 사용한다. 브라우저 검증은 사용자가 직접 담당한다. **이번 계획 문서 작성에서는 테스트·실제 API 호출을 실행하지 않았다.**

## 10. 2026-11-16 확정 결정: 사전 질문 답변 5~8

다음 결정은 구현 기준이며, 실제 구현·수치 검증 완료를 의미하지 않는다. 답변 1~4는 [운영 런타임 계획](../0.infra/langgraph-oss.md)에 반영한다.

5. **기본값과 비교 목표**: 표의 기본값 제안을 구현 기준으로 수용한다. 기존 지표의 동작과 사용자 설정은 보존한다. 세부 수식 예외·seed·TA-Lib 설치 함수 가용성은 엔지니어링 검증 대상이며, TradingView의 화면·수치와 완전히 같아야 하는 것은 아니다.
6. **누적 지표**: OBV/PVT/AD는 symbol·interval별 고정 계산 시작점을 사용하여 count 변경 시 겹치는 날짜 값을 유지한다. 실제 origin 날짜와 확보 가능한 이력은 조사 후 정하고 응답에 명시한다. 임의의 시작일이나 전체 상장 이력 확보를 가정하지 않는다.
7. **선택 signal**: TSI·TRIX는 기본적으로 주 지표만 출력한다. signal은 사용자가 선택할 수 있는 부가 출력으로 둔다.
8. **분석 범위**: 지표 미지정 시 기존 SMA·RSI·MACD 기본 구성을 유지한다. 명시적 전체20, 선택 지표, 같은 지표의 복수 설정은 두 에이전트 모두 지원한다.

## 11. 다음 작업과 구현자가 구체화할 사항

- 수용된 기본값을 바탕으로 canonical 이름·별칭·매개변수 허용 범위, smoothing·초기 seed·표준편차 정의를 카탈로그로 작성한다.
