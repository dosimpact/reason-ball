# Goal

목적 : 기술적 분석 agent + OpenUI + Dynamic Canvas로, 대화에서 필요한 차트와 표를 골라 나만의 분석 화면을 만든다.

- 참고 : `21-mini-projects/6-openui-poc/6-b-3-lite-canvas-ux/`의 화면과 코드를 가져와 현재 프로젝트에 맞게 적용한다.
- 범위 : **'기술적 분석 · Canvas' Chat에만 적용**. 기존 기술적 분석 inline, TA-Lib 채팅, SEC 채팅은 유지한다.
- 이 문서는 구현 계획이다. 아래 기능이 모두 현재 구현되어 있다는 의미는 아니다.

## Canvas에 무엇을 넣을 것인가

- 설명과 해석은 채팅에 쓴다.
- **Canvas wrapper가 들어간 UI 요소만 Canvas에 추가할 수 있다.**
- wrapper는 차트·표·카드 등 하나의 의미 있는 UI 묶음을 감싼다.
- 사용자가 채팅에서 'Canvas에 추가'를 누르면 해당 요소가 Canvas에 들어간다.
- 에이전트가 보고서 전체를 Canvas 안에 자동으로 써 내려가는 현재 방식은 변경한다.

[사용 예]

```text
사용자 : AAPL 가격과 RSI, MACD 분석해줘

채팅
  분석 설명
  가격 차트     [Canvas에 추가]
  RSI 차트      [Canvas에 추가]
  MACD 차트     [Canvas에 추가]

사용자가 가격 차트와 RSI 차트만 선택
  → Canvas에는 선택한 두 차트만 표시
  → 이후 다른 종목의 차트도 추가해서 비교
```

## Canvas wrapper

목적 : 채팅의 UI 요소를 Canvas로 가져오는 공통 컴포넌트

- 모델은 분석에 필요한 UI를 만들고, 독립적으로 보관할 수 있는 요소를 wrapper로 감싼다.
- wrapper에는 제목, UI 내용, 조회 조건, 원래 대화·분석 근거를 연결한다.
- 차트와 필터처럼 함께 동작해야 하는 요소는 하나의 묶음으로 추가한다.
- 같은 요소를 여러 번 눌러 중복 추가하지 않도록 한다. 다른 조건으로 생성한 분석은 별도 요소로 구분한다.
- Canvas에서 제거해도 원래 채팅의 답변과 차트는 남긴다.

[고려사항]
- OpenUI 컴포넌트 목록·검증기·렌더러에 wrapper를 함께 등록한다. 프롬프트에 이름만 추가해서는 동작하지 않는다.
- 추가 시점의 종목·주기·지표 설정을 가져온다. 추가 이후 Canvas의 조건 변경이 원래 채팅 화면을 바꾸지 않도록 한다.
- 차트에 필요한 데이터 조회와 상태도 함께 연결한다. 화면 모양만 복사하지 않는다.

## Canvas 배치 - Grafana처럼

목적 : 담아 놓은 UI 요소를 사용자가 원하는 위치와 크기로 배치

- 요소별 드래그 이동, 크기 조절, 제거를 지원한다.
- 가격 차트와 지표 차트를 나란히 놓거나 종목별로 묶어서 비교한다.
- 대화별로 추가한 요소와 배치를 저장하고, 다시 열면 복원한다.
- 좁은 화면에서는 세로로 배치해 내용을 읽을 수 있게 한다.

참고 : 예제의 분할선 드래그는 채팅과 Canvas의 크기를 조절하는 기능이다. 개별 요소를 옮기는 그리드 배치와 wrapper는 별도로 구현한다.

## 예제에서 가져올 기능

- 채팅·Canvas 분할 화면 : 경계선 드래그, 크기 저장·복원, 닫기·다시 열기.
- 텍스트 선택 → '채팅에 물어보기' : Canvas 요소의 문장을 선택해서 해당 분석을 근거로 후속 질문.
- PDF 저장 : Canvas에 담은 요소를 인쇄용 화면으로 출력. 차트 로딩 완료와 종목·기간·기준 시점을 함께 표시한다.
- 공유 링크 : 후속 단계. Canvas 구성과 당시 데이터를 저장해서 같은 화면을 조회할 수 있게 한다. 접근 권한과 공개 범위는 별도로 정한다.

## 에이전트와 프롬프트 변경

- Canvas 전용 그래프 `technical_analysis_canvas_agent`를 수정한다. 기존 가격 수집·TA 계산 도구는 재사용한다.
- 기존 '보고서 전체를 Canvas로 출력'하는 경로를 '채팅 설명 + wrapper가 포함된 OpenUI'로 변경한다.
- Canvas에 실제 추가하는 동작은 프런트엔드에서 처리한다. 추가·이동·크기 조절만으로 모델을 다시 호출하지 않는다.
- 선택한 요소에 대한 질문은 해당 요소의 원래 분석과 조회 조건을 근거로 답한다.
- 단순 설명 질문에는 채팅으로 답하고 기존 Canvas를 유지한다. 재분석 요청은 새 결과를 채팅에 표시하고 사용자가 추가 여부를 결정한다.

[프롬프트 방향]

```text
분석 설명과 해석은 채팅에 작성한다.
사용자가 따로 보관하고 비교할 수 있는 차트·표·카드는 Canvas wrapper로 감싼다.
전체 답변을 하나의 wrapper로 감싸지 않는다.
서로 의존하는 차트와 조회 조건은 하나의 의미 있는 요소로 묶는다.
Canvas 요소에 관한 후속 질문에는 전달된 분석 근거와 조건을 사용한다.
실제로 계산하지 않은 수치나 현재 조회하지 않은 데이터를 추정하지 않는다.
```

[문맥 연결]
- 선택한 문장만 전달하지 않고 요소 ID, 원래 분석, 종목·주기·지표·기준 시점을 함께 연결한다.
- 서버는 해당 대화에 속한 요소인지 확인하고 저장된 근거를 읽는다.
- 차트 조건 변경과 모델 재분석을 구분한다. 차트만 새로 조회했다면 기존 해석의 기준 시점도 표시한다.

## 구현 순서

1. **wrapper와 요소 단위 상태** : 채팅 UI에서 Canvas에 추가·제거하고, 대화별로 저장·복원한다.
2. **Canvas 전용 그래프 출력 변경** : 채팅 설명과 추가 가능한 UI 요소를 생성한다. 기존 보고서 전체 출력은 전환한다.
3. **드래그 배치** : 요소 이동·크기 조절과 배치 저장. 예제의 분할 크기 저장도 가져온다.
4. **인용 질문과 PDF** : 요소 문맥을 이용한 후속 대화, Canvas 인쇄용 화면을 지원한다.
5. **공유 링크** : 저장 시점의 화면·데이터와 접근 범위를 정한 뒤 별도 구현한다.

## 검증

- wrapper가 없는 설명은 Canvas에 들어가지 않는지.
- 가격·RSI·MACD 중 선택한 요소만 추가되는지, 중복 추가·제거가 정상인지.
- 추가한 요소의 조회가 정상이고, 각 요소의 종목·설정이 서로 섞이지 않는지.
- 드래그·크기 변경 후 대화를 다시 열어도 구성과 배치가 복원되는지.
- 인용 질문이 해당 요소를 근거로 답하고 기존 Canvas를 유지하는지.
- PDF에 차트가 로딩된 상태로 나오고 기간·기준 시점을 확인할 수 있는지.
- 다른 채팅 화면과 그래프는 기존대로 동작하는지.

API 검증과 Playwright 사용자 흐름 검증을 함께 진행하고, 스크린샷을 증거로 남긴다. 검증에 사용한 브라우저와 임시 자원은 종료한다.
