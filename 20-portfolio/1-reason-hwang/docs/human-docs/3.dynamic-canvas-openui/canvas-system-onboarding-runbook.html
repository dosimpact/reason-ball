A

먼저, Canvas는 무엇인가

대화에서 필요한 결과만 골라 만드는 개인 분석 작업대입니다.

채팅은 설명을 담당합니다

“AAPL의 RSI가 왜 이렇게 나왔나요?” 같은 질문, 분석 해석, 도구 실행과 후속 대화가 남습니다.

Canvas는 비교를 담당합니다

가격·RSI·MACD 중 필요한 요소만 담고, 크기와 위치를 바꾸며 여러 종목을 비교합니다.

Canvas는 그래프 DB의 지식 그래프나 브라우저의 HTML canvas API를 뜻하지 않습니다. 여기서는 사용자가 패널을 배치하는 화면 영역을 가리킵니다. 실제 금융 차트 엔진은 별도로 Lightweight Charts를 사용합니다.

이전 고정 build_program() 경로는 제거되었습니다. Python의 presentation 어댑터는 UI 문자열을 조립하는 대신 compact 데이터와 표시 제약을 전달합니다. LLM은 이를 보고 전체 UI를 구성합니다.

OpenUI Lang은 임의 JavaScript 실행문이 아닙니다. 등록된 컴포넌트·함수·액션과 Query를 렌더러가 해석합니다. 모델이 가격 배열을 임의로 계산하는 역할도 아닙니다.

root = Col([CanvasItem("report-id:chart", "AAPL 가격", [panel])])
chart = Query("technical_analysis_chart", {ticker:"AAPL", interval:"1d", count:"120", schema_version:2, instances:"[]"}, {bars:[], status:"loading"})
panel = QueryPanel([FinancialChart(chart)], Action([@Run(chart)]), [Input($ticker, "티커", "text")])
위 코드는 관계를 설명하는 축약 예시입니다. 실제 프로그램은 $ticker 초기 선언과 Query 인자 연결, 서버 발급 ID를 포함해야 합니다. 예시 ID를 실행에 그대로 사용하지 마세요.

L

Query와 분석은 다른 시계

현재 화면의 차트와 원래 해석의 기준 시점을 구분합니다.

시계 ① 원래 분석

서버에 보존된 report의 기간·시그널·근거입니다. 원래 채팅 설명과 인용 질문이 참조합니다.

시계 ② 현재 차트 조회

현재 티커·주기·지표 조건으로 Query API가 받은 결과입니다. 새로고침하면 달라질 수 있습니다.

예를 들어 AAPL 분석에서 복사한 패널의 티커를 MSFT로 바꾸어도 원래 AAPL 분석 문장은 자동으로 MSFT 해석으로 바뀌지 않습니다. 패널 안내와 출처를 확인하고, 해석까지 바꾸려면 재분석 흐름을 사용합니다.

실제 조회는 allowlist인 technical_analysis_chart와 technical_analysis_catalog를 사용합니다. Host가 허용 인자와 snapshot 스키마를 검사하며, 헤더·본문 파싱을 포함한 30초 제한을 둡니다.

지표·배열·오류의 계약

수치는 계산 엔진에서 오고, 표시 여부는 화면 상태입니다.

  • TA20은 20종 지표와 한 지표의 복수 설정을 지원합니다. 기본 RSI14·SMA20·MACD12/26/9, 최대40 인스턴스입니다.
  • oscillator 하위 패널은 최대4개입니다. 가격 overlay와 구분되며 숨긴 지표도 요약·상세에 남습니다.
  • 지표 표시를 켜고 끄는 것은 화면만 바꿉니다. 시세 재조회나 모델 실행을 하지 않습니다.
  • null은 0이 아닙니다. 준비 구간·결측값을 임의 숫자로 채우지 않습니다.
  • 가격 bars와 지표 values는 같은 길이와 시간축을 따라야 합니다. 불일치는 조회 또는 차트 표시 오류로 드러납니다.
  • 지원 주기는 일봉 1d·주봉 1wk입니다. 표시 봉 수는 2–200 범위입니다. 긴 계산 이력과 표시 봉 수는 다릅니다.
전체 native TA-Lib 채팅은 별도 talib_agent입니다. 이 Canvas의 TA20·FinancialChart 경로와 동일한 도구 집합이라고 생각하지 마세요.
