# SEC A2UI UX 독립 리뷰 · 2026-09-22

## 범위와 근거

사용자 요청: SEC 조회 A2UI의 이해하기 어려운 흐름을 UX Review agent가 재점검하고 재설계한 뒤 실제 `http://localhost:2820/a2ui/sec`에서 검증한다. 이 문서는 독립 리뷰 에이전트의 진단과 권고다. 구현 및 브라우저 PASS를 뜻하지 않으며, 후속 구현 기록에서 채택 범위와 실행 증거를 연결한다.

확인한 현재 근거:

- [문서 지도](../INDEX.md), [공통 설계 원칙](../stock/tech-shared/design-principles.md), [SEC 현재 설계](../stock/tech-shared/a2ui-system/sec.md), [도메인 지도](../stock/us-corporate-filings/INDEX.md).
- `1-fe-host/src/features/a2ui-demo/{demo,output-workspace,activity-renderer,progress-view}.tsx`.
- `3-langgraph-fast/src/graph/primary_graphs/sec_a2ui/{surface,workflow,report_surface}.py`.
- 기존 [Inline/Canvas 실제 화면](evidence/2026-09-22-sec-agent/mcp-inline-canvas.png). 이는 이전 실행의 화면이며 이번 작업의 실시간 브라우저 관찰이 아니다.

소스와 위 화면에서 확인한 UI 구조를 **확인**으로, 사용자 영향에 대한 리뷰 판단을 **해석**으로 구분한다. 주 에이전트가 실시간 브라우저를 독점 사용하며 본 리뷰 에이전트는 공유 브라우저·서비스를 조작하지 않는다.

## 권고 흐름

### 1. 진입

업무 제목, 한 문장 설명, 회사·티커 입력 또는 요청 예시를 보여준다. 기본은 대화에 결과를 남긴다. '무엇을 할 수 있나요?'는 안내만 답하고 화면 조회를 실행하지 않는다. 선택하지 않은 Canvas 빈 영역은 숨긴다.

### 2. 회사 확인

회사명·티커 결과와 '이 회사 공시 보기'를 같은 결과 단위에 둔다. 검색 결과가 하나여도 회사 선택과 분석 문서 선택의 의미를 혼합하지 않는다. 자연어로 특정 회사의 공시를 요청했고 회사가 명확한 경우에는 기존 에이전트 규칙대로 회사 단계를 거쳐 공시 목록을 바로 제시할 수 있다.

### 3. 공시 선택

선택 회사, 공시 개수, 분석 가능 여부를 보인다. 문서별 주 표기는 '10-K · 보고기간 · 제출일'이며 수정본은 구별한다. 해당 문서의 직접 선택 버튼을 제공한다. 전체 필터를 쓰지 않아도 분석 가능한 공시를 찾을 수 있도록 빠른 경로를 제공한다. 사용자가 선택하지 않은 문서의 분석을 자동 시작하지 않는다.

### 4. 분석 요청

현재 회사와 선택 문서를 확인한 상태에서 '핵심 요약', '위험 요인', 직접 요청을 제공한다. 요청한 항목만 분석하며 같은 원문·인용 검증을 거친다. 공시 변경 경로가 회사 재검색보다 가깝게 보인다. 분석 불가능한 문서는 이유와 공시 목록으로 돌아가는 행동이 표시된다.

### 5. 결과와 후속 요청

회사·문서·분석 요청을 결과 제목 주변에 보존한다. 본문, 근거, 분석 한계를 제공한다. 새 자연어 렌더링은 Inline의 새 surface를 만들며 과거 결과는 상단의 읽기 전용 표시로 구별한다. Canvas 모드에서는 현재 작업 화면 한 곳을 갱신한다. Fixed/Dynamic, surfaceId, ToolNode 같은 구현 용어는 주 업무 안내에 노출하지 않는다.

### 6. 오류·빈 결과·복구

빈 회사 검색에는 검색어 변경, 빈 공시에는 조건 변경, 미저장 원문에는 분석 가능한 공시 선택을 안내한다. 서비스 또는 모델 실패는 기존 정상 결과를 보존한다. 처리 중 버튼이 잠기며 실패 후 다시 사용할 수 있다. 새 대화는 결과/Canvas/표시 위치를 초기화한다.

## 유지할 계약

- SEC-A2UI-10: 단일 LangGraph의 에이전트가 실제 도구를 선택한다. 기능 질문을 무조건 검색하지 않는다.
- SEC-A2UI-11: Inline 렌더링마다 새 ID, Canvas는 대화당 동일 ID. 화면 버튼은 발신 화면 문맥을 사용한다.
- 공시를 조용히 임의 선택하거나 새 원문 수집을 자동 시작하지 않는다.
- 공시 식별자·보고서 출처·인용·수정본 관계와 분석 한계는 서버 권위를 유지한다.
- UI의 직접 선택/빠른 분석은 허용 action을 확장하거나 재사용하며 기존 revision·문맥 검증을 우회하지 않는다.

## 주 에이전트의 실시간 초기 관찰 인계

2026-09-22 주 에이전트가 2820 실브라우저 DOM에서 기본 Inline 상태의 두 열·빈 Canvas, 서로 경쟁하는 세 설명/환영 문구, 업무보다 먼저 나타나는 출력 위치 Select를 확인했다고 전달했다. 본 리뷰 에이전트의 직접 브라우저 관찰과 구분한다. 소스 진단 SEC-UX-02/03을 뒷받침한다.

구현 인계에서 채택한 방향은 결과별 직접 action, 단계 제목/문맥, 과거 Inline 결과의 접기/다시 보기(읽기 전용 유지), Canvas 사용 전 한 열, 분석 프리셋, 명확한 문서 제목·날짜, 간결한 로딩이다. 출력 위치는 '다음 답변'에 적용된다는 표현과 각 결과의 목적지 표시를 권고했다. Canvas 버튼의 자체 문맥은 그대로 유지한다.

추가 주의: 분석 가능 문서만 표시하는 기본값을 택하면 현재 필터임을 눈에 보이게 표시하고 전체 공시 경로를 유지해야 한다. '공시가 없음'과 '저장된 분석 가능 공시가 없음'을 구분한다. 과거 결과를 접더라도 다시 펼쳐 원문/근거를 읽을 수 있어야 하며 펼침이 서버 action을 재활성화하지 않는다.

## 구현 후 독립 재리뷰 · 구현 중 스냅샷

2026-09-22 구현 차이와 [선택 후 화면](evidence/2026-09-22-sec-ux/analysis-before-review.png)을 재확인했다. 브라우저는 주 에이전트가 조작했으며 이 절은 소스와 전달받은 화면에 대한 독립 리뷰다. 최종 테스트 결과가 아니다.

### 확인된 개선

- 기본 Canvas 빈 영역 제거, 넓은 단일 대화 영역, '다음 답변' 목적지 표현이 적용되었다.
- 회사/공시의 직접 버튼으로 표와 중복 Select가 제거되었다. 분석 가능한 연간보고서라는 기본 필터 범위를 화면에 표시하고 연간/분기/전체 빠른 전환과 추가 조건을 제공한다.
- 선택 화면에서 회사, 공시 종류와 제출일, 보고기간이 분석 프리셋보다 먼저 보인다. 화면의 다음 행동은 '핵심 요약'으로 명확하며 위험 요인과 전체 분석도 가능하다.
- 식별자/원본·수정본 상세, 직접 요청, 다른 회사 찾기는 접힌 보조 영역으로 정리되었다. 과거 Inline은 펼칠 수 있는 읽기 전용 결과로 구별된다.
- 반복적인 처리 단계 목록 대신 짧은 완료 상태가 표시된다.

선택 단계의 주 행동/문맥과 공간 배치는 초기 리뷰의 주요 문제를 해소했다. 아래 한정된 후속 수정과 수용 테스트가 필요하다.

## 후속 소스 재검토 · R1–R4

2026-09-22 주 에이전트의 수정 후 소스를 재검토했다. R1은 보고서 앞 `report-document`의 종류/보고기간/제출일로, R2는 대상이 포함된 과거형 완료 문장과 모델 지침으로, R3은 `surface-title.ts`의 최신 전체 updateComponents 기준 제목으로 반영되었다. 이 세 항목은 소스 기준 해결이다. 실행 결과는 별도 검증 기록을 따른다.

추가 검토에서 **SEC-UX-R4: 과거 보고서의 접힌 내용 열람 불가**를 확인했다. `activity-renderer.tsx`의 과거 결과는 `fieldset disabled`로 감싸져 있고, `navigation-adapters.tsx`의 Accordion/Collapsible은 Base UI의 native 버튼 트리거를 사용한다. 따라서 바깥 이력 details를 펼쳐도 안쪽 출처·접이식 분석 본문은 열 수 없다. 모든 세부 내용이 펼쳐진 상태라고 전제할 수 없으므로 읽기 전용 이력 열람 계약의 차단 문제다. 바깥 summary만 확인한 직전의 비차단 판단은 이 발견으로 정정한다.

권고: 과거 결과의 업무 action Button/Input/Select만 잠그고 열람 전용 Accordion/Collapsible 트리거는 유지한다. 클라이언트 onAction과 서버의 과거 surface action 거절은 계속 유지한다. 회귀 증거로 과거 보고서를 다시 펼친 뒤 출처/분석 Accordion을 열 수 있고 회사·공시·분석 action은 실행할 수 없음을 함께 확인해야 한다. 실행 중 임시 잠금과 영구 이력 읽기 전용은 별도 상태다.

## R4 해소와 보고서 최종 시각 검토

2026-09-22 재수정 후 `activity-renderer.tsx`와 `catalog.tsx`를 확인했다. 과거 결과의 영구 잠금은 `SurfaceReadOnly`로 전달하며 SEC의 업무 `Button`, `Input`, `Select`에만 `disabled`를 적용한다. `fieldset`은 실행 중에만 잠긴다. Accordion/Collapsible 자체는 비활성화하지 않으며 과거 onAction 거절도 남아 있다. R4의 소스 원인은 해소되었다.

주 에이전트가 Storybook 94개 통과 및 실브라우저 위험 분석→표현 변경→과거 출처 펼침→과거 업무 버튼 비활성화를 통과했다고 전달했다. 본 리뷰 에이전트는 해당 실행을 직접 조작하지 않았으며 전달받은 실행 증거와 소스를 구분한다.

`1-fe-host/test-results/sec-agent-SEC-A2UI-12-revi-95243-upports-agent-layout-change-chromium/sec-ux-risk-report.png`를 직접 열어 시각 확인했다. 과거 결과는 짧게 접히고 현재 회사, 10-K, 보고기간, 제출일이 본문 앞에 보인다. 위험 분석은 카드로 분리되며 원문 인용이 해당 주장과 함께 유지된다. 분석 한계와 출처 펼침, 추가 분석/공시 변경 경로도 결과 하단에 있다. 현재 화면의 문서 식별과 다음 행동에 새로운 차단 문제는 보이지 않는다. 긴 분석에서 인용문 때문에 높이가 늘어나는 것은 남지만, 이번 범위의 정보 보존 계약에 부합한다.

이 평가는 제공된 데스크톱 보고서 화면과 읽기 전용 소스 검토 범위다. 모바일/Canvas 실행 증거는 후속 검증 기록에서 확인한다. 테스트 출력 경로는 실행 산출물이며 영구 증거 경로로 복사할 때 후속 기록에 연결한다.

## 영구 증거와 Canvas 최종 시각 확인

위 보고서 테스트 출력은 [최종 보고서 증거](evidence/2026-09-22-sec-ux/sec-ux-risk-report.png)에 보존되었다. 이후 참조는 임시 `test-results` 경로 대신 이 링크를 사용한다.

[최종 Inline/Canvas 증거](evidence/2026-09-22-sec-ux/sec-ux-inline-canvas.png)를 직접 열어 확인했다. 왼쪽의 AAPL Inline 결과와 오른쪽의 MSFT 작업 화면이 각 회사명·티커·목적지 표시로 구분된다. CPNG 과거 결과는 읽기 전용 접힘 이력으로 남는다. Canvas 제목은 MICROSOFT CORP이며 회사 입력/결과도 MSFT로 일치하여 이전 CPNG 문맥이 제목에 잔존하지 않는다. '다음 답변 → 작업 화면에서 이어가기' 표시와 기존 결과 유지 안내도 보인다. 이 정적 화면 범위에서 새 차단 문제는 없다.

주 에이전트는 Canvas 시나리오 PASS를 전달했다. ID 유지와 버튼 문맥 격리는 정적 이미지 자체로 판정할 수 없으므로 실행 테스트 증거를 따른다. 긴 페이지의 전체 캡처에서 sticky 패널 위치는 실제 현재 뷰포트 상태를 반영하므로 상단 여백만으로 위치 실패라고 판정하지 않았다. 모바일 평가는 아직 대기한다.

## 모바일 최종 시각 검토와 리뷰 종료

[모바일 최종 증거](evidence/2026-09-22-sec-ux/sec-ux-mobile.png)를 직접 열어 확인했다. 제목과 설명은 좁은 폭에서 줄바꿈되고, 다음 답변 선택기·회사 문맥·선택 문서 종류/제출일·보고기간·세 분석 버튼이 화면 안에 배치된다. 접수번호 상세, 직접 분석 요청, 공시/회사 변경도 각기 구별된다. 제공 이미지에서 잘린 주 행동이나 가로 넘침은 보이지 않는다. 새 Canvas를 강제로 노출하지 않는 단일 영역은 모바일에서도 유지된다.

주 에이전트는 최초 모바일 빠른 시작에서 runtime 준비 전 임시 agent에 요청하여 결과가 누락된 FAIL과, `useAgent.isReady` 가드 적용 뒤 분기/전체/추가 조건 빈 결과/복구/선택/가로폭 시나리오 38.8초 PASS를 전달했다. `sec-welcome.tsx`를 직접 읽어 클릭 가드와 준비 전 버튼 비활성화가 모두 적용됨을 확인했다. 이 기록은 초기 실패를 삭제하지 않고 수정 후 통과와 구분한다.

잔여 비차단 UX 메모: 필터를 여러 번 바꾸면 '공시 목록을 열었습니다' 같은 확인 메시지가 쌓여 모바일 세로 길이가 길어진다. 현재 행동은 상단 A2UI 안에 명확히 있고 확인 문장은 완료형이어서 지시 충돌은 해소되었다. 향후 버튼 기반 조건 변경의 반복 확인을 줄이면 대화 입력창까지 이동하는 부담을 더 낮출 수 있다. 이번 완료를 막는 새 결함으로 판정하지 않는다.

**독립 리뷰 결론**: 소스와 전달받은 데스크톱 보고서·Inline/Canvas·모바일 이미지 범위에서 R1–R4가 반영되었고 추가 차단 UX 결함을 찾지 못했다. 브라우저의 최종 전체 재실행, 키보드 점검, 자원 정리는 주 에이전트 검증 기록에 맡긴다. 본 리뷰 에이전트는 브라우저나 서비스에 접속/변경하지 않았고 이 문서만 작성했다.
