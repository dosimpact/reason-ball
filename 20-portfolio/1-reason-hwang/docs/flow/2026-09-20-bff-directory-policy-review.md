# BFF-DIR-001: 단순한 디렉터리 정책 우선 리뷰

- 날짜: 2026-09-20
- 도메인: tech-shared BFF / us-corporate-filings
- 맥락: 진행 중인 책임 분리가 사용자가 원하는 수준보다 많은 모듈과 파일을 만들었다.
- 사용자 결정: 업무 모듈 하나를 AppModule에 연결, 외부 SEC 연동·명세는 lib, TypeORM·DTO는 entity, 업무 서비스 중심으로 간소화. 코드 정리 전에 정책 문서를 먼저 리뷰한다.
- 산출물: [디렉터리 정책 초안](../stock/tech-shared/2-bff-apps/directory-policy.md).
- 상태: 정책 리뷰 대기. 기존 리팩터링 작업 트리는 보존하고 추가 코드 변경·API 삭제·전체 작업 커밋은 진행하지 않았다.
- 범위 미확정: 원문 다운로드 기본 포함 여부, 5개 업무 API 외 비동기 작업 상태 조회 1개 유지 여부, 기존 parser 소비자 전환.
- 정리: 이전 턴에서 소유한 Swagger 테스트 서버를 종료해 해당 임시 PostgreSQL·ZIP fixture를 정리했다.
- 검증: 문서 구조·로컬 링크·목표 모듈/API 목록 확인. 이번 변경은 문서만이므로 실행 검증 대상이 아니다.
- 대체 관계: 이전 BFF-STRUCTURE-001 중간 구조를 확정안으로 취급하지 않는다. 과거 flow 내용은 보존한다.

## 2026-09-20 리뷰 반영: SEC client와 타입 통합

- 사용자 결정: `sec.client.ts`와 `sec.types.ts`를 파일 하나로 구성한다.
- 변경·이유: 외부 SEC 요청·응답 타입을 `sec.client.ts`에 함께 정의하여 불필요한 파일 분리를 줄인다.
- 반영 위치: BFF-DIR-001 정책의 2번 목표 디렉터리 및 타입 배치 규칙.
- 검증·상태: 정책 트리에서 별도 타입 파일을 제거하고 본문 규칙과 일치시켰다. 코드 적용은 정책 리뷰 후 진행한다.

## 2026-09-20 승인 및 후속 변경

- 사용자가 정책을 승인하고 구현을 요청했다. 메타데이터→옵션 원문 순서를 확정했다.
- 이후 작업 Entity·상태 GET 대신 백필 POST SSE만 유지하도록 변경했다. 기존 5+1 권장안은 채택하지 않는다.
- [구현·검증 기록](2026-09-20-bff-simplification-sse.md)이 최신 실행 결과와 stock 동기화를 기록한다.
