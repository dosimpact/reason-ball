# Persona English 비즈니스 설계

> 저량(Stock) · 2026-09-30 동기화 · [문서 지도](../README.md) · [시스템](system-design.md) · [테스트](test-design.md)

## 1. 제품과 사용자

Persona English는 한국어 설명을 선호하는 영어 학습자가 AI 캐릭터와 실생활 역할극을 연습하는 웹 앱이다. 학습자는 첫 발화를 시작하기 어렵고, 일반 채팅에서는 과업 완료·교정·다음 연습이 흐릿하다. 창작자는 캐릭터의 말투와 교육 태도, 미션의 목표와 단계를 일관되게 저작하고 게시해야 한다. 제품은 **발견 → 대화·힌트·교정 → 평가·보상 → 복습·재도전**의 학습 흐름과 **초안 → 검토 → 게시 → 버전 관리**의 창작 흐름을 제공한다.

첫 대상은 pre-A1~A2 성인 학습자다. 제공 카탈로그는 C2까지 넓지만 전체 수준의 학습 효과나 원어민 수준 도달을 입증한 것은 아니다. 로그인 전 방문자·익명 체험 계정, 정회원 학습자, 자기 콘텐츠를 관리하는 창작자, 전체 카탈로그를 확인하는 제한된 관리 계정의 권한을 구분한다. 후자의 역할은 전역 관리자 권한이 아니다.

## 2. 지금 제공하는 경험

| 영역 | 현재 제품 동작 | 진입 화면 |
|---|---|---|
| 홈·탐색 | 캐릭터·미션 추천, 최근 대화 이어하기, 검색·상세·빈 상태 | `/`, `/characters`, `/missions` |
| 저작 | 캐릭터·미션 초안 작성, AI 보조, 게시 버전과 내 생성물 편집 | `/characters/new`, `/missions/new`, `/:id/edit`, `/profile` |
| 학습 | 자유/미션 대화, 저장된 기록 복원, 단계·힌트·교정·평가·보상 | `/chat/:characterId`, `/history` |
| 개인 공간 | 학습 설정, 진도, 즐겨찾기·저장 미션, 복습 노트, 보상 | `/profile` |
| 공유 | 공개 또는 토큰 링크의 읽기 전용 대화 | `/shared/:token` |

위 표는 라우트와 기능의 존재를 뜻한다. 실제 AI·원격 DB를 통한 최종 사용자 결과는 [테스트 설계](test-design.md)의 최신 실행 결과로 판정한다. 홈은 상단 탐색과 모바일 메뉴·하단 탐색을 사용한다. 고정 대화는 예시로 표시하며 가짜 점수·무동작 재생 버튼을 두지 않는다. 첫 CTA는 실제 미션 목록으로 이동하고 단일 공개 캐릭터를 추천과 인기 영역에 중복 노출하지 않는다. 데이터 로딩·오류는 관련 영역에서 보여 준다.

발견 화면은 캐릭터 상세의 관련 미션을 최대 6개만 미리 보여 주고 전체 목록은 캐릭터 필터가 적용된 `/missions`에서 연다. 미션 목록은 이전·페이지 선택·다음으로 모든 페이지에 접근하며 카테고리에 맞는 장소 옵션을 표시한다. 캐릭터의 대화 수는 사람 수로 표현하지 않고, 자유 대화와 추천 미션 진입을 구분한다. 실제 평점 데이터가 없는 캐릭터 카드·상세에는 평점이나 별점을 표시하지 않는다. 채팅 본문에서 내부 대화 ID를 노출하지 않으며 필요한 ID는 대화 관리에서 확인한다. 대화 기록은 메시지 수와 실제 빈 기록·검색 결과 없음 상태를 구분한다. 학습 설명에는 확인되지 않은 자동 난이도 조절이나 기능 지원을 단정하지 않는다. 이 화면 표현은 `CHAR-07`, `MISSION-06`, `DISC-03/04`, `CHAT-02/04`, `REF-03/04`에 적용한다.

## 3. 미션 카탈로그와 접근 정책

- `MISSION-CATALOG-01`: `assets/missions/authoring/`의 원본을 컴파일해 4개 대분류·24개 세부 영역·pre-A1~C2 7수준의 실생활 672개와 직무 문제 해결 80개, 총 752개 미션을 관리한다. 기존 샘플 1개는 별도로 보존되어 관리 계정의 원격 전체 목록은 753개다. 로컬 저작 상태 `draft`와 원격 게시 상태, 사람 교사/학습자 검증은 서로 다른 값이다.
- `MISSION-CURRICULUM-01/02/03`: 각 과업은 상황, 상대 역할, 관찰 가능한 결과, 단계별 영어 예문과 한국어 힌트를 가진다. 연구 자료와 10개 초보 진입 과업·24개 관심 영역 경로를 연결한다. 경로는 추천이며 자동 배정이나 선수 잠금이 아니다. 연구가 개별 미션의 학습 효과를 증명한 것은 아니다.
- `MISSION-PROBLEM-SOLVING-01`: 개발자·디자이너·IT 운영·비즈니스 회의 미션은 사실, 제약, 권한, 미확인 사항을 영어 질문·협의로 다루고 결정 또는 후속 확인을 남긴다. 특정 기술 정답을 영어 정답으로 강제하지 않는다.
- `MISSION-PROVISION-01/02`: 정회원은 프로필의 CEFR·관심 상황을 저장한 뒤 초기 5개 미션을 한 번 배정받는다. 재접속과 프로필 변경이 배정을 늘리거나 바꾸지 않는다. 정회원의 목록·상세·신규 실행은 배정된 미션에 한정되며 서버와 DB가 확인한다. 관리 계정은 전체 카탈로그를 확인하되 타인의 비공개 초안을 얻지 않는다.
- `MISSION-GUEST-BROWSE-01`: 미로그인·익명 체험 계정은 게시된 공개 미션 전체의 목록·검색·상세를 볼 수 있다. 비공개 지침과 초안은 제외한다. 열람은 시작 권한이 아니며 회원 전환 후에는 정회원 배정 규칙을 적용한다.

저작 형식·검증 명령은 [미션 자산 안내](../../assets/missions/README.md), 교육과정 상세와 연구 한계는 [교육과정 설계](../research/mission-curriculum-design.md)와 [연구 근거](../research/mission-learning-evidence.md)에 둔다.

## 4. 요구사항 원장 — 수용 기준

### 4.1 Vercel Chatbot 기준 기능

다음 표는 일반 AI 채팅의 수용 기준이다. 표에 있다는 이유만으로 구현 또는 실연동 검증이 끝난 것은 아니다.

| ID | 기능 | Persona English 적용 방식 |
|---|---|---|
| CHAT-01 | 게스트/회원 인증 | 체험은 익명 사용자, 동기화·창작·공개는 회원 권장 |
| CHAT-02 | 새 대화와 대화 기록 | 캐릭터 및 선택 미션 단위로 대화 생성·목록·재개 |
| CHAT-03 | 스트리밍 응답 | Vercel AI SDK UI 메시지 스트림 사용 |
| CHAT-04 | 모델 선택 | 허용된 모델 카탈로그에서 대화별 선택, 기본값 제공 |
| CHAT-05 | 첨부파일 | 이미지/문서 첨부와 메시지 파트 표시 |
| CHAT-06 | 메시지 편집·재생성 | 사용자 메시지 편집 후 분기, 마지막 답변 재생성 |
| CHAT-07 | 응답 평가 | 좋아요/싫어요와 선택적 사유 저장 |
| CHAT-08 | 공개 범위·공유 | private/unlisted/public 정책과 공유 링크 |
| CHAT-09 | 대화 삭제 | 소유자만 삭제, 연결된 개인 데이터 정책 적용 |
| CHAT-10 | 추천 프롬프트 | 캐릭터·미션·학습 단계별 다음 발화 제안 |
| CHAT-11 | 도구 호출 | 미션 상태 조회, 표현 힌트, 평가, 사전/상황 정보 도구 |
| CHAT-12 | 아티팩트 | 긴 학습 노트, 단어장, 미션 요약을 별도 패널로 표시 |
| CHAT-13 | 스트림 복구 | 새로고침/네트워크 단절 뒤 진행 중 응답 복구 정책 |

| CHAT-15 | 멀티모달 메시지 | text/file/tool/reasoning 등 파트 기반 메시지 모델 |

| REF-19 | 삭제 | 개별/전체 삭제 확인과 영속 반영 |

| REF-23 | 날씨 도구 | 성공·거절·실패 UI를 포함한 예시 tool |
| REF-24 | Artifact 생성 | Text, Code, Image, Sheet workspace |
| REF-25 | Artifact 편집 | 직접 편집, targeted edit, rewrite, autosave |
| REF-26 | Artifact 버전 | 이전/다음, diff, 복원, 최신 복귀 |
| REF-27 | Text Artifact | 문서와 문법·문장 suggestion 적용 |
| REF-28 | Code Artifact | 편집, 격리 실행, output/error, copy |
| REF-29 | Sheet Artifact | 표 편집, 정리, 분석, CSV copy |
| REF-30 | Image Artifact | 이미지 생성, 편집, 버전, 저장·재조회 |
| REF-31 | 영속성 | chat/message/vote/artifact/suggestion/stream reload 복원 |
| REF-32 | 비용 보호 | 인증, 소유권, 사용자/IP rate limit, bot 방어, model allowlist |
| REF-33 | 오류 복구 | chat/upload/tool/artifact/storage별 설명과 retry |
| REF-34 | 관찰 가능성 | request/stream/tool/cost/error 상관 추적 |

Artifact 작업영역은 목록, 편집 입력, 미리보기와 버전 비교를 light/dark 테마에서 읽을 수 있게 표시한다. 테마 변경은 Artifact의 저장·버전 계약을 바꾸지 않는다.

자유 대화와 미션 대화는 같은 저장·생성 기반을 사용한다. 미션 대화는 고정 버전, 학습 목표, 평가·보상 권한을 추가로 검사한다.

### 4.2 캐릭터 시스템

| ID | 요구사항 | 완료 기준 |
|---|---|---|
| CHAR-01 | 캐릭터 생성 단계 | 이름, 소개, 성격, 목표, 관계, 말투, 교육 태도, 금지 지침 입력 |
| CHAR-02 | AI 프로필 이미지 생성 | 프롬프트로 복수 후보 생성, 하나를 선택해 저장 |
| CHAR-03 | Supabase Storage 저장 | 원본/게시 자산 정책에 맞는 버킷과 경로에 업로드 |
| CHAR-04 | 캐릭터 모델링 | 입력값을 구조화된 버전으로 저장하고 런타임 프롬프트로 컴파일 |
| CHAR-05 | 미리보기 | 게시 전에 외형, 공개 정보, 짧은 대화 샘플 확인 |
| CHAR-06 | 초안·게시·버전 | draft/published/archived 상태와 불변 게시 버전 유지 |
| CHAR-07 | 캐릭터 발견 | 검색, 태그, 난이도, 인기/신규 필터 및 상세 페이지 |
| CHAR-08 | 즐겨찾기 | 캐릭터를 저장하고 홈·프로필에서 다시 접근 |
| CHAR-09 | 보상 갤러리 | 잠긴 이미지와 해금된 이미지를 구분해 표시 |
| CHAR-10 | 안전 정책 | 이미지/텍스트 입력 검토, 신고와 비공개 전환 정책 |

캐릭터의 `목표`는 단순 설명이 아니라 대화 행동의 방향이다. 예: “처음 해외여행을 온 학습자가 체크인에 성공하도록 기다려 주는 친절한 호텔 직원.” 캐릭터의 숨겨진 시스템 지침과 공개 프로필은 분리한다.

## 5. 수용·안전 기준

| ID | 요구사항 | 수용 기준 |
|---|---|---|
| NFR-01 | 반응형 | 360px 모바일부터 데스크톱까지 핵심 여정 사용 가능 |
| NFR-02 | 접근성 | 키보드 탐색, 명시적 레이블, 상태 알림, 색상 외 정보 제공 |
| NFR-03 | 체감 성능 | 즉시 낙관 UI, 스트리밍 상태, 이미지 지연 로딩/대체 UI |
| NFR-04 | 복원력 | 생성 실패 시 입력 보존, 재시도, 중복 보상 방지 |
| NFR-05 | 개인정보 | 비공개 기본값, 최소 수집, 삭제/내보내기 경로 |
| NFR-06 | 안전 | 입력·출력·이미지 정책, 신고, 미성년자 친화 기본값 |
| NFR-07 | 비용 통제 | 사용자/기능별 한도, 이미지·TTS·대화 사용량 계측 |
| NFR-08 | 검증 가능성 | 외부 시스템 mock과 안정적인 test id/role 기반 E2E |
| NFR-09 | 관찰 가능성 | 요청·생성 job·오류·지연을 상관 ID로 추적 |
| NFR-10 | 국제화 준비 | UI 문자열과 학습 언어/설명 언어를 분리 가능하게 설계 |

1. 현재 기능을 설명할 때 **요구사항**, **코드 구현**, **mock/계약/DB 검증**, **원격 Supabase·실제 AI·브라우저 검증**을 구별한다. ID별 최신 판정은 [테스트 설계](test-design.md)를 따른다.
2. 대화·학습 설정·저작 초안·복습 노트·해금 전 보상은 기본 비공개다. 공유 링크는 현재 공개 상태와 토큰을 확인하고 취소할 수 있어야 한다. 소유자 권한은 화면 숨김만으로 보장하지 않는다.
3. 서버는 저장된 캐릭터·미션 버전과 대화 메시지를 근거로 평가·보상한다. 브라우저 완료 표시나 전달된 owner ID로 XP·보상을 만들지 않는다. 힌트를 쓴 완료와 추적된 자립 완료를 구분하되 힌트 사용 자체가 점수·보상을 깎지 않는다.
4. 음성·이미지·AI 생성은 공급자 능력과 권한이 확인된 경로에서만 성공을 표시한다. 교정과 선택 발화 평가는 학습 지원이며 공인 시험 결과가 아니다. 원어민 수준이나 듣기·발음 숙달을 텍스트 평가만으로 주장하지 않는다.
5. 자동 결제, 수익 분배, 네이티브 앱, 사람 강사 화상 수업, 발음 음소 채점, 복습 스케줄러, 전체 752개 미션의 사람 검수와 학습 효과 입증은 현재 완료 범위가 아니다.

## 6. 출시 판정

현재의 release gate는 [테스트 설계 §4–5](test-design.md#4-최신-실행-판정)다. 특히 실제 OAuth AI 채팅 스트림과 원격 Supabase 성공 경로를 통과해야 하며, mock·PGlite·부분 E2E PASS를 전체 서비스 PASS로 합치지 않는다. 미션 원격 적재·배정 성공은 카탈로그의 모든 대화·평가·보상 품질 검증을 뜻하지 않는다.
