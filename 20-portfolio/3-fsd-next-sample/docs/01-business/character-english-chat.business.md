# Persona English 비즈니스 설계서

> 문서 상태: 구현 기준선 1.0  
> 작성일: 2026-09-05  
> 대상 독자: 제품 책임자, 기획자, 디자이너, 개발자, QA  
> 연계 문서: `02-development/character-english-chat.development.md`, `03-validation/character-english-chat.implementation-e2e.md`

## 1. 문서 목적

Persona English는 사용자가 직접 만들거나 발견한 AI 캐릭터와 역할극 미션을 수행하며 실생활 영어 회화를 연습하는 서비스다. 이 문서는 제품이 풀어야 할 문제, 제공할 가치, 전체 기능 범위, 핵심 사용자 여정, 성공 기준을 정의한다.

제품의 기준선은 Vercel의 Next.js Chatbot 템플릿이 제공하는 현대적인 AI 채팅 경험이다. Persona English는 그 기능을 보존하면서 캐릭터 모델링, 미션 제작, 학습 평가, 음성 재생, 이미지 보상, 발견과 성장 시스템을 추가한다.

기준 자료는 2026-09-05에 확인한 [Vercel Chatbot 템플릿](https://vercel.com/templates/next.js/chatbot)과 [공개 소스 저장소](https://github.com/vercel/chatbot)다. 공식 기준의 App Router, AI SDK, shadcn/Tailwind, 인증, 대화 영속성 및 멀티 모델 경험을 최소선으로 삼고, 실제 소스의 채팅·도구·Artifact 사용자 흐름을 `REF-*` gate로 세분화했다.

이 문서의 요구사항 ID는 개발 설계와 E2E 검증 결과에 동일하게 사용한다. 화면이 존재하거나 단위 테스트가 통과한 것만으로는 완료로 인정하지 않는다. 사용자가 실제 브라우저에서 핵심 결과를 확인하는 E2E 시나리오가 통과해야 해당 기능을 `검증됨`으로 본다.

## 2. 제품 한 문장

> 내가 좋아하는 AI 캐릭터와 현실적인 역할극을 완수하고, 즉시 교정과 음성 피드백을 받으며 매일 말할 수 있는 영어를 늘리는 서비스.

## 3. 해결하려는 문제

### 3.1 학습자의 문제

- 초급 학습자는 문법과 단어를 알아도 호텔, 카페, 공항 같은 실제 상황에서 첫 문장을 꺼내기 어렵다.
- 범용 챗봇은 무엇을 연습해야 하는지, 언제 미션을 끝냈는지, 실력이 어떻게 나아졌는지 알려주지 않는다.
- 동일한 튜터와 반복 학습하는 정서적 동기와 수집·성장 보상이 부족하다.
- 음성 예시와 자연스러운 표현을 문맥 안에서 즉시 듣고 따라 할 기회가 부족하다.
- 실수에 대한 불안 때문에 사람과 대화하기 전에 안전하게 연습할 공간이 필요하다.

### 3.2 창작자의 문제

- 매력적인 캐릭터의 외형, 성격, 목표, 말투와 교육 규칙을 일관된 AI 페르소나로 만들기 어렵다.
- 교육적으로 유효한 역할극 미션을 단계, 필수 표현, 성공 조건, 힌트, 보상까지 구조화하기 어렵다.
- 캐릭터와 미션을 공개하고 개선할 수 있는 버전·미리보기·게시 흐름이 필요하다.

### 3.3 사업 기회

범용 AI 채팅의 자유도와 언어 학습 앱의 구조적인 진도를 결합한다. 캐릭터에 대한 애착은 반복 방문을 만들고, 짧은 실생활 미션은 학습 성취를 명확히 하며, 해금 이미지와 연속 학습은 장기 동기를 만든다.

## 4. 제품 원칙

1. **대화가 곧 학습이다.** 설명을 먼저 읽게 하기보다 역할극 안에서 말하고, 필요한 순간에 힌트와 교정을 제공한다.
2. **초급자에게 다음 행동을 보여준다.** 빈 입력창만 주지 않고 목표, 추천 답변, 필수 표현, 남은 단계를 항상 알 수 있게 한다.
3. **캐릭터는 일관된 동료다.** 외형뿐 아니라 성격, 목표, 관계, 말투, 교육 태도를 버전이 있는 모델로 보존한다.
4. **보상은 학습 행동과 연결한다.** 이미지 해금은 결제나 무작위 클릭이 아니라 미션 성공과 성장의 결과다.
5. **안전하고 설명 가능한 평가를 한다.** 학습자에게 점수만 주지 않고 근거, 더 자연스러운 표현, 다음 연습을 제공한다.
6. **검증되지 않은 기능을 완료라고 부르지 않는다.** 모든 제품 기능은 브라우저 E2E 시나리오와 연결한다.
7. **외부 인프라는 교체 가능해야 한다.** AI, 저장소, 음성, 이미지 생성은 제품 도메인과 분리된 어댑터로 취급한다.

## 5. 목표와 비목표

### 5.1 1차 목표

- CEFR Pre-A1~A2 학습자가 5~10분 안에 하나의 실생활 영어 미션을 끝낸다.
- 사용자가 캐릭터를 생성하고 AI 이미지를 선택해 저장·게시할 수 있다.
- 사용자가 미션을 직접 만들거나 AI 초안을 편집해 게시할 수 있다.
- 캐릭터와 스트리밍 채팅을 하며 미션 진행, 힌트, 교정, 완료 평가를 경험한다.
- 캐릭터 메시지 버블을 눌러 영어 TTS를 듣는다.
- 미션 완료 시 보상 이미지를 해금하고 프로필에서 다시 본다.
- Vercel Chatbot의 일반 채팅 기능을 학습 문맥에서도 사용할 수 있다.
- Supabase를 인증, 데이터베이스, 스토리지의 기준 시스템으로 사용한다.
- 테스트에서는 결정적인 mock 경계를 사용하고 모든 기능을 Playwright 브라우저 테스트로 검증한다.

### 5.2 1차 비목표

- 사람 강사와의 실시간 화상 수업
- 앱 내부 결제와 정산의 실제 운영
- 원어민 수준(C1~C2)의 시험 대비 커리큘럼
- 공개 캐릭터 마켓의 수익 배분
- 네이티브 iOS/Android 앱
- 음성 입력의 발음 파형 분석과 음소 단위 채점

비목표는 장기 로드맵에서 재검토할 수 있지만 초기 구현의 완료 조건에는 포함하지 않는다.

## 6. 핵심 사용자

### 6.1 민지 — 말문이 막히는 초급 학습자

- 수준: CEFR A1
- 목표: 해외 호텔과 식당에서 필요한 말을 혼자 할 수 있기
- 행동: 출퇴근 중 하루 10분 학습, 틀리는 것을 두려워함
- 성공: 힌트를 보더라도 역할극을 끝내고 다음날 다시 방문

**JTBD:** “해외에서 마주칠 장면을 미리 연습해서 실제 상황에서 첫 문장을 자신 있게 말하고 싶다.”

### 6.2 준호 — 캐릭터 팬형 반복 학습자

- 수준: A2
- 목표: 좋아하는 세계관의 캐릭터와 자연스럽게 매일 영어로 대화
- 행동: 수집과 연속 기록에 동기가 높음
- 성공: 캐릭터 관계 레벨과 보상 갤러리를 꾸준히 확장

**JTBD:** “공부처럼 느끼지 않으면서 좋아하는 캐릭터와 대화하고 표현을 쌓고 싶다.”

### 6.3 소라 — 학습 콘텐츠 창작자

- 역할: 영어 강사 또는 캐릭터·스토리 창작자
- 목표: 특정 학습 목표를 가진 캐릭터와 미션을 빠르게 제작하고 공유
- 성공: AI 초안을 수정해 게시하고 실제 학습 완료율을 확인

**JTBD:** “교육적으로 구조화된 역할극을 반복 제작하고 학습자 반응을 바탕으로 개선하고 싶다.”

## 7. 핵심 가치 루프

```text
캐릭터/미션 발견
        ↓
학습 목표와 보상 확인
        ↓
캐릭터와 역할극 대화
        ↓
힌트 · 음성 · 즉시 교정
        ↓
미션 평가와 이미지 해금
        ↓
진도/관계 성장 · 다음 미션 추천
        └──────────────────────→ 반복
```

창작 루프는 `아이디어 → AI 초안 → 편집 → 미리보기 → 게시 → 이용 데이터 → 새 버전`으로 구성한다.

## 8. 제품 범위

### 8.1 Vercel Chatbot 기준 기능

다음 기능은 일반 AI 채팅의 기준선으로 지원한다.

| ID | 기능 | Persona English 적용 방식 |
|---|---|---|
| CHAT-01 | 게스트/회원 인증 | 체험은 익명 사용자, 동기화·창작·공개는 회원 권장 |
| CHAT-02 | 새 대화와 대화 기록 | 캐릭터 및 선택 미션 단위로 대화 생성·목록·재개 |
| CHAT-03 | 스트리밍 응답 | Vercel AI SDK UI 메시지 스트림 사용 |
| CHAT-04 | 모델 선택 | 허용된 모델 카탈로그에서 대화별 선택, 기본값 제공 |
| CHAT-05 | 첨부파일 | 이미지/문서 첨부와 메시지 파트 표시 |
| CHAT-06 | 메시지 편집·재생성 | 사용자 메시지 편집 후 분기, 마지막 답변 재생성 |
| CHAT-07 | 응답 평가 | 좋아요/싫어요와 선택적 사유 저장 |
| CHAT-08 | 공개 범위·공유 | private/unlisted/public 정책과 공유 링크 |
| CHAT-09 | 대화 삭제 | 소유자만 삭제, 연결된 개인 데이터 정책 적용 |
| CHAT-10 | 추천 프롬프트 | 캐릭터·미션·학습 단계별 다음 발화 제안 |
| CHAT-11 | 도구 호출 | 미션 상태 조회, 표현 힌트, 평가, 사전/상황 정보 도구 |
| CHAT-12 | 아티팩트 | 긴 학습 노트, 단어장, 미션 요약을 별도 패널로 표시 |
| CHAT-13 | 스트림 복구 | 새로고침/네트워크 단절 뒤 진행 중 응답 복구 정책 |
| CHAT-14 | 사용량 제한 | 사용자 등급 및 비용별 속도·일일 생성 제한 |
| CHAT-15 | 멀티모달 메시지 | text/file/tool/reasoning 등 파트 기반 메시지 모델 |

위 요약 항목을 실제 Vercel Chatbot 수준으로 판정할 때는 다음 세부 호환 gate를 사용한다. `REF-*`는 삭제 가능한 참고 목록이 아니라 최종 release 요구사항이다.

| REF-15 | 메시지 액션 | copy와 assistant up/down vote |
| REF-16 | 메시지 편집 | 편집 지점 이후 분기를 교체하고 재생성 |
| REF-17 | 제목 | 첫 메시지 자동 제목과 수동 이름 변경 |
| REF-18 | 기록 | 날짜 그룹, pagination, 대화 재개 |
| REF-19 | 삭제 | 개별/전체 삭제 확인과 영속 반영 |
| REF-20 | 공개·공유 | private/public 링크와 비소유자 read-only 화면 |
| REF-21 | 도구 실행 | 다단계 server tool과 typed state UI |
| REF-22 | 도구 승인 | 민감 도구 Allow/Deny와 후속 대화 |

| REF-24 | Artifact 생성 | Text, Code, Image, Sheet workspace |
| REF-25 | Artifact 편집 | 직접 편집, targeted edit, rewrite, autosave |
| REF-26 | Artifact 버전 | 이전/다음, diff, 복원, 최신 복귀 |
| REF-27 | Text Artifact | 문서와 문법·문장 suggestion 적용 |
| REF-28 | Code Artifact | 편집, 격리 실행, output/error, copy |
| REF-29 | Sheet Artifact | 표 편집, 정리, 분석, CSV copy |
| REF-30 | Image Artifact | 이미지 생성, 편집, 버전, 저장·재조회 |
| REF-31 | 영속성 | chat/message/vote/artifact/suggestion/stream reload 복원 |
| REF-32 | 비용 보호 | 인증, 소유권, 사용자/IP rate limit, bot 방어, model allowlist |
| REF-33 | 오류 복구 | chat/upload/tool/artifact/storage별 설명과 retry |
| REF-34 | 관찰 가능성 | request/stream/tool/cost/error 상관 추적 |

Free Chat은 위 기능을 범용적으로 제공한다. Mission Chat은 같은 기반을 사용하되 학습 평가와 보상 무결성을 위해 모델·도구·지침을 제한한다.

### 8.2 캐릭터 시스템

| ID | 요구사항 | 완료 기준 |
|---|---|---|
| CHAR-01 | 캐릭터 생성 단계 | 이름, 소개, 성격, 목표, 관계, 말투, 교육 태도, 금지 지침 입력 |
| CHAR-02 | AI 프로필 이미지 생성 | 프롬프트로 복수 후보 생성, 하나를 선택해 저장 |
| CHAR-03 | Supabase Storage 저장 | 원본/게시 자산 정책에 맞는 버킷과 경로에 업로드 |
| CHAR-04 | 캐릭터 모델링 | 입력값을 구조화된 버전으로 저장하고 런타임 프롬프트로 컴파일 |
| CHAR-05 | 미리보기 | 게시 전에 외형, 공개 정보, 짧은 대화 샘플 확인 |
| CHAR-06 | 초안·게시·버전 | draft/published/archived 상태와 불변 게시 버전 유지 |
| CHAR-07 | 캐릭터 발견 | 검색, 태그, 난이도, 인기/신규 필터 및 상세 페이지 |
| CHAR-08 | 즐겨찾기 | 캐릭터를 저장하고 홈·프로필에서 다시 접근 |
| CHAR-09 | 보상 갤러리 | 잠긴 이미지와 해금된 이미지를 구분해 표시 |
| CHAR-10 | 안전 정책 | 이미지/텍스트 입력 검토, 신고와 비공개 전환 정책 |

캐릭터의 `목표`는 단순 설명이 아니라 대화 행동의 방향이다. 예: “처음 해외여행을 온 학습자가 체크인에 성공하도록 기다려 주는 친절한 호텔 직원.” 캐릭터의 숨겨진 시스템 지침과 공개 프로필은 분리한다.

## 9. 상세 사용자 여정

### 9.1 첫 방문과 온보딩

1. 사용자는 홈에서 “영어로 체크인해 보기”라는 구체적 결과와 대표 캐릭터를 본다.
2. 회원가입 없이 데모 미션을 시작할 수 있다.
3. 시작 전에 수준, 학습 목적, 교정 강도를 최소 입력으로 선택한다.
4. 익명 진행은 같은 브라우저에서 유지한다.
5. 여러 기기 동기화, 캐릭터/미션 게시, 장기 진도 저장 시 계정 연결을 안내한다.

### 9.2 캐릭터 만들기

1. 기본 정보: 이름, 역할, 한 줄 소개를 입력한다.
2. 성격: 특성 태그와 자유 서술, 따뜻함/유머/엄격함 정도를 설정한다.
3. 목표: 캐릭터가 학습자를 어떻게 돕고 어떤 관계로 성장할지 정한다.
4. 대화 지침: 말투, 답변 길이, 주 사용 언어, 교정 방식, 금지 행동을 정한다.
5. 외형: 이미지 설명을 입력하고 AI 후보를 생성한다.
6. 후보를 선택하면 임시 자산이 Supabase 비공개 스토리지에 저장된다.
7. 미리보기에서 프로필 카드와 세 턴 샘플 대화를 확인한다.
8. 초안 저장 또는 게시한다. 게시 시 공개 데이터와 이미지가 정책 검사를 통과해야 한다.

AI 생성 실패 시 입력값과 초안은 유지하고 재시도할 수 있어야 한다. 이미지는 사용자가 선택하기 전 캐릭터 대표 이미지가 되지 않는다.

### 9.3 미션 만들기

1. 사용자는 “호텔에서 체크인하기” 같은 상황과 대상 수준을 입력한다.
2. AI가 학습 목표, 역할, 단계, 필수 표현, 예시 답변, 성공 조건을 제안한다.
3. 사용자는 단계별 내용을 편집하고 연결할 캐릭터를 선택한다.
4. 완료 보상 이미지와 해금 조건을 선택한다.
5. 학습 적합성 검사를 통해 너무 어려운 표현과 누락된 성공 조건을 수정한다.
6. 미리보기로 학습자 화면을 확인하고 초안 저장 또는 게시한다.

### 9.4 미션 수행

1. 상세 페이지에서 목표, 예상 시간, 보상, 캐릭터를 확인한다.
2. “미션 시작”을 누르면 캐릭터가 상황에 맞는 첫 문장으로 대화를 시작한다.
3. 사용자는 자유롭게 입력하거나 추천 답변/힌트를 선택한다.
4. 캐릭터 메시지 버블의 명시적인 음성 버튼을 누르면 TTS가 재생된다.
5. 각 턴 뒤 진행 목표가 갱신되고 필요한 경우 간단한 교정이 표시된다.
6. 모든 필수 목표를 충족하면 캐릭터가 자연스럽게 역할극을 마무리한다.
7. 결과에서 평가 근거와 복습 표현을 보고 보상 이미지를 해금한다.
8. 다시 하기 또는 다음 추천 미션으로 이동한다.

### 9.5 자유 대화

미션 없이 캐릭터와 대화할 수 있다. 일반 채팅의 스트리밍, 첨부, 편집, 재생성, 평가, 공유, 아티팩트 기능을 지원하되 학습자 설정에 따라 자연스러운 교정과 추천 표현을 제공한다. 자유 대화는 임의로 미션 성공이나 보상 해금을 만들지 않는다.

## 11. 학습 설계

### 11.1 수준 모델

- **Pre-A1:** 단어와 고정 표현, 한 문장 응답, 한국어 힌트 기본 노출
- **A1:** 짧은 현재형 문장, 핵심 질문/응답, 선택형 힌트
- **A2:** 이유·선호·과거 경험을 두세 문장으로 말하기, 영어 힌트 우선

프로필 수준은 개인화의 초기값일 뿐 고정된 능력 판정이 아니다. 미션별 난이도를 별도로 선택할 수 있다.

### 11.2 평가 축

| 축 | 질문 | 사용자 피드백 |
|---|---|---|
| 과업 달성 | 의도가 전달되고 목표를 완료했는가? | 완료 목표와 남은 목표 |
| 이해 가능성 | 상대가 추가 추론 없이 이해할 수 있는가? | 잘 전달된 핵심 |
| 문법 | 수준에 맞는 핵심 문법 오류가 있는가? | 원문과 짧은 수정 |
| 어휘·표현 | 상황에 자연스러운가? | 더 자연스러운 대안 |
| 상호작용 | 질문에 답하고 대화를 이어 갔는가? | 다음에 사용할 전략 |

평가는 학습 지원용이며 공인 시험 점수로 표현하지 않는다. 모든 점수에는 관찰 가능한 대화 근거를 포함한다.

### 11.3 교정 정책

- 기본은 대화를 계속한 뒤 한 줄 코칭을 제공하는 `gentle` 모드다.
- `immediate`는 중요한 오류를 바로 교정하고 다시 말할 기회를 준다.
- `summary`는 대화 중 개입을 최소화하고 종료 후 모아서 보여준다.
- 의미 전달에 영향이 없는 사소한 오류는 초급자의 흐름을 위해 매번 지적하지 않는다.
- 사용자는 한국어 설명의 양과 답변 길이를 설정할 수 있다.

### 11.4 추천 답변과 힌트

힌트는 세 단계다.

1. 의도 힌트: “예약자 이름을 말해 보세요.”
2. 핵심 표현: “I have a reservation under …”
3. 완성 문장: 사용자의 상황이 반영된 전체 예시

힌트 사용은 실패가 아니다. 결과에는 자립 완료와 도움을 받은 완료를 구분해 다음 학습을 추천한다.

## 12. 보상과 성장

- 미션 성공 시 지정된 캐릭터 이미지가 한 번만 해금된다.
- 동일 미션 재완료는 최고 평가와 학습 기록을 갱신하지만 같은 보상을 중복 발급하지 않는다.
- 보상 상세에는 획득한 미션과 날짜를 표시한다.
- 잠긴 이미지는 민감 내용을 노출하지 않는 블러 썸네일 또는 실루엣으로 표현한다.
- 관계 레벨은 대화량만이 아니라 미션 완료, 복습, 연속 학습을 반영한다.
- 조작적인 무한 알림, 손실 위협, 확률형 보상은 사용하지 않는다.

## 13. 발견과 공개 콘텐츠

공개 캐릭터와 미션은 검색 가능해야 하며 다음 신호로 정렬할 수 있다.

- 초급자 완료율과 재도전율
- 응답 평가와 신고율
- 최근 게시·업데이트
- 사용자 수준 및 관심 상황과의 관련성
- 콘텐츠 다양성

인기 순위가 안전성과 교육 적합성보다 우선하지 않는다. 공개 콘텐츠의 작성자, 사용 수준, 마지막 업데이트, AI 생성 여부를 표시한다.

## 14. 인증과 권한 경험

- 게스트는 공개 콘텐츠 탐색과 제한된 데모 대화를 할 수 있다.
- 익명 Supabase 사용자는 개인 진행을 저장할 수 있으나 공개 게시와 비용이 큰 생성에는 제한을 둔다.
- 회원은 장기 진도 동기화, 창작물 게시, 공유 링크 관리가 가능하다.
- 작성자만 초안을 읽고 수정할 수 있다.
- 공개 캐릭터/미션은 누구나 읽을 수 있지만 게시 버전만 런타임에서 사용한다.
- 관리자 권한은 신고 처리와 비공개 전환에 한정되며 감사 기록을 남긴다.

## 18. 안전, 신뢰, 프라이버시

### 18.1 캐릭터와 이미지

- 실존 인물 사칭, 비동의 성적 이미지, 미성년자 성적 콘텐츠를 금지한다.
- 공개 전 텍스트와 이미지 정책 검사를 거친다.
- AI 생성 이미지는 메타데이터와 UI에서 표시할 수 있게 보존한다.
- 잠긴 보상 원본은 공개 URL로 노출하지 않고 권한 확인 뒤 서명 URL을 발급한다.

### 18.2 대화

- 시스템 프롬프트와 내부 평가 기준을 클라이언트에 노출하지 않는다.
- 첨부파일 MIME, 크기, 개수를 제한하고 악성 파일을 신뢰하지 않는다.
- 캐릭터 지침보다 플랫폼 안전 정책과 학습자 보호 정책이 우선한다.
- 위기·의료·법률·금융과 같은 고위험 요청은 캐릭터 역할을 벗어나 적절한 한계를 안내한다.

### 18.3 데이터

- 대화, 프로필, 초안, 잠긴 자산은 기본적으로 비공개다.
- 공유 링크는 취소 가능하며 추측하기 어려운 토큰을 사용한다.
- 삭제는 사용자 기대와 법적 보존 요구를 구분해 설명한다.
- 서비스 역할 키와 AI 인증 정보는 브라우저 번들에 포함하지 않는다.

## 19. 기능 완료의 정의

하나의 요구사항은 다음 조건을 모두 만족할 때만 `검증됨`이다.

1. 비즈니스 요구사항 ID와 개발 컴포넌트/API/테이블이 연결되어 있다.
2. 성공, 빈 상태, 오류 또는 권한 거부 중 관련 경로가 구현되어 있다.
3. lint와 TypeScript 검사가 통과한다.
4. 필요한 데이터 계약 또는 로직 테스트가 통과한다.
5. mock 환경의 실제 브라우저에서 Playwright E2E가 사용자 결과를 확인한다.
6. Supabase RLS/Storage처럼 mock이 의미를 대체할 수 없는 경계는 별도 통합 검증 결과가 있다.
7. `03-validation` 문서에 PASS/FAIL/SKIP 증거가 기록되어 있다.

E2E가 없거나 실패하면 화면이 동작해 보여도 `구현됨, 미검증` 또는 `FAIL`로 기록한다.

## 22. 의사결정 및 가정

- 제품 작업명은 **Persona English**다. 이름 변경이 기술 식별자를 바꾸지 않도록 표시명과 내부 ID를 분리한다.
- 초기 학습자는 한국어를 설명 언어로 사용하는 Pre-A1~A2 성인이다.
- 브라우저 E2E에서는 AI와 원격 인프라를 결정적인 mock으로 대체한다.
- Supabase 권한은 mock E2E와 별도로 로컬 또는 연결된 Supabase에서 검증해야 한다.
- 개발 환경 AI는 조직 인프라인 GPT OAuth Proxy를 사용하고, 운영 환경은 직접 OpenAI API를 사용할 수 있다.
- 모델 이름과 공급자 URL은 환경 설정이며 제품 코드에 고정하지 않는다.
- 이미지와 음성 생성도 Vercel AI SDK의 모델 추상화를 통과한다.
