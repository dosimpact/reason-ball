# 연구 기반 실생활·직무 미션 교육과정 작성

- 날짜: 2026-09-21
- 배경: 사용자가 영어 완전 초보부터 심화까지 실제 필요한 미션을 연구 논문·튜터링 방법론에 근거해 JSON으로 작성하고 서브에이전트를 적극 활용하도록 요청했다. 작업 도중 비즈니스 미팅·개발자·디자이너·IT의 곤란한 문제를 먼저 제시하고 해결하는 방식을 명시했다.
- 시작 상태: root/4개 하위 catalog, 24세부 분류, 7개 CEFR 작성 코드와 호텔 체크인 `planned` 샘플 1개. 기존 DB 분류 migration·DB 테스트·stock·Supabase README 변경은 사용자 작업 상태로 보존했다.
- 탐색 제한: codebase-memory 스킬을 읽었지만 이 세션에는 graph 도구가 노출되지 않아 project/generation/coverage 확인을 할 수 없었다. 비코드 JSON·문서와 해당 scripts를 직접 읽는 fallback을 사용했다. 그래프 확인을 수행했다고 주장하지 않는다.

## 연구와 설계 결정

- 공식 CEFR와 과업 중심·간격·회상·교정 피드백·균형 있는 입력/출력 방법론, 과업 중심 메타분석의 방법론 비판 등7개 출처를 확인했다. 확인한 전문/초록 범위와 한계를 `research-sources.json`과 연구 문서에 기록했다.
- 수량은 학습효과의 최적값이 아니라 영역 coverage 기준이다. 기본24영역×7수준×4과업=672개, 이후 사용자 직무 요구4역할×5수준×4과업=80개를 추가해 총752개를 목표로 했다.
- 단순 이름·장소 치환으로 생성하지 않고 원본의 상황·역할·단계·전이를 개별 작성했다. 공통 지원/평가 정책은 순수 compiler가 조합한다.
- 완전 초보 진입10개와 관심 영역24개 경로, 직무4개 경로를 제공한다. 선수 관계는 필수 잠금이 아니라 추천으로 관리한다.
- C2는 원어민 보장이 아니다. 텍스트 자료는 듣기·발음 실증이나 문자·소리 기초 교육 전체를 대체하지 않는다. 1/3/7/21일 및 단계별 소요 시간은 운영 가설이다.
- 사용자 추가 요구를 `MISSION-PROBLEM-SOLVING-01`로 명시하고 직무 본문에 `caseBrief`를 추가한다. 문제→사실/미확인점→제약 내 협의→담당/기한/다음 행동 또는 에스컬레이션을 과업 결과로 삼는다.

- 연구 에이전트: 7개 근거 조사, 여행168개, 일과·취미28개, 관계168개 교차검토, 개발자/비즈니스 추가 사례.
- 교육과정 에이전트: 교육과정과 수량 설계, 관계168개 작성, 업무168개 교차검토, 디자인 추가 사례.
- 스키마 에이전트: 본문 스키마·validator와 회귀 검사, 업무168개, 일상/여행/일과336개 교차검토, IT 추가 사례.
- 부모: 일상140개, 공통 저작 계약·compiler·추천 경로·통합검증·stock/flow 동기화. 에이전트 간 파일 소유권을 나눠 기존 변경을 되돌리지 않았다.
- 감사 원장: `docs/research/mission-content-audit.md`, `mission-work-social-audit.md`, `mission-social-peer-audit.md`. 영어 오류, 예문에만 있던 정보, 가상 선택지·제스처, 역할·입력 불일치를 수정했다. AI 교차 편집이며 외부 사람 교사 검토로 기록하지 않는다.

## 1차 검증 — 기본672개 생성 시점

- `pnpm missions:compile`: 본문672개+하위catalog4개+추천경로1개=677파일 생성 성공.
- `pnpm missions:check`: 기본672개와24×7×4, 본문/목록 일치·경로·참조·추천 경로 재현성 PASS.
- `pnpm missions:test`: 당시18개 Node 회귀 PASS.
- 이후 사용자 직무 요구로 목표를752개로 변경하고 caseBrief·직무별 coverage·권한/에스컬레이션 검사와 compiler 회귀를 추가했다. 추가80개 작성·교차검토 및 최종 통합검증은 아래에 별도 기록한다. 1차 PASS를 추가80개 PASS로 확대하지 않는다.

## 영향받는 저량과 운영 경계

- business: MISSION-CATALOG-01, MISSION-CURRICULUM-01/02/03, MISSION-PROBLEM-SOLVING-01.
- system: authoring→pure compile→catalog/body/paths, strict caseBrief, 기본/직무 분리 coverage, 경로·키 불변성, 로컬 저작과 실행 계약의 구분.
- test: 원본 재현성·전체 coverage·내용 편집 감사와 미실행 AI/학습자 검증을 구분.
- 이번 콘텐츠 작업에서는 DB schema/migration/RLS/원격 데이터·앱 실행 코드를 변경하지 않았다. 원격 게시/importer·실제 AI 역할 수행·사람 교사 검토·학습자 효과 실험은 수행하지 않았다. 최종 로컬 상태는 `draft`다.
