# 2026-10-07 — PUSH-UI-SSOT: 구현 가이드를 기준 계약으로 정리

- 맥락: 사용자가 기존 25번 예제를 몰라도 가이드 자체가 SSOT여야 한다고 명시함.
- 결정: 가이드 문서 ID를 PUSH-UI-SSOT로 정의하고 독립적인 진행 UI 채팅 구현의 규범적 데이터/상태/이벤트/실행/검증 계약을 문서 안에 모두 둠. 단계 수는 서비스별 N으로 일반화하고 3단계는 설명용으로만 사용함.
- 변경: thread/turn/placeholder 정의, 입력과 UI payload 타입, metadata/ID 규칙, 초기화·보존 범위, 노드 성공/실패 분기, 메시지 상태 판정, 서버 최종 상태 확인, 설정 예시, UI 데이터와 렌더러의 책임, 변경 시 문서 우선 갱신 원칙을 명시함. 기존 예제 전용 식별자 및 소스 참조 없음.
- 영향 stock: business/system은 PUSH-UI-SSOT를 독립 구현의 기준 문서로 연결함. 기존 예제 구현 현황은 stock에 그대로 유지하며 예제의 런타임 계약/graph ID 변경을 뜻하지 않음.
- 검증: 필수 계약/소스 참조 없음/stock 링크와 git diff --check 확인. 문서 변경만 있으며 실행 가능한 완성 앱을 추가한 것이 아니므로 provider/browser 테스트는 재실행하지 않음.
- 상태: 완료. 기존 가이드 작성 및 독립화 flow를 보존하고 이 기록으로 기준 문서의 역할을 구체화함.
