# 청킹 전략

문서를 LLM 컨텍스트에 맞게 나누는 것.

## 옵션
1. **고정 크기** (500 tokens, 50 overlap) — 단순. 의미 경계 무시.
2. **의미 단위** — 마크다운 헤더, 코드 함수, 문장 단위.
3. **Parent-child** — 작은 청크로 검색, 큰 부모 청크를 LLM 컨텍스트로 주입. 권장.

## 임베딩 차원
- Titan v2: 1024 (또는 256/512 로 축소 가능)
- OpenAI text-embedding-3-large: 3072
- 차원이 클수록 품질 ↑ 그러나 저장/검색 비용 ↑

## RAG 안티패턴
- 너무 큰 청크 → 노이즈 증가, top-k 다양성 부족
- 너무 작은 청크 → 컨텍스트 단편화, 인용 신뢰도 ↓
