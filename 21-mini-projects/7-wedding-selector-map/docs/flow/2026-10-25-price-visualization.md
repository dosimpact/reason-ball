# 2026-10-25 가격 시각화 개선과 원본 열람 UI 제거

## 맥락

사용자가 가격 정보를 그래프로 더 쉽게 파악하도록 개선하고, 원본 자료를 확인하는 기능은 화면에서 빼달라고 요청했다. 원본 수집·표준 모델·근거 보존은 계속 사용하며 소비자에게 보여주는 가격 비교 경험을 바꾼다.

## 결정과 적용 범위

- VIS-001 목록: 현재 검색/필터 결과의 실제 가격 분포와 표본 수, 평균·중앙값을 제공한다. 다른 지표나 준비대행의 서로 다른 상품/산정 단위를 한 분포에 섞지 않는다.
- VIS-002 상세: 같은 홀·조건의 식대와 대관료로 비용 구성을 시각화하고, 하객 수별 보증 인원·인원 구간을 반영한 참고액 변화를 보여준다. 미확인 대관료는 무료로 표현하지 않는다.
- VIS-003 비교: 선택 업체의 공개비용을 가로 막대로 비교한다. 준비대행은 상품 분류와 1인/상품/패키지 산정 단위를 분리한다. 임의의 스드메 합계를 만들지 않는다.
- VIS-004 화면 단순화: 공시 페이지·원본 파일·원시 계약 문서·메타데이터·표준 모델 JSON 열기/다운로드, 셀/시트 근거 표시는 소비자 UI에서 제거한다. 비교 CSV는 소비자가 선택한 업체의 값·단위·조건을 내보내는 기능으로 유지하고 출처 URL 열은 제외한다.
- VIS-005 보존: 두 database 원본, 표준 모델, 원문 근거와 생성/검증 산출물은 삭제하지 않는다. 지도 출처 표시는 지도 라이선스 표시이므로 웨딩 공시 원본 열람 기능과 구분한다.

## 진행과 검증 상태

기존 stock과 구현을 읽고 소비자 화면의 원본 열람 링크·다운로드·셀 좌표·문구 위치를 확인했다. 목록/공통 가격 계산, 상세, 비교를 나누어 구현한다. 기존 정적 `client`의 원본 열람 설명과 모델 내부의 근거 보존 원칙은 별도 범위로 유지한다.

현재 이 기록의 최초 상태는 구현 진행 중이다. 정적 검사·가격 회귀·실제 브라우저 결과와 스크린샷은 구현 완료 후 같은 기록의 후속 항목에 추가한다. 이전 플랫폼 구현 이력의 원본 열람 검증은 당시 동작의 기록이며, 이번 UI의 완료 근거로 사용하지 않는다.

## 구현 완료

- 목록의 가격 인사이트: 식대/선택 하객 수 참고비용 전환, 실제8구간 분포, 평균·중앙값·중간50% 가격대, 표본 수, 구간 hover/키보드 조회와 접기. 준비대행은 상품×산정 단위 하나를 선택한 표본만 집계한다.
- 상세: 같은 홀/조건의 식대·대관 누적 막대, 실제 인원 간격을 사용하는 하객 수별 추이, 평균·중앙값·선택 업체 표시가 있는 식대 분포, 준비대행의 상품별 가격 범위. 인원 조건에 해당하지 않는 지점은 선을 끊고, 미확인 대관료는 미확인으로 유지한다. 추이 점의 호버/터치 영역을 세로 칼럼으로 넓혀 수치를 쉽게 읽게 했다.
- 비교함: 웨딩홀별 누적 비용 막대와 값·보증인원, 준비대행 상품×산정 단위별 독립 범위 막대. 기존 표는 그래프 아래에서 접고 펼친다. 준비대행만 비교할 때 하객 입력을 숨긴다.
- 원본 열람·원시 계약 문서·모델 JSON·셀/시트 근거와 출처 링크를 UI에서 제거했다. 가이드/로딩/빈 가격 문구도 원본 확인을 유도하지 않도록 변경했다. 비교 CSV는 남기고 출처 URL 열을 삭제했다.
- 소비자 API는 자료·출처 배열과 URL 및 셀 근거를 제거하며, 가격·조건·상품별 가격 profile은 유지한다. 내부 원본과 모델은 그대로 사용한다.

정적 검사: 전체 ESLint·TypeScript·Prettier와 운영 빌드 PASS. 테스트28개 PASS. 새 `getVenueCostBreakdown`은 참고액 계산과 같은 선택기를 공유하고, 서로 다른 홀/시즌의 식대·대관을 혼합하지 않는 회귀를 추가했다. 통계의0/미확인·최댓값 bin·동일금액, 소비자 응답의 원본 제거, 상품/단위별 코호트 분리도 검사한다.

운영 Chrome 1440×1000 및 390×844에서30개 브라우저 항목 PASS. JavaScript/콘솔 오류0건. 모바일 비교함은 뷰포트 변경 직후 전환 중인 프레임을 캡처한 것을 발견해, 모바일에서 비교함을 직접 연 뒤 화면 내 경계·제목·4개 그래프 그룹을 추가 확인했다(너비370px, x10px, y약29.5px, 높이약784.9px). 이미지로 최종 렌더링을 확인했다. 원본 데이터 전체 의미의 사람 검수나 실제 모바일 기기 Safari 검증을 뜻하지는 않는다.
