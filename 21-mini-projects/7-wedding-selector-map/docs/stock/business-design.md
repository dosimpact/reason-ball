# 오롯 Wedding Atlas 업무 설계

## WEB-001 목적과 자료 범위

소비자가 웨딩홀과 결혼준비대행 업체의 위치, 가격, 상품 구성, 계약 조건을 함께 살펴보고 합리적으로 후보를 좁히는 종합 비교 서비스다. 현재 사용자 앱은 [`app`](../../app/README.md)의 Next.js 웹이며, 기존 정적 `client`는 보존된 이전 구현이다.

수집 기준일은 2026-10-25다. `database/참가격_웨딩홀_업체별_공시원본`의 웨딩홀 게시글 338건과 연결된 기존·추가 공시와 `database/참가격_결혼준비대행_자료`의 준비대행 공시 108건을 모두 조회한다. 업체/공시 레코드는 총 446건이며 이 수치는 전국 모든 영업 업체의 수를 뜻하지 않는다. 공시 공개일·적용연도·수집일은 구별한다. 미래 날짜 등 원문 이상은 덮어쓰지 않고 확인 메모로 남긴다.

## WEB-002 탐색과 후보 관리

- 웨딩홀 / 스드메·플래닝 탭을 전환하고 업체명·주소·지역을 검색한다.
- 지역, 공개비용 상한, 가격 확인 가능 여부, 관심 업체를 함께 필터링한다. 웨딩홀의 하객 수를 바꾸면 참고 비용과 예산 필터에 반영한다.
- 최근 공시순, 공개비용 낮은순·높은순, 이름순으로 정렬한다. 미확인 가격은 가격 정렬의 마지막에 둔다.
- 목록은 24건씩 더 보며, 필터 결과는 지도에도 함께 반영한다. 검색어·지역·업체 종류를 URL로 복원한다.
- 관심 업체와 최대 3곳의 비교 후보는 브라우저에 저장한다. 저장소 사용이 불가능해도 현재 세션의 선택은 계속 동작한다.
- 모바일에서는 목록/지도를 전환하고 상세 패널·비교표를 작은 화면에서 탐색한다.

가격 미기재 업체도 기본 목록에 포함한다. 검색 결과가 없으면 조건 초기화를 제공한다. 광고·인기 평점이나 실재하지 않는 후기를 만들지 않는다.

## WEB-003 웨딩홀 가격 비교

기본 식대 지표는 대표 공시에서 해석 가능한 **성인 1인 기본 식대의 최저값**이다. 소인·추가 인원·옵션·할인액·인원 묶음 총액을 이 지표에 섞지 않는다. 이미지 등에서 숫자 확인이 어려운 값은 0원으로 대체하지 않는다. 대관료와 대관·장식 합계는 상세에서 구별한다.

하객 수를 이용하는 공개비용 참고액은 각 공시 조건별로 다음과 같이 계산한다.

```text
적용 인원 = max(선택 하객 수, 해당 조건의 공개 보증 인원)
참고액 = 해당 조건의 성인 기본 식대 × 적용 인원 + 해당 조건의 공개 대관료
```

공시 조건 하나 안에서 계산한 후보 중 최저 참고액을 사용한다. 서로 다른 시즌의 식대·대관 최저값을 따로 골라 더하지 않는다. 보증 인원 미기재 시 선택 하객 수를 사용하고, 대관료 미기재 시 식대만 계산했다는 범위를 알린다. 장식·선택 비용·미확인 필수 비용 등이 빠진 참고 합계이며 **확정 총액·현재 예약 견적이 아니다**. 상세의 홀별 조건과 실제 계약 견적을 함께 확인한다.

목록의 가격 분포는 현재 검색·필터 결과에서 확인 가능한 같은 가격 지표를 집계하며 표본 수·평균·중앙값을 함께 표시한다. 적용연도가 섞일 수 있으므로 현재 지역의 확정 시세로 표현하지 않는다. 상세 분포는 같은 지역·같은 적용연도·동일 이전 공시 상태의 실제 최저 식대 표본을 집계한다. 표본이 부족하면 비교 가능한 분포가 없음을 안내한다. 평균과의 차이를 할인율로 표현하지 않으며 정규분포를 가정하지 않는다.

상세의 비용 구성은 참고액 계산에 선택한 같은 홀·조건의 식대와 대관료를 구분해 토프다. 대관·장식 합계인 경우 해당 이름으로 표시하며 미확인 대관료를 무료로 표현하지 않는다. 하객 수별 변화 그래프는 각 인원에 적용되는 보증 인원·인원 구간을 다시 반영한 참고액이다. 그래프의 생략된 필수 비용과 참고 범위는 숫자 가격과 같은 기준으로 설명한다.

## WEB-004 지도

업체 마커의 가격 옆에는 주소에서 확인한 구 이름 배지를 표시한다. 구가 없는 주소에는 임의 배지를 만들지 않는다. 모든 이름표에 지역 배지를 유지한다.

MAP-FULL-001: 지도는 레일 옆 전체 화면 높이100dvh를 차지한다. 검색·목록은 왼쪽 부유 패널이며 상세는 같은 자리를 사용한다. 모바일 목록/지도 전환을 유지하고 지도 조작은 상단 패널에 가리지 않도록 하단 우측에 배치한다. 가격분포는 목록에서 기본 접힘이며 필요할 때 펼친다. 검색부터 키보드로 탐색할 수 있다. [UX 리뷰 및 검증](../flow/2026-10-26-full-map-ux-review.md).

Leaflet과 CARTO Positron 배경 지도로 업체를 탐색한다. 공개 주소를 지오코딩한 결과는 **업체·웨딩홀 이름을 윗줄, 가격을 작은 아랫줄**에 표시한 마커로 보여준다(MAP-LABEL-001). 긴 이름은 한 줄 말줄임으로 정리하고 마우스 올리기·키보드 포커스와 접근성 이름에서 전체 이름과 가격을 확인할 수 있다. 마커가 밀집하면 겹치는 이름표를 실제 좌표의 점으로 축약한다. 점의 툴팁과 클릭으로 업체를 확인한다. 선택한 업체는 이름·가격 마커를 우선 표시하고 강조한다.

좌표 미확인 업체는 **지역 대표점**으로 묶는다. 지역 대표점을 업체의 실제 건물 좌표로 표현하지 않는다. 범례에 주소 검색 좌표와 정확 위치 미확인 수를 구별한다.

지도와 목록의 업체를 선택하면 같은 상세 패널을 연다. 지도 확대·축소·현재 검색 결과에 맞추기를 제공한다. 상세에서는 네이버 지도의 업체명 검색 결과를 열 수 있다. 지오코딩 결과는 주소 검색 일치 결과이며 현장 방문이나 건물 입구를 보증하지 않는다. 외부 배경 지도 실패가 업체 목록·가격 비교를 중단시키지 않는다.

## WEB-005 상세·가격 조건

업체 상세는 위치·전화, 가격 수집 기준과 적용연도, 홀/상품별 가격, 보증 인원과 조건, 포함·추가 비용의 구분, 확인 메모를 보여준다. 가격 분포·비용 구성·하객 수에 따른 변화를 그래프로 살펴볼 수 있다. 소비자가 예약·계약 전에 알아야 하는 조건 설명은 유지한다.

원본 XLSX·TXT·MD·이미지·공시 페이지·메타데이터·표준 모델 JSON을 열거나 다운로드하는 기능은 소비자 화면에 제공하지 않는다. 원시 계약 문서 아코디언과 시트·셀 좌표도 노출하지 않는다. 원본과 해석 근거는 내부 표준 모델과 검증 자료로 계속 보존한다. 최신 영업 상태·예약 가능일·업체의 현재 제안 가격을 자동 확인하는 서비스는 아니다.

## WEB-006 검증

핵심 가격 로직·원본 참조·지도 좌표 구분의 자동 검증과 실제 브라우저 흐름 검증은 별도 증거로 남긴다. 브라우저 대상은 초기 렌더링, 지도 타일·마커, 검색, 복합 필터, 종류 전환, 정렬, 상세 지연 로드, 가격 분포·비용 구성·하객 변화 그래프, 관심 저장/새로고침, 비교·하객 변경·CSV, 원본 열람 UI 부재, 빈 결과, 모바일·키보드 흐름이다. 최신 검증 결과는 [가격 시각화 변경 이력](../flow/2026-10-25-price-visualization.md)을 따르며 [최초 플랫폼 구현 이력](../flow/2026-10-25-next-wedding-platform.md)은 당시 결과로 보존한다.

## WEB-007 결혼준비대행 가격

스튜디오·드레스·메이크업·패키지 등 해석 가능한 기본상품 금액과 적용 조건을 제공한다. 업체별 실제 패키지 가격과 개별 기본상품 가격을 별도 필드로 보관한다. 비교표는 스튜디오·드레스·메이크업·패키지별 기본가를 각각 보여주고 1인·상품·패키지 산정 단위를 구분한다. 개별 기본상품의 최저가를 스드메 전체 합계로 표시하거나 여러 업체의 개별 최저가를 더해 실재하는 패키지처럼 표현하지 않는다.

준비대행의 공개비용 정렬·예산 필터는 패키지 최저 공시가를 우선하고, 없으면 개별 기본상품 최저 공시가를 이용한다. 이 값들의 상품 구성은 서로 다르므로 카드의 기준 표시와 상세의 상품 조건을 확인해야 한다. 단순 가격순이 동일 상품의 가성비 순위를 뜻하지 않는다. 이미지·HWP·복잡한 옵션 혼합 등 해석되지 않은 가격도 원본 경로를 보존한다.

## WEB-008 비교함

최대 3곳을 나란히 보며 웨딩홀은 같은 하객 수로 비교한다. 식대, 대관료, 보증 인원, 계산에 적용한 인원, 계산 범위, 적용연도·공개일을 확인한다. 웨딩홀과 준비대행을 함께 담으면 서로 다른 표로 나눈다. 서로 다른 분류의 비용을 자동 합산하지 않는다. 웨딩홀은 같은 조건에서 선택한 식대·대관료의 가로 비용 구성 막대로 비교하고, 준비대행 그래프는 상품 분류·산정 단위를 분리한다.

CSV 비교표에는 원 단위 금액과 상품·산정 단위·비교 기준·주의 문구를 포함하며 원본/출처 URL은 제외한다. 미확인 금액은 빈 값으로 남긴다. 관심/비교는 로그인 없는 로컬 저장 기능이며 다른 기기 계정 동기화는 없다.

## WEB-009 지도 없는 가격표 페이지

검색 도구는 업체 종류·검색어·필터 버튼 한 줄로 제공한다. 지역·하객 수/상품 단위·예산·연도·가격 확인·저장 조건은 필터 모달에서 즉시 변경하며 지역은 체크박스로 여러 곳을 선택하며 지역 간에는 OR, 예산 등 다른 조건과는 AND로 결합한다. 검색창 아래에 지역·검색어·예산·연도·가격 확인·저장 조건을 개별 해제 가능한 태그로 표시한다. 태그는 가로 스크롤하며 비교 기준도 함께 표시한다. 지역 선택이 없으면 전국이다. 모바일 업체 종류는 선택 메뉴로 제공한다.

상단 소개·통계 영역은 표 위에 상시 표시하지 않는다. 표 머리글의 가격 요약 버튼으로 모달을 열어 현재 필터 결과의 업체 수·가격 확인 수·중앙값·최저 참고금액·계산 기준을 확인한다.

`/prices`는 지도 없이 여러 업체의 가격과 조건을 넓은 표로 훑어보는 독립 페이지다(TABLE-001). 기존 `/` 지도 탐색과 관심 저장·최대 3곳 비교 흐름을 유지하고, 내비게이션의 **가격표**에서 이동한다. 탐색·저장·비교 메뉴가 모두 별도 URL 페이지라는 의미는 아니다.

- 웨딩홀은 공통 하객 수를 기준으로 선택된 같은 홀·조건의 성인 식대, 대관료 또는 대관·장식 합계, 보증/계산 인원, 공개비용 참고액과 적용 조건을 함께 확인한다. 업체의 서로 다른 홀에서 가져온 각 최저값을 한 계산처럼 표시하지 않는다.
- 준비대행은 상품 분류와 산정 단위를 명시해 선택한다. 스튜디오·드레스·메이크업·패키지 및 1인/상품/패키지 단위가 다른 최저가를 동일 상품 가격이나 스드메 합계로 섞지 않는다.
- 업체명·지역 검색과 예산·적용연도·가격 확인·저장 필터, 열별 정렬, 페이지 이동을 제공한다. 미확인 금액은0으로 대체하지 않고 가격 정렬 방향과 관계없이 뒤에 둔다.
- 업체 이름과 표 머리글을 고정해 긴 표의 문맥을 유지하고, 모바일에서는 표 안에서 가로 스크롤한다. 현재 표의 결과 수와 페이지 범위를 함께 표시하며 한 페이지의 행 수를 선택한다.
- 행에서 관심 저장, 최대 3곳 비교 선택, 업체 상세를 연다. 저장·비교 목록은 지도 탐색과 같은 브라우저 상태를 공유한다.
- CSV는 현재 필터 결과 전체의 가격·단위·조건을 저장하며 현재 페이지에 표시한 일부 행에 한정하지 않는다. 원본/출처 URL을 포함하지 않고 미확인 금액을 빈 값으로 남긴다.

모바일·짧은 화면은 문서 세로 스크롤과 표 최소 높이를 확보한다. 모바일 업체명은 두 줄까지 표시하고 초기 가격열이 잘리지 않도록 고정열 폭을 조절한다.

초기 상태는 전국·웨딩홀·하객200명·공개비용 낮은순·20행이다. 준비대행 최초 진입은 가격 확인 업체 수가 가장 많은 상품×단위로 시작하며 명시한 URL 단위는 유지한다. 검색어·지역·종류·하객·상품 단위·예산·적용연도·가격 확인·저장 필터·정렬·행 수·페이지를 URL로 복원한다. 다른 필터를 적용해 현재 페이지 범위를 벗어나면 유효한 페이지로 조정한다.

가격표의 참고액도 WEB-003의 부분 합계 규칙과 WEB-007의 상품·단위 구분을 따른다. 가격 낮은순이 동일 상품의 가성비 순위나 예약 가능한 확정 견적을 뜻하지 않는다. 새 페이지의 구현·정적·브라우저 검증 상태는 [가격표 변경 이력](../flow/2026-10-26-price-table.md)을 따른다.

## MODEL-BIZ-001 공시 슈퍼셋 활용과 경계

[`packages/wedding-data-model`](../../packages/wedding-data-model/README.md)의 스키마 `0.1.0`을 원본·근거·업체·조건·가격·정책을 연결하는 기준으로 사용한다. 앱 파이프라인은 두 자료의 446건을 조회용 projection으로 만들고, 레코드별 스키마 형식의 공시 export를 생성한다. 원본 경로·해시, 해석된 금액·셀 근거·원문 조건, 주소·전화, 계약 취소 조항을 연결한다.

자동 해석 결과는 미검수 상태다. 미공개·무료·포함·문의 등을 구별하며 상품별 단위도 보존한다. 전체 원문의 모든 의미, 할인 관계·조건 엔진·취소 위약금 계산까지 이관한 상태는 아니다. [시스템 설계 MODEL-001–008](system-design.md#model-001-슈퍼셋-모델의-범위)에 구현 범위와 확장 경계를 명시한다.

## APP-LOCAL-001 독립 배포

사용자 앱은 앱 내부에 보관한 자료만으로 지도·가격표·상세·비교를 제공한다. 외부 원본 저장소 없이 배포 가능하며 원본 열람 UI는 추가하지 않는다. 가격과 조건 데이터는 이관 전446개 업체와 동일하게 유지한다. 갱신은 명시적인 원본 동기화 후 재생성한다.

## DESIGN-001 공통 색상

화이트와 웜 토프으로 따뜻한 린넨과 크림톤의 웨딩 분위기를 표현한다. 넓은 표면은 중립색이며 버튼·선택·배지에만 토프을 사용한다. 본문과 가격표 숫자는 짙은 중립색으로 표시한다. 선택 마커는 토프 배경/흰 글자, 일반 마커는 흰 배경/짙은 토프 글자다. Positron 배경에는 색상 필터를 적용하지 않는다.

## PRICE-ZERO-001 대관료 0원 조건 제외

소비자 가격 비교에서 대관료 최저값이 0원인 조건 전체(0~유료 범위 포함)를 제외한다. 업체와 원본은 보존한다. 서버 카탈로그의 `applyComparisonPolicy`가 동일 정책을 목록·상세에 적용하고 남은 기본 조건으로 식대 범위·대관료·보증 인원 요약을 재계산한다. 조건이 모두 제외되면 가격 미확인으로 유지한다. 대관료 미기재(null)는 기존 부분 합계 규칙을 유지한다. [변경 이력](../flow/2026-10-26-zero-rental-policy.md).

## EXPLORE-RANGE-001 탐색 가격 범위

탐색 > 조건 설정에서 대관료·1인 식대·선택 하객 수 참고비용의 최소/최대를 만원 단위로 입력한다. 빈칸은 제한 없음, 경계값은 포함, 세 조건은 AND로 적용한다. 대관료·식대는 업체별 최저 공시가이고 참고비용은 기존 같은 조건 합산 규칙을 따른다. 해당 가격 미확인 업체는 활성 범위에서 제외된다. 기본 하객 수는 200명이며 인원 변경 시 라벨과 계산이 함께 바뀐다. 초기화·업체 종류 변경 시 범위를 지운다.

## MAP-LIST-001 지도 범위 목록 연동

탐색 목록은 기본적으로 현재 지도 bounds 안의 실제 좌표 확인 업체만 표시한다. 이동·확대·축소 종료 및 크기 변경 시 갱신한다. 이동된 이름표나 지역 대표 좌표로 업체 위치를 추정하지 않는다. 목록 상단의 “현재 지도 범위만 보기”를 해제하면 위치 미확인 업체도 포함한 전체 검색 결과로 돌아간다. 지도 마커/자동 맞춤의 입력은 전체 검색 결과를 유지하여 목록 갱신으로 지도 범위가 재설정되는 순환을 방지한다. 목록 가격 분포와 결과 수는 같은 범위를 따른다.

## MAP-POSITRON-001 차분한 배경 지도

기본 배경은 CARTO Positron이며 CSS 색상 필터를 적용하지 않는다. `NEXT_PUBLIC_CARTO_BASEMAPS_KEY`를 빌드 전에 app/.env.local에 설정한다. 브라우저용 키는 빌드된 클라이언트에 포함되며 소스 저장소에는 커밋하지 않는다. OSM/CARTO 저작자 표시를 유지한다. 키 미설정 시 OSM 기본 지도, 타일 오류 시 기존 HOT 대체 지도를 사용한다.


### TABLE-CALM-001 가격표 강조 절제

가격표는 화이트·웜 그레이 표면과 중립 테두리를 사용한다. 검색창·요약 버튼·필터 태그의 상시 색상 강조를 줄이고 가격 본문은 짙은 중립색, 부가 문구는 보조색으로 구분한다. 주요 동작·선택·키보드 포커스는 구분 가능하게 유지한다. 가격표 전용 표면 토큰으로 지도 팔레트와 독립 조정한다.

### DESIGN-002 두 번째 메인

웜 토프 #806957을 유지하고 테라코타 #A65F4D를 두 번째 메인으로 사용한다. 저장 하트·비교 상태·상단 비교 버튼·대관 차트 계열에만 사용한다. 가격표 본문/배경/테두리는 기존 중립색을 유지한다. 토큰은 --orot-secondary, hover, soft, border이며 chart-secondary가 이를 참조한다.

## THEME-001 사용자 팔레트 선택

사이드 레일 위치의 테마 버튼에서 린넨 웨딩(기본 토프/테라코타), 펄 블루, 로즈우드, 모카 실크, 이브닝 웨딩 5가지를 즉시 적용한다. 모바일은 떠 있는 팔레트 버튼으로 제공한다. 초록 계열은 제외한다. 가격표의 절제된 중립 표면과 Positron 지도 배경은 유지한다. `orot:theme` localStorage에 검증된 테마 ID를 저장하고 HTML data-theme의 CSS 토큰으로 앱 전역 및 포털 모달에 적용한다. 초기 인라인 스크립트가 화면 표시 전에 저장값을 적용한다. 저장소 실패 시 현재 세션 선택은 유지한다. 앱 아이콘은 기본 브랜드 색상을 유지한다.
