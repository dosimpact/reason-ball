# 2026-10-01 사진 재분석·고양이 UX 개선

## 배경과 범위
사용자는 보존한 다섯 장의 사진을 다시 분석하고 서브에이전트 조사에 근거해 UX를 개선하도록 요청했다. 후속 요청으로 캐릭터를 고양이로 바꾼다. 원작의 개미 사진은 참고 자료로 유지하며 현재 제품 표현은 Cat Atelier로 변경한다. 엔진 규칙, 3난이도×100레벨, 5슬롯, 웹·React Native 실행 범위는 유지한다.

UI/사진 감사, 상호작용 감사, Canvas 표현 작업을 병렬로 분담했다. 감사는 보존 사진, 이전 모바일 스크린샷, 실제 컴포넌트·엔진 소스를 비교했다. 원본 사진의 문구나 캐릭터를 새 게임 자산으로 복제하지 않는다.

이전 [모바일 화면](evidence/web-mobile.png)은 다음 상자 수량과 `BOXES` 표기가 겹치고, 작은 캐릭터와 낮은 대비로 운반 상태를 파악하기 어려웠다. 모바일에서 주요 설명을 숨기면서 첫 진입 즉시 타이머가 시작되던 점도 개선 대상으로 선정했다. 각 열 맨 위 픽셀만 수집하는 규칙은 사진으로 확정한 원작 규칙이 아니라 기존 프로젝트 계약이다.

## 수용한 변경과 이유
- UX-02: 첫 성공 배치 전에는 제한시간을 시작하지 않아 그림과 큐를 읽을 시간을 준다. 도움말 정지와 수동 정지를 분리해 닫은 뒤 사용자의 이전 정지 선택을 보존한다.
- UX-03: 현재 상자와 다음 두 상자의 색·수량을 독립된 줄로 표시한다. 어두운 숫자와 색상 이름, 빈자리 수·작업 상태, 최소 44px 주요 터치 영역으로 모바일 조작성을 높인다.
- UX-04: 고양이의 크림색 얼굴, 삼각 귀, 수염, 꼬리, 발과 색상 몸통을 Canvas에서 그린다. 같은 색 블록을 집으로 운반하고 도착 시 축소·사라진다. 동작 줄이기 설정에서는 발 움직임과 도착 효과를 생략한다. 노출 표시에는 엔진의 `exposedIds`를 그대로 사용해 오해를 줄인다.
- UX-05: 이전 최소 ID 활성 상자가 색 대기 중이면 움직이는 개체가 전혀 없어도 힌트가 기다리라고만 했던 문제를 수정한다. 이때 노출 색과 일치하는 앞 상자를 추천한다. 추천 가능한 상자가 없으면 보상 광고를 요청하지 않는다. 광고 대기 중 게임을 정지해 보상 후 추천 대상이 변하지 않게 한다.
- COMPAT-01: 내부 `Ant` 타입과 `ants` 필드, 패키지명·저장 키·브리지·네이티브 식별자를 유지한다. 표시 이름과 캐릭터 변경을 불필요한 저장 데이터·설치 ID 변경으로 확대하지 않는다.

## 회귀 재현
힌트 감사에서 다음 순서로 실제 엔진을 진행하면 활성 상자가 남고 이동 개체는 0마리이며 빈 슬롯이 있지만, 기존 힌트가 null을 반환했다.

```ts
let state = createGame(2, "hard");
for (const lane of [2, 1, 2, 0, 1, 1, 1, 2, 2, 2, 1, 2, 2, 0]) {
  state = tickGame(deployBox(state, lane), 2000);
}
```

이 상태의 앞 큐에는 수집 가능한 violet이 있다. 새 회귀 검증은 이동 개체 없음·빈 슬롯 있음·노출 색 일치를 확인하고 실제 진행 가능한 힌트가 반환되는지 확인한다. 임의 선택 이후 모든 상태의 완주를 보장한다고 확대 해석하지 않는다.

## 검증·후속 상태
통합 검증 대기. 이 기록은 수용한 설계와 변경 근거를 기록하며 새 테스트의 통과를 주장하지 않는다. 루트 작업자가 최종 코드에서 TypeScript·ESLint/FSD·엔진 회귀·광고 브리지·production build·브라우저 시나리오와 화면을 검증한 뒤 결과를 추가한다.

필수 시나리오는 320px/390px/짧은 화면 큐 겹침·터치 영역, 첫 배치 전후 시간, 정지 상태에서 도움말 열기/닫기, 24마리 고양이 운반과 집 도착, reduced-motion, 슬롯 가득 참, 힌트 회귀, 추천 불가 광고 미요청, 광고 완료/실패/취소 후 정지 복원이다. 모바일 내장 HTML은 다시 생성하고 네이티브 실행 여부는 별도로 명시한다. 기존 iOS 전체 Xcode 부재와 운영 광고 설정 한계는 이번 웹 UX 변경만으로 해소되지 않는다.

기존 [초기 설계](2026-10-01-initial-design.md), [검증](2026-10-01-validation.md), [모바일 검증](2026-10-01-mobile-validation.md)은 당시 기록으로 보존한다.


## 최종 통합 검증
- TypeScript 웹·모바일, ESLint/FSD, Prettier, production build PASS.
- 게임·저장 단위 22 PASS (300레벨 해법 및 힌트 회귀 포함), 모바일 광고/브리지 mock 8 PASS.
- 브라우저 전체 실행: 15 PASS / 1 FAIL / 8 중복 SKIP. 실패는 desktop hard100 보드 하단이 720px 경계를 4px 초과한 화면 회귀였다. 짧은 desktop canvas를 224px로 조정한 뒤 해당 화면 검사를 desktop/mobile/small-mobile 모두 재실행해 3 PASS. 수정한 광고 힌트 시나리오도 별도 1 PASS. 합산 고유 시나리오 16개 통과이며 마지막 전체 실행이 단일 green run이었다고 주장하지 않는다.
- 첫 선택 전 타이머 정지, 첫 선택 후 진행, 도움말 후 수동 정지, 레벨 완주/저장, 실패/재시작, 추천 불가 상태의 광고 미요청, earned/denied/wrong-ID 응답을 확인했다.
- 390×844에서는 보드·선택·힌트·재시작이 화면 안에 들어온다. 320×640 및 360×640은 세로 스크롤을 허용하며 가로 넘침 없이 버튼 최소44px, 큐54px를 유지한다.
- [모바일 고양이 운반](evidence/cat-ux-mobile.png), [데스크톱](evidence/cat-ux-desktop.png), [320px 전체 화면](evidence/cat-ux-small.png)을 직접 확인했다.
- 모바일 내장 HTML 재생성 PASS (223.41 kB, gzip71.44 kB). iOS/Android JS bundle export PASS. 이번 고양이 변경 후 native APK 재설치 및 실제 광고 재노출은 수행하지 않았다. 이전 native/광고 실행 결과는 이전 버전 증거다.
- 24마리 상한과 reduced-motion 분기는 유지했다. 이번 변경의 최대 부하 프레임 성능 및 reduced-motion 시각 검증은 별도 미수행이며 모든 기기60fps를 주장하지 않는다.
