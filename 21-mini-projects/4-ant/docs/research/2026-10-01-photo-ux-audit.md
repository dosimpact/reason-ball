# 사진 5장 재분석 · 게임 UX 개선 제안

분석일: 2026-10-01. 원본 5장과 기존 웹 모바일·데스크톱 검증 캡처를 직접 열어 비교했다. 이 문서는 개선 전 증거와 제안이며, 적용·검증 결과를 주장하지 않는다.

참조 게임은 사진 01에서 접시가 화면 너비의 약 92%, 높이의 약 38%를 차지한다. 사진 05의 구멍과 상자는 접시 밖에 있어 개미의 작업 동선이 장면으로 읽힌다. 사진 수치의 단순 복제보다는 이 정보 위계가 중요하다.

## 기존 구현 캡처의 차이

비교 근거: [모바일](../flow/evidence/web-mobile.png), [데스크톱](../flow/evidence/web-desktop.png), `src/widgets/game/index.tsx`, `renderer.ts`.

- 모바일 390px 캡처에서 흰 접시는 약 330px 폭이고, 세로로 긴 로켓 그림은 약 145px 폭으로 표시된다. 레퍼런스의 새와 현재 로켓은 종횡비가 달라 폭만으로 크기 결함을 단정할 수 없다. 다만 장식 여백, 별도 브랜드 영역, 도움 패널 때문에 게임 장면에 할당된 면적은 개선 가능하다.
- 구멍과 5개 슬롯이 흰 접시 안에 묶여 있어 그림의 공간과 상자 조작 공간의 구분이 약하다. 출발 상자→픽셀→구멍의 동작을 더 잘 읽게 하는 분리가 필요하다.
- 대기열 선두는 넓고 낮은 버튼이다. 다음 상자는 겹친 띠로 보이고 세 번째 상자 위에 `1 · 18 BOXES` 같은 설명이 겹친다. 숫자는 상자 수집량과 대기 상자 수를 혼동하기 쉽다.
- `+` 슬롯은 버튼처럼 보이지만 클릭 기능이 없는 `div`다. 실제 조작은 아래 대기열이며 자동으로 첫 빈 슬롯에 배치된다.
- 개미 몸체와 운반 블록은 코드상 작은 고정 크기다. 활동이 있는 화면에서 픽셀보다 작은 개미가 많아지면 선택 결과를 추적하기 어렵다. 시작 캡처에는 활동이 없어 실제 이동 가시성은 브라우저로 재검증해야 한다.
- 모바일에서는 진행률이 사라지고, 잠깐 설명은 작은 상태 문구에만 담긴다. 전체 도움말은 첫 행동을 분리하지 않은 긴 문장이다.

## 우선순위와 수용 기준

### UX-R01 · 조작 순서를 읽을 수 있는 플레이 화면

그림 영역, 구멍이 있는 운반 공간, 5개 활성 도크, 3열 대기열을 위에서 아래로 구분한다. 헤더는 레벨·시간·속도·도움·일시정지를 우선하고 장식 문구는 줄인다. 남은 블록 또는 진행률은 모든 화면에서 보이게 한다.

- 360×800, 390×844에서 5슬롯과 3개 선두 상자가 스크롤 없이 모두 보인다.
- 모바일 게임 면적은 가용 너비의 90% 이상을 사용한다. 실제 화면 높이에 따라 그림을 축소하며 주요 버튼을 잘라내지 않는다.
- 도안 종횡비를 보존하고 구멍/상자와 겹치지 않는다. 출발 위치는 실제 5개 도크의 중심과 일치한다.
- 핵심 터치 컨트롤은 최소 44×44 CSS px를 확보한다.

### UX-R02 · 지금 선택할 상자와 앞으로 올 상자의 구별

선두 상자는 큼직한 입체 상자 + 큰 수집량, 뒤 2개는 각각 색과 숫자가 읽히는 별도 줄로 만든다. 선두만 버튼이며 뒤 상자는 미리보기임을 드러낸다. 대기열 총량/키보드 번호는 상자 영역 밖에 놓는다.

- 3열 모두 선두·다음·그다음의 수량이 다른 텍스트와 겹치지 않는다.
- 모바일 선두 버튼 최소 44px 높이, 선두 수량 20px 이상, 미리보기 수량 12px 이상.
- 빈 도크는 비활성 자리처럼, 배치된 도크는 해당 색 상자처럼 보인다. 슬롯의 `+`를 누르는 잘못된 기대를 유발하지 않는다.
- 큐 선택→첫 빈 슬롯 배치→다음 상자 전진은 게임 상태 그대로 반영되며 이동 중 중복 배치가 없어야 한다.

### UX-R03 · 규칙과 첫 행동을 상황에 맞게 안내

첫 화면의 긴 설명은 한 행동 중심의 짧은 안내로 바꾸거나 보조한다. 예: “아래 맨 앞 상자를 선택하면 빈 자리에 놓여요.” 첫 배치 뒤에는 “같은 색의 맨 위 블록을 가져와요.”로 설명한다. 도움말은 여전히 다시 열 수 있어야 한다.

- 실제 구현 규칙인 **각 열의 맨 위 픽셀**을 정확히 설명한다. “바깥쪽 아무 블록”으로 바꾸지 않는다.
- 안내가 3개 선두 선택 버튼을 가리지 않는다. 처음부터 퍼즐의 정답을 상시 노출하지 않는다.
- 일시정지·가득 찬 슬롯·진행 불가 상태가 서로 다른 메시지로 구별된다.
- 안내·성공 모달의 초점 관리와 키보드 조작을 유지한다.

### UX-R04 · 운반을 보는 재미와 피드백

픽셀의 윗면/옆면과 작은 그림자로 블록감을 높이고, 개미는 몸체·더듬이·색이 인지되는 크기로 그린다. 돌아오는 개미가 작은 블록을 들고 있다는 차이를 명확히 한다. 구멍 도착 또는 도크 소진의 짧은 시각 피드백은 저장된 상태에 맞춰 제한적으로 적용한다.

- 운반 중 화면 캡처에서 개미 몸체와 들고 있는 블록을 구분할 수 있다.
- 그림·개미·구멍은 동일 Canvas 좌표계로 정렬한다. Canvas 외부 도크에 맞춘 출발점 확인이 필요하다.
- 동시 개미 상한24, DPR 상한2, 엔진 tick/React 갱신 분리를 유지한다.
- reduce-motion에서는 반복 장식/입자 효과를 줄인다. 추가 DOM 노드를 개미마다 만들지 않는다.
- 어려움100에서 프레임 간격과 long-frame을 이전 기준과 비교한다. 한 기기의 수치를 보편적60fps 보장으로 표현하지 않는다.

### UX-R05 · 결과와 다음 행동의 우선순위

성공 화면에는 완료 레벨과 수집한 블록 수, 눈에 띄는 다음 레벨 버튼을 둔다. 재시작은 보조 행동이다. 실패 때에는 시간 초과/슬롯 막힘의 실제 원인을 구별한다. 현재 없는 재화·광고 보상은 만들지 않는다.

- 성공 화면에서 어떤 레벨을 완료했는지와 다음 행동을 즉시 확인할 수 있다.
- 광고 힌트는 선택형이며 SDK 보상 이벤트 이후 지급한다. UX 정리 때문에 광고 동의/보상 계약을 바꾸지 않는다.

## 구현 경계와 검증 순서

게임 엔진과 생성 규칙을 유지하고 UI/Canvas 표현을 우선 개선한다. React DOM은 조작부, Canvas는 픽셀과 개미를 담당한다. FSD 의존 방향과 SLAP을 유지한다. 새 그림·로고를 위해 원작 자산을 재사용하지 않는다.

1. 초기 플레이와 첫 배치를 모바일·데스크톱에서 직접 확인한다.
2. 3열 선택, 5슬롯 포화, 개미 운반, 일시정지, 힌트, 승리/실패를 확인한다.
3. 짧은 모바일 높이와 가로 화면에서 스크롤/겹침/터치 영역을 확인한다.
4. 최대 난이도 성능과 기존 게임/광고 테스트를 재실행한다.
5. 적용된 결정만 stock에 반영하고 날짜가 있는 flow에 전후 증거와 미검증 범위를 남긴다.

## 사용자 추가 결정: 고양이 캐릭터

원본 사진의 운반 개미 분석은 비교 증거로 유지한다. 이번 개선에서 사용자가 운반 캐릭터를 고양이로 변경하도록 요청했으므로, UI 이름은 CAT ATELIER / 고양이 작업실로 바꾸고 UX-R04의 가시성 기준은 고양이와 들고 있는 블록에 적용한다. 색·운반·슬롯·큐 규칙은 유지한다. 사진에서 관찰된 사실과 새 제품 결정을 혼동하지 않는다.
