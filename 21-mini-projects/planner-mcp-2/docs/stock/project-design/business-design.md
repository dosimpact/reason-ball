# 비즈니스 설계

상태: 합의 사항과 첫 핵심 구현 반영. [원본 요구사항](../../../master-requirement.md)을 바탕으로 작성합니다.

## 목적과 범위

프로젝트 설계를 AI 구현·1차 검증과 사람의 최종 확인으로 연결합니다. 첫 구현은 로컬 프로젝트·템플릿·문서·정형 체크리스트·MCP/UI에 집중합니다. 구현 기본값과 범위는 [시스템 설계](../tech-shared/system-design.md)를 따릅니다.

## 사용자 흐름

사람이 설계와 완료 조건을 정의하면 AI가 구현과 1차 검증을 수행합니다. 사람은 Storybook·Bruno·브라우저 등에서 최종 검증하고 Planner UI의 체크리스트에 확인 결과를 반영합니다. 수정은 Codex CLI를 통해 AI에게 요청합니다.

## 요구사항과 업무 규칙

- REQ-001 — 설계 Overview: 트리 항목을 선택하면 비즈니스 스펙(What)과 설계 내용(How to)을 간단히 표시합니다. 연결 가능한 검증 문서가 있으면 검증 방법도 확인할 수 있도록 연결합니다. 검증 문서 연결은 필수가 아닙니다.

- REQ-002 — Overview 작성·편집: Planner MCP가 연결된 Codex CLI의 AI가 MCP를 통해 What·How to 요약을 작성합니다. 사람은 필요할 때 UI에서 직접 수정할 수 있습니다. AI도 최신 내용을 읽고 사람이 수정한 내용을 다시 변경할 수 있으며 별도 확인은 필수가 아닙니다.

- REQ-003 — Overview 구성: 중요한 비즈니스 흐름을 자유로운 트리로 표현합니다. 고정된 항목 종류나 계층을 강제하지 않으며 사람이 큰 틀에서 구현 흐름을 이해하도록 합니다.
- REQ-004 — 구현 시작·범위: Codex CLI에서 “구현해줘”라고 지시하면 AI가 MCP로 설계 문서를 조회하고 이미 설계된 범위만 먼저 구현·1차 검증합니다. 별도의 UI 설계 완료 체크는 시작 조건이 아닙니다.
- REQ-005 — 최종 검증: AI가 사람의 최종 검증 체크리스트를 작성하고, 사람이 직접 검증한 뒤 UI에서 체크합니다.
- REQ-006 — 설계 변경: 검증 완료된 기능의 설계가 변경되면 해당 기능은 `reopen` 상태가 됩니다. AI가 영향받은 검증 항목만 체크 해제하며 나머지는 유지합니다. MCP는 관련 설계·검증 문서와 체크리스트 조회, 특정 항목의 선택적 체크 해제를 지원해야 합니다.

- REQ-007 — AI 검증 결과: 설계-검증 문서의 체크리스트에서 항목별 AI 검증 결과와 사람의 최종 확인을 별도로 표시합니다. AI의 1차 검증 결과 기록은 해당 설계-검증 문서의 자식 문서로 추가하고 부모에서 조회할 수 있도록 연결합니다. 재검증 시에는 새 결과 자식 문서를 추가하지 않고 기존 결과 문서를 갱신합니다.
- REQ-008 — 템플릿 인스턴스: 생성된 문서는 원본 템플릿이 변경되어도 생성 시점의 템플릿 기준을 유지합니다. 문서 본문·진행 상태의 편집은 가능하며, 원본 템플릿 변경을 기존 문서에 자동 반영하지 않습니다.

- REQ-009 — 정형 공용부: 문서 메타 정보와 체크리스트는 Markdown 본문과 분리된 정형 데이터로 관리하며 UI·REST API·MCP에서 항목 단위로 조회·수정합니다.

## 도메인 기능 구분 (DEC-001)

| 도메인 기능 | 식별자 | 책임 |
| --- | --- | --- |
| 프로젝트 관리 | `project-management` | 프로젝트 CRUD, 설계·구현·검증 흐름과 노드 관리 |
| 템플릿 관리 | `template-management` | 문서 양식, 기본 체크리스트, 예시, AI 작성 지침 관리·조회 |
| 문서 관리 | `document-management` | 템플릿 인스턴스 생성, 본문 편집, index·부모·자식 관계, Overview 관리 |
| 진행·검증 관리 | `progress-verification` | 정형 체크리스트, AI 검증 결과, 사람 확인 상태, 선택적 reopen 관리 |
| AI 작업 안내 | `ai-workflow` | 작업 규칙, 문서 탐색 방법, 구현·검증 절차 제공 |

## 미정 사항

현재까지 기록한 미정 사항은 합의에 반영했습니다. 추가 세부 사항은 후속 설계에서 정합니다.

## AI MCP Interface 안내

- REQ-010 — sidebar 하단 버튼으로 도구 안내 페이지에 이동합니다. 현재 MCP 도구의 설명과 입력 스펙은 라이브러리를 통해 실제 등록 정의에서 자동 생성합니다. 검색과 필수·선택 파라미터 확인을 지원합니다.

## 단계 흐름 배치

- REQ-011 — React Flow의 기본 단계 흐름은 설계 → 구현 → 검증 가로 배치입니다. 사용자는 노드를 드래그하여 위치를 옮길 수 있습니다. 이동 위치는 저장하여 새로고침 후에도 유지합니다.

- 사람 확인은 AI 검증보다 먼저 수행할 수 있습니다. AI 결과와 사람 확인을 별도로 표시·관리합니다.

## Frontend UX 개편

- 프로젝트 진입 시 설계 index를 열고 index 상단의 하위 문서 카탈로그에서 생성·탐색합니다. 하위 문서 만들기는 부모와 단계를 자동 지정하고 생성 창에 위치를 표시합니다.
- 프로젝트·문서 검색, 단계 탭, 계층형 문서 목록, 부모 문서로 돌아가기를 제공합니다. 편집 중 다른 문서/프로젝트/화면으로 이동할 때 미저장 변경을 확인합니다.
- GitHub 스타일의 중립 배경·파란 탐색 강조·초록 주요 작업 색상과 shadcn 컴포넌트를 사용합니다.

- 주요 메뉴는 독립 URL을 갖습니다: 작업 공간 `/`, 템플릿 관리 `/templates`, AI 작업 안내 `/ai-workflow`. 주소 공유·직접 접속·새로고침·브라우저 이력 이동에서도 해당 화면을 표시합니다.

## 문서·템플릿 확장 기능 (REQ-012, 구현)

- 문서 템플릿은 확장 기능 목록(extension list)을 가집니다.
- 첫 확장 종류는 **React Flow Diagram View**입니다. 문서에 React Flow 다이어그램을 첨부하며, 문서 관리 화면에서 추가할 수 있습니다.
- 사용자는 문서에서 첨부 다이어그램의 렌더링 결과를 확인합니다. AI도 MCP 인터페이스로 확장 데이터를 작성·수정할 수 있습니다.
- 기존 프로젝트 단계·하위 문서 트리와 별개로, 개별 문서 안의 설계 내용을 표현하는 다이어그램입니다.
- 상세 설계: [문서 관리](../document-management/INDEX.md), [템플릿 관리](../template-management/INDEX.md).

## Notion 스타일 문서 작성

- 사람은 문서 본문과 템플릿 본문·예시·AI 지침을 블록 서식 편집기로 작성합니다. `/`로 블록을 선택하고 제목·목록·표·코드 등으로 내용을 구성합니다.
- 목록의 `→`(Tab)는 들여쓰기, `←`(Shift+Tab)는 내어쓰기입니다. Markdown 원문과 렌더링 미리보기를 전환할 수 있습니다.
- 저장한 내용은 기존 Markdown 계약을 유지하여 AI MCP와 공유합니다. 상세 동작은 [문서 관리](../document-management/INDEX.md)의 편집 규칙을 따릅니다.

## CodeWeave (CW-01)

코드 흐름을 들여쓰기·방향·자유 Prefix·레이어·주석으로 정리한다. `(+)`/`(-)`는 추가/삭제 예정의 As-Is/To-Be 표시이며 코드 구현 상태는 추적하지 않는다. 첫 제품 범위는 컴파일·트리 접기/펼치기·라인 정보·MCP 탐색/수정이다. 이번 단계는 npm 분리를 고려한 core 우선 구현이며 화면·MCP 연결은 후속이다. [상세 설계](../codeweave/INDEX.md).

- 문서·템플릿의 두 번째 확장 종류는 CodeWeave입니다. 코드 흐름 원문을 작성하면 계층 트리·변경 표시·주석을 확인할 수 있고, AI는 MCP로 흐름을 탐색하거나 라인 속성을 수정합니다. React Flow와 여러 CodeWeave 확장을 함께 첨부할 수 있습니다.
