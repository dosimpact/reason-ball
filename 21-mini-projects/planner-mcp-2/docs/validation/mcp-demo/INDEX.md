## 실행

저장소 루트에서 실행합니다.

    pnpm --filter planner-mcp-2 test:mcp-demo

기본 대상은 http://dodonet.iptime.org:14000/mcp 입니다. 다른 소유 서버를 시험할 때는 PLANNER_MCP_URL로 MCP endpoint를 지정합니다.

매 실행은 **보존할 새 데모 프로젝트 하나와 삭제할 임시 프로젝트 하나**를 생성합니다. 기존 프로젝트는 읽기만 합니다. 새 데모에는 설계·기존 구현 설명·검증 문서와 정형 체크리스트를 남깁니다. 반복 실행 시 데모도 하나씩 추가되므로 자동 회귀 테스트의 기본 test 명령에는 포함하지 않습니다.

제품 데이터 조회·변경은 MCP SDK tools/call만 사용합니다. SQLite 직접 수정, REST, 브라우저 데이터 입력, 사람 확인 true 설정은 하지 않습니다. 로컬 파일 작업은 요구사항 읽기, 실행기 작성, 검증 증거 기록에 한정합니다.

## 결과 해석

- PASS: MCP 응답과 재조회 결과가 해당 assertion을 만족함.
- FAIL: assertion 실패. 문서의 AI 결과도 failed로 기록.
- MANUAL: MCP로 수행할 수 없는 사람/UI 검증. AI skipped, 사람 미확인으로 기록.
- 27개 요구사항 그룹에 케이스를 연결했지만, 그것만으로 모든 요구사항이 충족되었다는 뜻은 아닙니다.
- M06은 snapshot 생성·인스턴스 수정의 독립성을 검사합니다. 원본 템플릿 수정/삭제 후 보존은 H03입니다.
- M14는 선택 항목의 AI 결과 초기화를 검사합니다. verified 변경·사람 true 체크 보존은 H08입니다.
- M39는 연결 재생성 후 저장 결과를 검사합니다. 서버 재시작·SSE 화면 반영은 H12입니다.
- 구현 문서는 **기존 Planner MCP 2 구현**과 이번 실행기를 설명합니다. 별도 제품의 구현 완료를 주장하지 않습니다.

호출 원문은 test-results/mcp-demo/<run-id>/calls.jsonl에 저장하고 Git에서 제외합니다. results.md에는 도구별 호출 통계와 원문 해시를 남깁니다. M02/M41처럼 사전 응답을 검사하는 케이스는 누적 증거 범위를 사용합니다.

중단 시 manifest.json의 demoId와 상태를 확인하세요. 소유 임시 프로젝트는 finally에서 정리하고, 부분 작성된 데모는 조사할 수 있도록 보존합니다. 재실행은 이어쓰기가 아니라 새 데모 생성입니다.
