[제품의 전체 흐름]
  - 사람은 설계와 완료 조건을 정의하고, AI가 구현 및 1차 검증을 수행한다. 최종 검증은 사람이 Storybook, Bruno, 브라우저 등에서 직접 확인한다.
  - AI 작업 시작은 Codex CLI에서 “구현해줘”라고 지시하면 충분하다. 별도의 UI 설계 완료 체크를 시작 조건으로 요구하지 않는다. AI는 MCP로 설계 관련 문서를 가져와 Planner MCP 규칙에 따라 이미 설계된 범위만 먼저 구현하고 1차 검증한다. (REQ-004)
  - 'Planner mcp'의 역할은 문서 카탈로그 관리, 상태 관리, UI View, SQLite 관리이다.
  - ‘사람 검증' 화면: 최종 검증 체크리스트는 AI가 작성하고, 사람이 직접 검증한 뒤 서비스 UI에서 체크한다. (REQ-005)
  - ‘수정 요청 → 재검증’: 수정이 필요한 부분은 codex-cli를 통해서 ai에게 요청한다.
  - 검증이 끝난 기능의 설계가 변경되면 해당 기능은 `reopen` 상태가 된다. AI가 영향받은 검증 항목만 체크 해제하고 나머지 체크는 유지한다. 이를 위해 MCP는 설계·검증 문서와 체크리스트를 조회하고 특정 항목의 체크를 선택적으로 해제할 수 있는 인터페이스를 제공해야 한다. (REQ-006)

[CodeWeave 요구사항]
- 목적: Codebase Memory MCP 같은 도구로 실제 코드를 탐색하고, 사람이 코드의 큰 흐름과 맥락을 이해할 수 있도록 정리한다. 코드 원문을 그대로 나열하는 것이 아니라 주요 로직과 레이어별 흐름을 표현한다.

- 첫 버전 범위: 텍스트 파싱·컴파일, Tree View, 라인 정보 조회, MCP 탐색 및 수정을 모두 포함한다.

- 작성·표현 규칙:
  - 텍스트로 흐름을 작성하며, 들여쓰기(indent)로 흐름의 깊이와 부모·자식 관계를 표현한다.
  - 들여쓴 로직 라인에는 방향 화살표를 명시한다. `->`는 호출·처리 진행, `<-`는 결과 반환을 나타낸다. 레이어 선언에는 화살표를 붙이지 않는다.
  - 라인 표기 순서는 `들여쓰기 + 화살표 + 선택적 변경 표시((+) 또는 (-)) + Prefix: + 본문 + 선택적 주석`이다. 예: `    -> (+) EFFECT: 생성 알림 표시 // 나중에 추가할 처리`.
  - 부모·자식 관계는 화살표가 아닌 들여쓰기 깊이로 결정한다. `<-`도 같은 깊이의 라인으로 유지하며, 반환한다고 트리의 깊이가 자동으로 바뀌지 않는다.
  - Prefix는 해당 라인의 로직 타입을 나타내며, `EVENT:`처럼 뒤에 콜론(`:`)을 붙여 본문과 구분한다. 파싱 결과의 타입 값에는 콜론을 포함하지 않는다. 예: `EVENT: 프로젝트 생성 버튼 클릭` → Prefix `EVENT`, 본문 `프로젝트 생성 버튼 클릭`.
  - Prefix는 사용자가 자유롭게 작성·추가한다. 에디터는 허용 타입 목록이나 업무 의미를 강제하지 않고, 콜론으로 구분된 값을 파싱·표시·보존한다. 예시의 Prefix는 고정 목록이 아니다.
  - `[Layer]`는 큰 책임 영역을 구분하고, 그 아래 흐름이 어느 레이어에 속하는지 보여준다.
  - 현재 모습(As-Is)과 변경 후 모습(To-Be)을 구분하기 위해 `(+)`는 추가 예정, `(-)`는 삭제 예정을 표시한다. 표시가 없는 라인은 변경 대상으로 표시하지 않은 흐름이다. 한 라인에는 둘 중 하나만 붙인다.
  - diff는 작성자가 원문에 넣은 `(+)`·`(-)`를 GitHub 코드 diff처럼 보여주는 표현이다. `(+)` 라인은 초록색과 `+`, `(-)` 라인은 빨간색과 `-`로 구분하며 원문의 표시는 보존한다. 별도 두 버전의 자동 비교를 뜻하지 않는다.
  - 실제 코드의 구현 여부·완료 상태는 별도로 관리하지 않는다. 변경 표시는 As-Is/To-Be 구분용이며 실제 코드와 자동 동기화하거나 구현 완료 시 자동 해제하지 않는다.
  - 주석으로 해당 로직의 설명과 맥락을 남길 수 있다. 한 줄 주석과 멀티라인 주석을 모두 지원한다.
  - 주석 문법 초안: 같은 줄의 `//`는 한 줄 주석이며, 로직 바로 다음 줄에 같은 깊이로 배치한 `/* ... */`는 해당 로직에 귀속되는 멀티라인 주석이다. 한 로직에 두 종류를 함께 사용할 수 있다.
  - 멀티라인 주석은 줄바꿈을 보존한다. 내부의 들여쓰기·화살표·Prefix·`(+)`·`(-)`·`[Layer]`는 주석 텍스트로 취급하며, 별도 흐름 노드를 만들지 않는다. 중첩 블록은 지원하지 않으며, 닫는 `*/`가 없으면 시작 라인을 포함한 문법 오류를 표시한다.

- 작성 예시

  아래는 ‘프로젝트 생성’ 흐름의 설명용 문법 초안이다. 들여쓰기는 2칸, 진행은 `->`, 반환은 `<-`, 사용자 정의 Prefix의 예시는 `EVENT:`·`CALL:`·`FLOW:`·`CHECK:`·`RETURN:`·`IO:`·`EFFECT:`, 한 줄 주석은 `//`, 멀티라인 주석은 `/* ... */`로 표현한다. 세부 문법은 구현 전 확정한다.

  ```text
  [UI]
    -> EVENT: 프로젝트 생성 버튼 클릭
      -> CALL: createProject // 사용자가 입력한 프로젝트 이름을 전달한다.

  [Application]
    -> FLOW: createProject
      -> CHECK: 프로젝트 이름 검증 // 이름이 비어 있으면 오류를 반환한다.
      /*
      프로젝트 이름의 앞뒤 공백을 제거한 뒤 검사한다.
      검증에 실패하면 저장을 진행하지 않는다.
      */
      -> CALL: projectRepository.save // 검증을 통과하면 저장한다.
      -> (+) EFFECT: 생성 알림 표시 // 나중에 추가할 처리
      <- RETURN: 생성된 프로젝트

  [Infrastructure]
    -> IO: projectRepository.save
      -> (-) IO: JSON 파일에 프로젝트 저장 // 삭제 예정인 As-Is 처리
      -> (+) IO: SQLite에 프로젝트 저장 // 추가 예정인 To-Be 처리
      <- RETURN: 저장된 프로젝트
  ```

  `-> FLOW: createProject`를 접으면 그 아래 검증·저장 호출·알림·반환 라인이 숨겨지고, 펼치면 다시 보인다. `CALL`의 대상 내부 흐름은 해당 레이어에서 별도로 설명한다.

  `-> (+) EFFECT: 생성 알림 표시` 라인을 클릭하면 방향 `->`(진행), 레이어 `Application`, Prefix `EFFECT`, 본문 `생성 알림 표시`, `(+)` 표시 있음, 주석 `나중에 추가할 처리`, 부모 `-> FLOW: createProject`를 확인할 수 있다.

  `-> CHECK: 프로젝트 이름 검증` 라인을 클릭하면 한 줄 주석과 멀티라인 주석 전체를 함께 확인한다. 주석 내부 라인을 클릭해도 귀속된 검증 노드의 정보를 보여준다. 부모 흐름을 접으면 해당 노드와 주석도 함께 숨긴다.

  위 저장 흐름의 `(-)` 라인은 빨강, `(+)` 라인은 초록으로 표시한다. 다음은 GitHub 코드 diff 스타일의 화면 표현 예시이며, 맨 앞 `-`·`+`는 렌더러가 표시하는 기호다. 두 저장 처리를 모두 실행한다는 의미가 아니라 As-Is에서 To-Be로의 교체를 설명한다.

  ```diff
   [Infrastructure]
     -> IO: projectRepository.save
  -    -> (-) IO: JSON 파일에 프로젝트 저장 // 삭제 예정인 As-Is 처리
  +    -> (+) IO: SQLite에 프로젝트 저장 // 추가 예정인 To-Be 처리
       <- RETURN: 저장된 프로젝트
  ```

  `-> (-) IO: JSON 파일에 프로젝트 저장` 라인을 클릭하면 변경 표시 `(-)`와 의미 `삭제 예정`을 확인한다. 구현 완료 여부는 표시하지 않는다.

- 파싱·시각화:
  - Mermaid처럼 작성한 텍스트의 표현 규칙을 파싱·컴파일하여 화면에 보여준다.
  - 각 라인의 본문, 들여쓰기 깊이, 부모·자식 관계, 방향 화살표, Prefix, 레이어, 변경 표시(`(+)`·`(-)`·없음), 주석을 구분해 읽을 수 있어야 한다. 주석은 종류(한 줄·멀티라인), 내용, 원문 라인 범위, 귀속 노드를 보존하며 UI와 MCP에서 조회·수정할 수 있어야 한다.
  - 들여쓰기 계층을 Tree View로 보여주며, 전체 접기와 특정 가지 펼치기·접기를 지원한다. 접기·펼치기는 표시 상태만 바꾸고 원문은 변경하지 않는다.
  - 특정 라인을 클릭하면 해당 라인의 파싱된 정보를 확인할 수 있어야 한다. 방향 화살표·주석·Prefix·변경 표시 등 해당 라인에 없는 정보는 없는 상태로 구분한다.

- MCP 연동:
  - CodeWeave 자체를 탐색하고 수정할 수 있는 MCP를 제공한다. 실제 코드를 찾는 Codebase Memory MCP와는 별도의 역할이다.
  - 지원 범위는 CodeWeave 문서와 흐름의 조회·탐색, 특정 라인의 내용·속성 조회 및 수정이다.
  - MCP를 통해 수정한 내용도 동일한 표현 규칙으로 파싱되고 화면에 반영되어야 한다.

- 구현 전 확정할 세부 계약:
  - 들여쓰기 단위, 주석 문법과 귀속 기준, 레이어 적용 범위. Prefix 자유 작성과 콜론 구분은 확정 사항이다.
  - MCP에서 수정 대상을 식별하는 방식과 도구별 입력·출력, 잘못된 문법의 오류 표시 방식.
  - 위 항목은 아직 정하지 않은 구현 설계 사항이며, 확정된 사용자 요구와 구분한다.
