# 제품 설계

## IUI-001 독립 Intelligent UI Python 프로젝트
`6-langgraph-platform-to-py`를 복사하고 `open-intelligent-ui`의 UI 카탈로그, 함수, 액션, 스타일, 채팅 화면, 브라우저 저장, 갤러리와 미디어 API를 가져왔다. 원본 두 프로젝트는 수정하지 않는다. 모델 실행은 Python LangGraph/DeepAgents와 직접 OpenAI 연결이다.

## IUI-002 인터랙티브 답변
개발용 `/lib-story`에서는 등록된 컴포넌트 55개·함수 59개·액션 1개를 검색하고 개별 예제의 OpenUI Lang과 렌더링을 비교한다. Col은 Col만 등록한 라이브러리의 세 가지 예제를 제공하며, 나머지 항목은 기본·변형/경계 사례 두 가지씩 제공한다. 코드를 편집·적용하거나 초기화할 수 있다. 모델 호출이나 대화 저장은 사용하지 않는다.

55개 컴포넌트, 59개 함수, CopyToClipboard 액션을 제공한다. 지도, 사진, 표, 차트, SVG, 수식, 폼, 계산, 게임을 표현한다. $variable과 @Set으로 브라우저에서 상호작용한다. 일반 채팅의 모델 출력 정확성은 보장하지 않는다. 문서 보고서 생성은 IUI-005의 원문 구조화·검증 경로를 사용한다.

## IUI-003 대화 보관과 도구
B와 같은 localStorage 대화 및 UI 상태 저장을 사용한다. Python의 날씨·주가·검색 mock 도구를 유지하며 실시간 정보로 표시하지 않는다. 문서 비교/PDF 검색과 SQLite 대화 저장은 이 프로젝트 범위가 아니다. 갤러리/preview의 Query는 별도 demoTools로 실행되며 일반 채팅에 서버 Query API를 추가하지 않는다.

수동으로 생성한 대화와 UI 상태는 현재 브라우저·프로필·origin의 localStorage에 남는다. 샘플 파일의 일괄 채팅 생성·히스토리 복원 페이지 생성 도구는 제거했다. 기존 대화는 보존하며 계정 동기화 기능은 없다.

## IUI-004 실행
Python 2036, frontend 3044. OPENAI_API_KEY와 OPENAI_MODEL은 backend-langgraph/.env에서 관리한다. 프런트엔드는 LANGGRAPH_API_URL로 연결한다. 인증·공개 배포·계정 동기화는 추가하지 않았다.

## IUI-005 원문 기반 인터랙티브 벤더 보고서
화면의 **보고서 만들기**에서 Markdown·HTML·TXT를 선택하고 **인터랙티브 보고서 생성**을 누르면 새 대화에 저장한다. 파일은 최대 500KB, 추출 본문은 최대 120,000자다. 선택한 본문을 모델로 전달하며 HTML의 스크립트·스타일은 실행하거나 삽입하지 않는다. 채팅에 적힌 로컬 경로를 자동으로 읽는 기능은 아니다.

벤더 분석의 섹션 1/3A/3B/7B 표를 인식하면 원문에서 KPI·기간 비교·캠페인·광고 적격성 제약 시간·위험 추정액을 추출해 Intelligent UI 프로그램을 구성한다. 개요·캠페인·재고·조치·근거를 탭 없이 하나의 긴 문서로 모두 표시한다. 캠페인 선택, 제약 시간 슬라이더, 시간·위험 추정액 차트 동시 표시, 조치 체크·복사, 근거 섹션 선택과 전체 원문을 제공한다. 상호작용은 브라우저에서 처리하며 추가 모델 호출이나 실제 예산·재고 변경을 일으키지 않는다. 대화·필터·체크 상태는 localStorage로 복원한다.

인식된 벤더 보고서의 수치와 차트는 모델이 다시 쓰지 않는다. 모델은 별도로 표시되는 **AI 해설** 카드만 생성한다. 해설 생성 실패·45초 초과·계약 위반 시 화면에 해설 제외를 알리고 원문 보고서를 계속 제공한다. 일반 주제의 보고서는 별도 작성 프롬프트로 생성하고 카탈로그·연속 섹션을 검증하며 최대 한 차례 재생성한다. 여행·기술·프로젝트 보고서에 벤더 전용 KPI나 캠페인 UI를 강제하지 않는다. 후속 설명 요청도 모델이 현재 요청 의도를 판단한다.

W1/W2 값과 기재 변화량을 별도로 보존한다. 금액 변화량 불일치와 동일한 현재·추천 예산은 확인 사항으로 표시한다. 이는 모든 오류를 판별하는 감사 기능이 아니다. 미기재 값을 0으로 바꾸지 않으며 품절·노출 제한 등 이슈 유형과 기간을 보존하고 중복 시간·위험액을 합산하지 않는다. 동일 예산 경고와 충돌하는 무조건 증액 문장은 원문 확인 안내로 대체한다. AI 해설 전체의 사실·인과 의미가 자동 검증되는 것은 아니다.

`docs/vendors/`의 Markdown 8개는 수동 업로드용 샘플 분석이다. 공급업체·캠페인·상품 식별자는 공개용 표기로 정리되어 있고 마켓플레이스/FBA를 가정한 데모 규칙을 안내한다. 파일은 앱 실행·자동 테스트·배치 도구의 의존성이 아니다.

인쇄/PDF에서는 본문의 스크롤 제한을 해제하고 채팅 메뉴·입력기를 숨긴다. 넓은 근거 표는 항목명과 값을 붙인 세로 레코드로 출력한다. 적용 중인 필터는 그대로 유지하므로 전체 출력 전에는 전체 캠페인·전체 근거와 최소 제약 시간 0을 선택한다. 기존 앱 생성 벤더 보고서도 열 때 연속 레이아웃과 차트 데이터 키를 보정하며 원문·AI 해설은 보존한다.

## IUI-006 모델의 의도 판단
메시지를 보낼 때마다 모델이 최근 대화 맥락으로 일반 UI 또는 보고서 요청을 판단한다. 보고서 버튼·특정 단어·문서 길이가 서버 경로를 직접 결정하지 않는다. 일반 여행 질문은 지도·일정 UI로, 같은 일정의 보고서 작성 요청은 연속 문서로, 보고서에 대한 좁은 설명 요청은 일반 응답으로 처리할 수 있다. 모델 판단은 확률적이며 모든 표현의 정확성을 보장하지 않는다.

보고서의 근거가 최신 메시지인지 이전 문서/답변인지도 모델이 선택한다. 새 주제에 무관한 이전 벤더 문서를 자동 적용하지 않는다. 의도 판단에는 별도 모델 호출 한 번이 추가되며, 실패나 20초 초과 시 오류를 표시하고 키워드 판정으로 되돌리지 않는다. 일반/보고서 작성 프롬프트는 분리하며 API 키는 계속 Python만 소유한다.
