# 제품 설계 — Filing Studio

## PROD-01 목적과 범위

사용자가 기업 보고서를 자유롭게 질문하고, 분석 결과를 대화 안에서 읽거나 Canvas 대시보드에 보관하는 로컬 단일 사용자 앱이다. 기존 6-5 문서 비교·Intelligent UI 계약을 승계하며 6-4의 패널 등록, 24열 그리드, 탭, 드래그·리사이즈·선택 경험을 서버 소유 상태에 통합한다. Grafana 설치가 필요하지 않다. [사용자 시나리오 US-01~16](user-scenarios.md)이 목표 경험이다.

## RESEARCH-01 자료와 근거

SEC 수집은 기업 식별 → 공시 검색 → 원문 저장의 서브그래프다. 수집 성공, 실패, 검색 인덱싱 완료를 구분한다. 섹션 발췌·전체 원문 범위 읽기·여러 보고서 검색을 제공한다. 기존 PDF 준비 CLI와 문서별 페이지 출처 검색도 유지한다. 준비된 PDF는 원문 페이지 읽기와 긴 페이지 이어 읽기도 제공한다. 원문 확인 요청은 현재 턴의 실제 페이지/섹션 읽기 증거를 검사하며, 보고서 개요는 여러 원문 영역을 읽도록 요구한다. 검색 구절만으로 전체 원문을 검토했다고 안내하지 않는다.

연간 매출·순이익·영업이익은 SEC XBRL을 사용한다. 연간 기간 종료일을 기준으로 정규화하고 정정/재공시를 구분한다. 통화와 단위를 함께 표시한다. 누락 연도를 0으로 채우지 않으며 연속한 연간 관측치에 대해서만 YoY를 계산한다. 보고서의 직접 근거와 분석 해석을 구분해야 한다. 조회 근거가 있는 최종 답변은 기업·수치·기간·단위·페이지의 근거 일치를 추가 모델로 검사한다. 최대 두 번 보완 후에도 불일치하면 분석을 보류한다. OpenUI 분석 패널의 신규 게시와 프로그램 수정도 저장 전에 근거 검사를 거치며, 실패나 검사 서비스 오류 시 기존 패널을 유지한다. 명시적 가정이나 일반 UI에는 외부 사실 근거를 요구하지 않는다. 사용자가 지정한 연도·기업 제외 범위는 표시 조건으로 별도 전달하며, 제외된 자료가 원문에 있다는 이유만으로 결과를 거절하지 않는다. 표시한 값·단위·출처와 비연속 기간의 YoY 표기는 계속 검사한다. 이 검사는 모델 기반이며 정확성을 보장하거나 원문 검토를 대체하지 않는다.

SEC 오류 안내는 HTTP 상태와 재시도 가능 여부를 구분하며 요청 헤더/쿼리를 노출하지 않는다. SEC 수집 저장소와 준비된 PDF 목록을 별도로 취급한다. 현재 환경은 SEC의 공개 엔드포인트에서 403을 반환한다. 수집 성공을 주장하지 않으며 준비된 PDF 분석을 계속 사용할 수 있다. 최신 공시 수집의 실환경 검증은 남아 있다.

## CHAT-01 대화 중심 탐색

첫 화면에서 바로 질문한다. 보고서·기업 비교·3년 추이·Canvas 외에 가정 계산기, 분석 입력 폼, 메모와 체크리스트 시작 예제를 제공한다. 대화 안의 작업 내역에서 검색·원문 읽기·패널 저장의 진행 중/응답 수신/실패/일부 실패/미완료 상태와 문서·페이지를 확인한다. 도구 응답 수신을 분석 정확성이나 수집 성공으로 단정하지 않는다. 대화 목록에서 생성·선택·이름 변경·삭제하며 이전 대화를 이어간다. 답변에는 통합 OpenUI 카탈로그의 표·차트·카드·인터랙티브 요소를 사용할 수 있다. 일반적인 UI 요청에 무관한 문서 검색을 강제하지 않는다. 주 화면은 OpenUI headless ChatProvider/useThread/useThreadList로 구성한다. `/comparison`은 승계한 기존 비교 화면이다.

보고서를 확보하는 작업은 SEC 수집 subagent에 위임할 수 있다. 검색·수집 실패는 자료의 사실 부재와 다르며, 오류 시 기존 결과를 유지한다. 검토용 대화는 실제 실행한 이력으로 남긴다. 사용자가 중단하면 즉시 안내하고 저장 이력에도 미완성 상태를 표시한다. 실패한 실행도 상태 안내를 보존하며 다시 질문할 수 있다. 복사된 과거 대화와 이번 검증 대화는 구분한다.

## CANVAS-01 결과 보관과 조작

대화의 분석 artifact를 버튼 또는 드래그로 Canvas에 추가한다. Canvas에 직접 생성하는 요청도 지원한다. 일반 OpenUI 프로그램과 실제 조회 결과를 가진 재무 패널을 저장한다. 독립 프로그램은 저장 전 카탈로그 parser 검증을 통과해야 한다.

패널 사이에 사용자가 둔 빈 공간은 자동으로 당겨 채우지 않으며 저장 위치를 유지한다. 겹친 패널은 충돌 처리로 정리한다.

패널은 안정된 ID, 제목, 탭, 배치, 고정 여부, 조회 조건, 데이터·출처, UI 입력 상태를 가진다. 사용자가 직접 또는 대화로 이동·크기 조절·선택·고정·수정·삭제한다. 추가 버튼과 드래그는 채팅에서 수정한 현재 입력값을 Canvas에 복사한다. 이후 Canvas 입력 변경은 채팅 원본과 독립적이다. 같은 artifact를 다시 추가하면 기존 패널로 이동한다. 동일 제목·프로그램·출처의 채팅 결과를 반복 게시하면 기존 artifact ID를 재사용한다. 새로 게시한 결과는 최종 답변의 표시 경로에서 해당 artifact를 참조해야 한다. Canvas 변경 요청에서 필요한 작업 종류와 기존 대상별 도구 성공이 없으면 제한 재시도하며, 끝내 완료하지 못하면 이미 적용된 결과와 별도로 미완료를 안내한다. 추가 가능한 채팅 결과 요청은 artifact 등록 도구의 성공도 검사한다. 삭제는 원문과 대화의 삭제를 의미하지 않는다.

Canvas 폭 600px 미만에서는 저장 좌표를 변경하지 않고 패널을 한 열로 표시한다. 이때 드래그·리사이즈는 비활성화한다. 넓은 화면에서 드래그·크기 조절 중 Escape를 누르면 저장 전 배치로 돌아간다. 핸들은 방향키로 이동하고 Shift+방향키로 크기를 조절한다. 너비·높이 선택도 제공하며 고정한 패널은 크기를 바꿀 수 없다.

앵커링은 위치 고정과 선택한 패널로 이동·강조하는 경험으로 구현한다. 고정한 패널의 이동/크기 변경은 거부하며 먼저 고정을 해제해야 한다. 중복 제목이나 모호한 제외 연도는 사용자에게 확인한다. 확인이 필요하거나 변경 작업이 없는 실행 계획에서는 Canvas 변경 도구를 제공하지 않으며, 사용자가 탭 등으로 대상을 확정하면 해당 패널만 변경한다.

## FRESH-01 갱신과 Snapshot

재무 패널의 수동 새로고침은 저장된 SEC 조회 조건으로 데이터를 가져오며 모델을 호출하지 않는다. Live 패널은 자동 갱신을 끄거나 1·5·15분으로 설정할 수 있다. 화면에 열린 탭의 패널이며 브라우저가 보일 때만 주기를 확인한다. Snapshot은 현재 데이터를 보관하고 수동·자동 갱신과 내용 교체를 차단한다. 다시 조회하려면 Live로 전환한다.

마지막 정상 조회, 원천 확인 시각, 선택한 관측치의 최근 공시일을 구분한다. 실패 시 기존 데이터와 정상 조회 시각을 유지하며 오류를 표시한다. 조회 중 다른 변경이 발생하면 늦은 결과는 적용하지 않는다. 정책과 데이터는 저장·복원된다. 정책 변경/새로고침도 대화 도구로 요청할 수 있다. 실제 SEC Company Facts 수동·1분 자동 갱신과 Snapshot 요청 중지를 검증했다. Snapshot에서 230초 동안 갱신 요청은 0건이었다.

## CANVAS-02 탭과 영속성

대화마다 별도 Canvas를 저장한다. 탭 추가·이름 변경·선택·삭제 및 패널의 탭 이동을 지원한다. 삭제 확인창에서 탭 제목과 포함 패널 수를 확인하고 취소할 수 있다. 승인하면 해당 탭과 패널만 삭제하고 다른 탭·대화·원본 artifact를 유지한다. 마지막 탭은 삭제할 수 없다. 대화 재선택과 새로고침 후 서버의 저장 상태를 읽는다. 사용자와 에이전트의 변경이 충돌하면 오래된 요청을 거절하고 최신 화면에서 다시 시도하게 한다. 패널 100개, 탭 20개를 상한으로 둔다.

## EXPORT-01 내보내기와 복원

- JSON: 전체 탭, 패널, 출처, 조회 조건과 UI 상태를 보관한다. 가져오기는 기존 패널을 보존하고 새 탭/ID로 추가한다.
- CSV: 전체 탭의 재무 데이터 행과 일반 표·차트의 값을 포함한다. 패널·탭·데이터 블록 번호·행 번호·열 이름·시각화 종류로 구분하고 출처를 함께 담는다. 계열형 차트는 계열/범주/값, 원형 계열은 범주/값, 산점도는 계열/X/Y/Z, 일반 Chart는 원본 데이터 열을 내보낸다. 저장된 입력값과 계산을 반영하며 표·차트가 없는 패널은 PDF/JSON 안내를 표시한다.
- PDF / 인쇄: 전용 인쇄 화면에서 모든 탭의 패널을 펼친 뒤 브라우저로 PDF를 저장한다.

에이전트는 내보내기 요청을 화면에 전달한다. 다운로드/인쇄 실행은 표시된 브라우저 컨트롤로 수행하며 파일 저장이 확인되지 않았는데 완료했다고 말하지 않는다.

## UI-01 카탈로그 호환성

6-5의 137개 구성요소와 59개 함수 및 CopyToClipboard를 보존한다. DashboardArtifact, YearOverYear, FocusPanel을 추가한다. Col은 기존 표의 열 계약이며 세로 레이아웃은 VStack이다. 프런트 카탈로그와 모델 프롬프트는 항상 함께 생성·동기화한다.

## LIMIT-01 경계와 검증

계정 인증·다중 사용자 협업·운영 배포·OCR은 현재 범위가 아니다. JSON 가져오기에서 기존 패널 보존·새 ID·입력 상태 복원과 잘못된 프로그램 거절을 브라우저에서 확인했다. 전체 탭 인쇄는 계산기 패널 두 개로 검증했으며 추가로 가정 데이터의 두 계열 차트와 40행 표를 3페이지 PDF로 검증했다. 실제 SEC 데이터 수집 성공을 의미하지 않는다. 검색과 생성 결과는 근거 확인이 필요하다. 이번 프로젝트의 검증 상태는 [구현 현황](implementation-status.md)과 [현재 변경 기록](../flow/2026-10-25-dashboard-implementation.md)을 따른다.

## INPUT-01 연속 입력 보존

같은 브라우저에서 같은 대화로 보내는 Canvas 변경은 순서대로 저장한다. 메모 입력 직후 체크박스를 연속 선택해도 앞선 저장과 자체 충돌하지 않는다. 외부 변경에 대한 revision 충돌 검사는 유지한다. 메모와 체크리스트 두 패널의 입력·새로고침 복원을 실제 브라우저에서 확인했다. 새 분석은 대화와 Canvas를 함께 보는 화면으로 시작한다. 신규 생성 개수 검사와 동일 실행 내 반복 게시 방지를 제공한다. 새 객체의 빈 대상 ID를 기존 대상 검사에서 제외하며, 실제 두 패널 생성 후 잘못된 미완료 안내 없이 입력 복원까지 확인했다.

## RESEARCH-02 같은 기업의 여러 보고서

선택적으로 준비한 NVIDIA FY2025 보고서와 FY2026 보고서를 함께 검색·읽을 수 있다. PDF만 분석하도록 요청하면 SEC API를 강제하지 않고 원문 근거를 가진 일반 차트/표로 게시한다. 확보되지 않은 연도나 근거 없는 변화를 채우지 않는다. 실제 검증 상태는 구현 현황에서 구분한다.

## SOURCE-01 출처 저장과 내보내기

일반 OpenUI 패널을 게시하거나 내용을 수정할 때 화면에서 실제 참조하는 출처를 패널 sources에도 저장한다. 도구에 별도로 전달한 출처와 합치되 동일한 항목은 중복하지 않는다. 수정된 프로그램에서 더 이상 사용하지 않고 도구에도 전달하지 않은 이전 출처는 남기지 않는다. 새 게시·수정에 적용하며 기존 데이터 전체를 소급 변경하지 않는다. JSON 내보내기에서 실제 보고서의 페이지별 출처 두 개가 유지되는 것을 확인했다.

## TAB-01 대화에서 탭 지정과 삭제 확인

새 탭을 만든 뒤 각 패널의 대상 탭을 명시하여 게시할 수 있다. 같은 실행의 동일 탭 생성 재시도는 기존 탭을 재사용한다. 내용이 있는 탭 삭제에서 패널 삭제 승인 여부가 불명확하면 포함된 패널 수와 함께 확인한다. 확인 중에는 상태를 유지하고 승인 후 해당 탭과 패널만 삭제한다. 실제 검증에서는 사용자가 미승인을 명시한 확인 질문→승인 버튼→대상만 삭제→reload를 확인했다. 일반적인 짧은 요청의 의도 분류는 모델에 의존하며 최초 실행에서 오분류 사례가 있었다.

확인이 필요하다고 판정된 요청은 질문을 그대로 표시하고 변경하지 않는다. 사용자는 대화 입력으로 답할 수 있다. 생성 결과를 단순히 다시 그리는 응답으로 확인 질문을 대체하지 않는다.

## SCOPE-03 기간과 보고서 범위

사용자 확정에 따라 실제 대표 검증은 3년치로 한다. 핵심은 n년 확대·축소와 특정 연도 제외이며 3년 고정 구현이 아니다. 숫자 조회/차트 도구는 기본 3년, 명시 요청은 기존 1~20년 입력을 유지한다. 수집 대상은 10-K와 10-Q 및 각 정정본으로 한정한다. 연간 재무 시계열은 10-K 근거만 사용하며 분기 원문 분석과 구분한다. n년 10-Q 수집은 최근 서로 다른 3n개 보고 기간을 목표로 하며 이는 누락 없는 달력 n년을 보장하지 않는다. 실제 확보 기간·누락은 별도로 안내한다.

## CACHE-01 SEC 로컬 재사용과 요청 억제

사용자 요청에 따라 SEC 자료는 로컬 SQLite 캐시를 먼저 사용한다. 기업 목록·과거 제출 목록은 24시간, 최신 제출 목록·재무 데이터는 기본 1시간 재사용하며 원문은 기존 보관본을 우선한다. 캐시 만료는 새 조회 여부를 결정하는 기준이며, 이미 수집한 분석 원문을 자동 삭제하지 않는다. 같은 URL의 동시 요청과 동시 새로고침은 각각 하나로 합친다. 실패·비정상 JSON은 기존 정상 캐시를 덮어쓰지 않는다.

SEC로 나가는 요청은 백엔드 프로세스에서 한 번에 하나, 최소 1초 간격으로 제한한다. 403/429 또는 Retry-After가 있는 서버 오류를 받으면 최소 60초 및 서버 지정 대기시간 중 긴 시간을 적용하고 후속 새 요청은 대기 안내로 종료한다. 유효한 캐시는 이때도 읽을 수 있다. 기존 결과를 최신 수집 성공으로 오인시키지 않는다. 캐시 보강이 SEC 접근 허용을 보장하지는 않는다.


## PLAN-INTENT-01 출력 목적지

“차트로 보여줘”나 “요약해줘”는 기본적으로 대화 안에서 응답한다. Canvas에 추가해 달라고 요청한 경우에만 새 패널을 만든다. 나중에 추가 가능한 채팅 결과를 명시적으로 요청한 경우에는 재사용 가능한 결과를 게시하되 Canvas는 변경하지 않는다. “1년치는 빼줘”처럼 어느 연도인지 정하지 않은 요청에는 제외 연도를 확인한다.


## SEC-Q-PARTS-01 분기 보고서 읽기

10-Q의 재무제표와 법적 절차처럼 Item 번호가 같아도 다른 Part에 속한 내용은 별도로 제공한다. “Item1을 보여줘”가 여러 섹션을 가리키면 Part별 후보를 안내한다. 분기 위험 요인은 `Part II Item1A` 등 실제 원문의 위치를 함께 표시한다. 자동 섹션 추출이 불가능한 경우 전체 원문 읽기를 사용하며 임의로 섹션을 합치지 않는다.


## PUBLISH-POLICY-01 요청한 위치와 개수 유지

“Canvas 패널 하나에 담아줘”는 하나의 패널을 생성하고, 답변 보완 중 같은 결과를 다시 저장해도 요청 개수를 넘기지 않는다. 이미 저장한 내용의 보완은 같은 패널을 수정한다. “최소 두 개”처럼 개수를 열어둔 요청에는 임의의 최대 개수를 적용하지 않는다. 채팅에 보관할 결과와 Canvas에 추가할 결과는 요청한 목적지에 따라 구분한다.


## DISCLOSURE-01 변경 여부 설명

공시의 '변경 없음'을 설명할 때 예외 범위를 포함한 원문 전체와 직역을 제공한다. 한 문장 요청에는 예외를 보존한 직역을 사용한다. 원문에 적힌 내용과 추가 해석을 구분하며, 예외에 열거된 위험을 근거 없이 새로 추가된 위험이라고 바꾸지 않는다. 모델 검사는 보조 수단이며 반복 검증에서도 오판할 수 있다.


## SEC-NATIVE-01 현재 수집 경험

SEC 수집은 독립 Python/LangGraph가 직접 수행한다. 저장한 정적 원문은 재사용하고 수집 결과에 재사용 수를 표시한다. Apple 연간3건/분기3건, SEC3년 재무 차트 및 제외 연도 유지 갱신을 실제 검증했다. BFF는 설정/코드 참고 대상일 뿐 서비스 의존성이 아니다. 기존 수집403 제약은 현재 복구됐으며 과거 실패 이력을 보존한다.
