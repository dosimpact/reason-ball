```
④ 필요한 근거 탐색
eg, 캠페인별 ROAS, CPA, 지출액, 예산 소진율, 예상 성과 등을 조회해 가설을 검증한다.

⑤ UX 패턴 선택
Diagnosis → Comparison → Recommendation → ReviewAndApply

```
```
id: budget_optimization
version: "1.0"

# ① 비즈니스 목적 해석
business_goal:
  platform: 광고주 유지율 개선 및 지속 가능한 광고 매출 성장
  advertiser: 광고 효율 개선, CPA 절감, 불필요한 지출 방지

  aligned_goal: >
    광고주의 예산을 효율적으로 활용하여
    광고 성과와 장기적인 투자 가치를 높인다.

# ② 사용자 의문 및 의사결정
user_decision:
  problem: >
    현재 캠페인 예산이 효율적으로 사용되고 있는지
    판단하기 어렵다.

  questions:
    - 어떤 캠페인이 비효율적인가?
    - 현재 예산 배분에 문제가 있는가?
    - 어느 캠페인의 예산을 조정해야 하는가?
    - 예산 변경 시 기대 효과와 위험은 무엇인가?

  desired_outcome: >
    광고주가 예산 증액, 감액, 재배분 또는
    유지 여부를 합리적으로 결정할 수 있다.

# ③ 해결 및 설명 가설 수립
hypothesis:
  proposal: >
    성과가 낮은 캠페인의 예산을 줄이고
    성과가 높은 캠페인으로 재배분하면
    전체 광고 효율이 개선될 수 있다.

  assumptions:
    - 캠페인 간 성과 차이가 충분히 존재한다.
    - 우수 캠페인은 추가 예산을 활용할 여력이 있다.
    - 재배분이 광고주의 목표에 부합한다.

  alternatives:
    - 예산보다 입찰 전략이 문제일 수 있다.
    - 일시적인 성과 변동일 수 있다.
    - 현재 예산 배분이 이미 적절할 수 있다.

# ④ 필요한 근거 탐색
evidence:
  required:
    - data: 캠페인별 ROAS, CPA, 지출액, 전환 수
      purpose: 캠페인별 광고 효율 비교

    - data: 캠페인별 예산, 소진율, 소진 시각
      purpose: 예산 제약 및 추가 투자 여력 분석

  optional:
    - data: 예산 변경 시 예상 성과
      purpose: 변경 전후 시나리오 비교

    - data: 과거 성과 추이
      purpose: 성과 차이의 지속성 검토

  validation:
    - 가설을 뒷받침할 충분한 데이터가 있는가?
    - 가설에 반대되는 근거는 없는가?
    - 예산 조정이 실제로 개선을 가져올 가능성이 있는가?

# ⑤ UX 패턴 선택 및 컴포지션 설계
ux_pattern:
  flow:
    - pattern: Diagnosis
      purpose: 현재 광고 성과의 문제를 진단한다.
      slots:
        - 성과 요약
        - 문제 원인 및 근거

    - pattern: Comparison
      purpose: 캠페인별 성과와 예산 대안을 비교한다.
      slots:
        - 비교 대상
        - 비교 지표

    - pattern: Recommendation
      purpose: 검증된 근거를 바탕으로 개선안을 제시한다.
      slots:
        - 추천 내용
        - 추천 근거
        - 기대 효과 및 위험

    - pattern: ReviewAndApply
      purpose: 변경 내용을 검토하고 최종 결정한다.
      slots:
        - 변경 전후 비교
        - 적용 및 취소 액션

  guidelines:
    - 검증된 근거에 따라 적합한 패턴을 선택한다.
    - 필요한 데이터가 부족하면 진단 패턴을 우선한다.
    - 각 Slot에 적합한 컴포넌트는 Component Catalog에서 선택한다.
    - 예산 변경은 반드시 광고주 확인 후 실행한다.
```

```
# Business UX Pattern Composition Planner

사용자의 요청을 분석하여 **비즈니스 목적에 부합하고, 사용자의 합리적인 의사결정을 돕는 UX 컴포지션**을 설계하라.

다음 5단계를 기준으로 판단한다.

1. **비즈니스 목적 해석**
   - 무엇을 개선하려는가?
   - 플랫폼과 사용자 목표가 어떻게 일치하는가?

2. **사용자 의문·의사결정 분석**
   - 사용자가 해결하려는 근본적인 문제는 무엇인가?
   - 사용자가 판단하기 위해 해소해야 할 의문은 무엇인가?

3. **해결 및 설명 가설 수립**
   - 어떤 해결책이 사용자의 문제를 개선할 수 있는가?
   - 사용자가 그 해결책을 선택할 만한 합리적인 이유는 무엇인가?
   - 다른 원인이나 해결 가능성은 없는가?

4. **필요한 근거 탐색 및 검증**
   - 가설을 검증하려면 어떤 데이터가 필요한가?
   - 사용자의 의문에 답하기 위한 핵심 근거는 무엇인가?
   - 근거가 부족하거나 가설과 충돌하는 부분은 없는가?

5. **UX 패턴 및 컴포지션 설계**
   - 어떤 UX 패턴이 사용자의 의사결정을 가장 효과적으로 지원하는가?
   - 각 근거를 어떤 정보 구조와 컴포넌트 조합으로 표현해야 하는가?
   - 어떤 순서로 정보를 전달하고 행동으로 연결해야 하는가?

## 핵심 원칙

- UI 컴포넌트부터 선택하지 말고, 비즈니스 목적과 사용자 의사결정에서 출발한다.
- 가설을 사실로 취급하지 않으며, 검증된 근거와 추정을 구분한다.
- 추천 수락을 유도하기보다 사용자가 기대 효과와 위험을 이해하도록 돕는다.
- 필요한 경우 여러 UX 패턴을 조합한다.
- 정해진 출력 스키마를 강제하지 않는다. **최종적으로 선택한 UX 구성과 그 근거를 명확하게 제시한다.**
```
