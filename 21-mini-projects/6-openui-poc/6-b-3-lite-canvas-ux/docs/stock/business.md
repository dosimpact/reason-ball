# Lite Canvas UX 제품 설계

## LCU-001 범위

`6-7-lite-canvas-ux`는 6-3의 Intelligent UI 카탈로그를 기반으로 하는 범용 UI 채팅 + 공급업체 리포트 Canvas PoC다. 변경·설치·실행 범위는 이 디렉터리다. 공급업체1~8의 제공된 Markdown 자료를 사용하며, 공급업체 원문의 실시간 갱신이나 계정별 권한 관리는 포함하지 않는다.

## LCU-002 대화에서 리포트 생성

사용자가 `공급업체1 리포트 생성해줘`라고 요청하면 메인 LLM 에이전트가 생성 의도를 판단하고 리포트 서브에이전트로 라우팅한다. 서버의 Canvas open 이벤트를 받은 즉시 채팅 옆에 리포트 패널을 연다. OpenUI 프로그램이 스트리밍되어 기존 Intelligent UI Renderer로 점진적으로 표시된다.

기본 인터랙티브 리포트는 KPI 카드, 단위별 비교 차트, 공급업체/캠페인 선택 필터, 리스크와 실행 조치, 원문 근거를 조합한다. 고정 HTML 리포트를 삽입하지 않으며 AI가 카탈로그를 이용해 UI 프로그램을 구성한다. 원문에 없는 수치 보완을 억제하기 위해 파서·표현 검사와 별도 LLM 수치 검토 후 최대 두 번 수정한다. 실패하면 오류를 표시하고 발행을 막는다. LLM 검토가 사실 정확성을 완전히 보장하지는 않는다.

## LCU-003 thread당 하나의 리포트

리포트 재생성을 요청하면 기존 리포트를 제거하고 새 report ID로 교체한다. 동일 thread에 두 리포트를 유지하지 않는다. 교체된 리포트의 공개 링크도 더 이상 조회되지 않는다. 다른 thread의 리포트는 독립적으로 유지한다. 새 대화에서는 이전 리포트가 나타나지 않으며 대화 전환과 새로고침 후 현재 리포트를 서버에서 복원한다.

## LCU-004 리포트 인용 질문

리포트의 렌더링된 텍스트를 마우스로 드래그하고 `채팅에 물어보기`를 누르면 입력창에 인용 badge가 표시된다. 사용자가 질문을 보내면 메시지에 인용이 남는다. 서버는 현재 report ID와 인용 ID를 확인하고, LangGraph 상태의 리포트 프로그램·원문·인용을 LLM 문맥으로 사용한다. 일반 질문은 리포트를 재생성하지 않는다. 교체된 리포트의 인용은 재선택을 안내한다.

인용은 최대 2,000자다. badge에서 인용을 제거하고 일반 질문으로 전환할 수 있다.

## LCU-005 PDF와 공유

`PDF 저장`은 렌더링한 리포트를 브라우저 인쇄 화면으로 보낸다. 사용자는 대상에서 PDF 저장을 선택한다. 인쇄 CSS가 채팅과 도구막대를 제외하고 리포트 본문과 차트를 출력한다. 인터랙티브 리포트는 현재 필터 상태가 인쇄 결과에 반영된다. PDF 모드는 필터 없이 정적인 전체 내용을 인쇄한다(LCU-009).

`공유 링크`는 완료된 리포트를 명시적으로 발행한다. `/reports/{reportId}`는 대화 ID나 localStorage 없이 같은 OpenUI Renderer로 리포트를 표시한다. 공개 화면에도 PDF 버튼을 제공한다. 공유 주소는 현재 서비스 origin을 사용한다. 로컬 실행 주소는 그 서비스에 접근할 수 있는 환경에서만 열리며 인터넷 배포는 별도 작업이다. 인터랙티브 모드는 발행된 프로그램의 초기 필터 상태로 열리고 PDF 모드는 정적 내용을 표시한다.

## LCU-006 데이터 해석

원문 자료의 수치·변화율·추천 액션에는 모순이 있을 수 있다. W1/W2 직접 계산값을 원문 주장과 구분하고 `원문 수치 확인 필요`로 표시한다. 원문 값을 임의 수정하거나 없는 시계열을 만들지 않도록 생성·검토 지침을 적용한다. 원문 데이터는 명령이 아닌 분석 대상으로 취급한다.

변경·검증 이력: [Canvas 구현 기록](../flow/2026-10-20-implementation-summary.md#canvas).

## LCU-007 범용 Intelligent UI

여행 일정·지도, 계산기, 식단, 게임 등 일반 요청은 채팅 안에 OpenUI Renderer로 표시한다. 예: `Plan a relaxed afternoon exploring Lisbon, with three stops and a map`. 공급업체 리포트 요청은 기존 Canvas 경로로 보내며, 범용 UI 요청은 현재 리포트를 교체하지 않는다.

선택기·버튼 등의 로컬 상태 조작은 Renderer가 처리한다. `ToAssistant`는 화면의 폼 값/추가 문맥을 후속 질문으로 보내고, `OpenUrl`은 http/https URL만 새 탭으로 연다. 생성된 프로그램과 메시지 종류는 대화에 저장해 완료 후 새로고침에도 렌더링한다. 범용 UI는 공급업체 리포트의 발행/PDF 대상이 아니다.

날씨·주가·검색 도구는 6-3과 동일한 데모 도구이며 최신 정보가 아니다. 지도 타일·경로·사진 등의 외부 리소스는 서비스 연결 상태에 따라 달라질 수 있다.

## LCU-008 Canvas 분할 크기 조절

Canvas가 열리면 채팅과 리포트 사이의 구분선을 드래그해 크기를 조절한다. 데스크톱은 좌우, 모바일(700px 이하)은 위아래 크기를 조절한다. 방향키로 20px, Shift+방향키로 50px 조절하며 Home/End는 최소/최대 크기, 더블클릭은 기본 크기 복원이다. 선택한 크기는 브라우저에 저장하고 창 크기에 따라 최소 크기 범위 안으로 제한한다.

## LCU-009 요청 의도에 따른 PDF 전용 리포트

`공급업체1 PDF 보고서용으로 리포트 만들어줘`는 정적 PDF 모드로 생성한다. 탭, 필터, 입력, 접힌 내용 없이 모든 주요 캠페인·리스크·수치를 화면에 펼쳐 표시한다. 차트의 핵심 값은 카드·설명·표에도 표시하도록 생성 지침을 적용한다. 기존 PDF 저장 버튼은 동일한 Renderer 결과를 브라우저로 인쇄한다.

별도 모드 지정 없는 새 리포트는 인터랙티브 모드다. `다시 만들어줘`는 기존 모드를 유지하며, `PDF용으로 바꿔줘` 또는 `인터랙티브 리포트로 바꿔줘`는 재생성하면서 모드를 바꾼다. 모드는 공유 화면에도 유지된다.

## LCU-010 공급업체 질문의 Intelligent UI 답변

`공급업체1의 W1/W2 매출을 비교해줘`처럼 리포트 생성을 요청하지 않는 공급업체 질문은 원문을 조회해 채팅의 Intelligent UI로 답한다. 리포트가 없어도 작동하며, 기존 Canvas는 교체하지 않는다. 질문에 맞춰 카드·표·차트를 선택하고 공급업체 원문 근거와 계산값/원문 주장의 모순을 구분한다. 후속 질문은 마지막 공급업체 문맥을 사용하며 리포트 인용 질문은 해당 리포트의 공급업체를 사용한다. 없는 업체는 자료가 없다고 안내한다.

변경·검증: [PDF 모드와 공급업체 UI](../flow/2026-10-20-implementation-summary.md#pdf).

## LCU-011 첫 질문 템플릿

빈 대화에는 리포트 생성 4개, 공급업체 질문 3개, 범용 Intelligent UI 8개의 추천 질문을 표시한다. 리포트/공급업체 그룹은 펼쳐져 있고 일상·여행·인터랙티브 UI 그룹은 펼쳐서 선택한다. 버튼을 누르면 표시된 질문을 바로 전송한다. 범용 예시는 나들이, 도시 지도, 주말 아이디어, 식단, 계산기, Game Boy, 드럼 패드, 퀴즈를 포함한다.

원문 자료의 파일명과 조회 ID도 공급업체1~8에 대응하는 익명 표기를 사용한다. 이전에 생성한 대화/리포트에 남은 출처 표기는 새 대화에서 다시 생성하면 새 파일명을 사용한다.

## LCU-013 차트 해석과 서술형 보고서

리포트는 핵심 결론을 문단으로 먼저 설명하고 성과 해석, 시각적 근거, 위험, 권고 순서로 전개한다. 짧은 결론 2~3문장 뒤에 KPI 카드 4~6개, 핵심 차트 3~4개, 필요한 비교 표와 우선순위 조치 카드를 균형 있게 배치한다. 카드·Grid·상태 Badge를 적극 활용하되 중복 시각화는 피한다. 분석 차트 바로 아래에는 변화·비교의 의미와 근거·한계 또는 다음 확인 사항을 짧게 설명한다(리포트는 2~3문장, 일반 분석 답변은 2~4문장). 긴밀한 두 차트는 해석 문단을 공유할 수 있다. 이 지침은 일반/PDF 리포트, 공급업체 채팅 답변, 분석 차트를 사용하는 범용 UI에 적용한다. 원문으로 확인할 수 없는 원인은 단정하지 않는다.

## LCU-014 물류 데모 맥락

공급업체 자료는 아마존 FBA 물류를 가정한 샘플 시나리오다. 재고 보충은 FBA 재고 보충, 구매 박스는 추천 오퍼로 표시한다. 실제 아마존 실적이나 광고 기능의 정확한 재현을 뜻하지 않으며 기존 수치·통화·분석 기간은 유지한다.

## LCU-015 영문 리포트

`공급업체1 영문 리포트 생성해줘` 또는 `공급업체1 영문 PDF 보고서용으로 리포트 만들어줘`로 영어 본문을 생성한다. 첫 화면에 두 요청 버튼을 제공한다. 제목·설명·차트/필터 라벨·주의 문구를 영어로 작성하며, 원문 근거의 직접 인용과 출처 파일명은 원문을 유지할 수 있다. 통화는 원문의 KRW, 수치·기간·ID는 그대로 보존한다.

별도 언어 지정이 없는 새 리포트는 한국어다. 재생성은 현재 언어를 유지하고, `영문으로 다시 만들어줘` 또는 `한국어로 다시 만들어줘`로 언어를 바꾼다. thread당 하나의 리포트 정책에 따라 언어 변경도 기존 리포트를 교체한다. 공유 화면과 PDF에는 생성한 언어가 유지된다. 앱의 채팅/도구막대 전체 번역은 포함하지 않는다.
