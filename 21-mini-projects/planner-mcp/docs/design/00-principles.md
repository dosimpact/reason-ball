# 현재 설계 원칙

상태: 확정

이 문서는 현재 적용할 기술·코드 작성 원칙의 원본입니다. 변경 이유는
[변경 이력](../changes/README.md)에 기록하고 이 문서는 최신 내용으로 갱신합니다.

## 기술과 저장소

- Todo List MCP를 기반으로 확장하며 Next.js + TypeScript를 사용합니다.
- UI와 서버 기능은 같은 Next.js 프로젝트에서 관리합니다.
- 기존 pnpm workspace와 루트 lockfile을 공유하고 패키지는 비공개로 유지합니다.
- 초기에는 별도 DB 없이 서버 전용 데이터 디렉터리 하위 JSON 파일에 저장합니다.
- 데이터 파일은 공개 `public/` 자산으로 취급하지 않으며 실행 데이터는 Git에 커밋하지 않습니다.
- 데이터 경로·스키마·의존성 버전 등 미확정 세부 사항은 관련 설계에서 구체화합니다.

## 변경 감지

- UI·MCP 저장과 외부 파일 편집을 포함해 지정 데이터 디렉터리 하위 변경을 감지합니다.
- 서버는 SSE로 UI에 변경을 알리고 UI는 수동 새로고침 없이 최신 내용을 반영합니다.
- 저장, 파일 감시, SSE 전송, UI 반영은 책임을 분리합니다.

## FSD와 코드 작성

- 파일·디렉터리는 FSD(Feature-Sliced Design) 기반으로 구성합니다.
- 모듈 배치와 의존성은 [아키텍처](02-architecture.md), Flow Spec feature의 상세 경계는 [Flow Spec 설계](04-flow-spec.md)를 따릅니다.
- SLAP(Single Level of Abstraction Principle): 한 함수 안에서는 같은 추상화 수준의 작업을 다룹니다.
- 상위 함수는 흐름을 조합하고 세부 검증·변환·저장은 역할별 함수로 위임합니다.
- 저수준 검증·변환·계산은 같은 입력에 같은 결과를 반환하고 입력을 변경하지 않는 순수함수를 지향합니다.
- 파일·네트워크 입출력, 시각·ID 생성은 부수효과 경계로 분리하고 필요한 값을 순수함수에 전달합니다.
