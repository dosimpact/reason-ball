# 0002: Todo List MCP에서 이어갈 설계 원칙

상태: 확정

기록 유형: 기반 원칙을 도입한 과거 결정. 현재 적용할 원칙은 [현재 설계 원칙](../design/00-principles.md)을 참조합니다.

날짜: 2026-09-15

## 배경

Planner MCP는 Todo List MCP를 기반으로 기능을 확장합니다.
이 문서는 사용자가 지정한 계승 원칙을 기록하며, 기존 구현 전체를 검증한 보고서는 아닙니다.
기술 구성은 [참고 프로젝트 package.json](../../../todo-list-mcp/package.json)에서 확인했습니다.

## 결정

### Next.js와 TypeScript

- Next.js와 TypeScript를 사용합니다.
- UI와 서버 기능을 같은 Next.js 프로젝트에서 관리합니다.
- 기존 패키지의 구성과 스크립트를 구현 시 참고합니다. 의존성 버전과 개별 도구의 채택은 구현 준비 단계에서 결정합니다.

### JSON 파일을 초기 저장소로 사용

- 초기에는 별도 DB를 두지 않고 지정 데이터 디렉터리 아래 JSON 파일로 저장합니다.
- 여기서 정적 파일은 디스크에 지속되는 데이터 파일을 뜻합니다. 공개 배포용 `public/` 자산으로 취급하지 않습니다.
- 파일 입출력은 서버의 저장소 계층으로 모으고, 비즈니스 로직은 저장 방식과 분리합니다.
- 실제 데이터 경로, JSON 스키마 및 파일 분할 단위는 후속 설계에서 결정합니다.

### 디렉터리 데이터 변경을 SSE로 UI에 전달

- 서버가 지정 데이터 디렉터리 하위의 데이터 변경을 감지하고 SSE로 UI 클라이언트에 알립니다.
- UI, MCP를 통한 저장뿐 아니라 외부에서 이루어진 대상 JSON 파일 변경도 감지 범위에 포함합니다.
- UI는 페이지를 직접 새로고침하지 않아도 변경된 데이터를 반영해야 합니다.
- 파일 감시, SSE 전송, UI 반영을 분리하며 세부 이벤트 계약과 재연결 처리는 [아키텍처 초안](../design/02-architecture.md)에서 구체화합니다.

### FSD 기반 디렉터리 구조

- 파일과 디렉터리는 FSD(Feature-Sliced Design) 아키텍처를 기준으로 구성합니다.
- 기능 및 도메인별 책임과 모듈 의존성 경계가 디렉터리 구조에 드러나도록 설계합니다.
- Next.js 라우팅 디렉터리와 FSD 계층의 연결, 서버 전용 저장소·MCP·SSE 모듈의 배치는 후속 설계에서 확정합니다.
- 구체적인 계층과 슬라이스는 기능 범위에 맞춰 결정합니다.

### SLAP과 순수함수

- SLAP(Single Level of Abstraction Principle)을 준수합니다. 한 함수 안에서는 같은 추상화 수준의 작업을 다룹니다.
- 상위 함수는 흐름을 조합하고, 세부 검증·변환·저장은 역할별 함수에 위임합니다.
- 저수준 데이터 검증·변환·계산은 순수함수를 지향합니다. 같은 입력에 같은 결과를 반환하고 입력을 변경하지 않습니다.
- 파일 시스템, 네트워크, 시각, ID 생성처럼 외부 상태에 의존하는 작업은 경계 계층에 둡니다. 필요한 값은 순수함수에 입력으로 전달합니다.
- 저수준 함수라도 파일 입출력 자체는 순수하지 않으므로 부수효과 경계로 명시합니다.

## 영향

초기 저장소 운영을 단순하게 시작하고 핵심 로직을 파일 시스템 없이 검증할 수 있습니다.
대신 파일 저장의 동시성·복구와 변경 감지·SSE 재연결 정책을 설계해야 합니다.
쓰기 가능한 지속 디스크와 장기 연결을 지원하는 실행 환경을 고려해야 하며,
다중 서버 운영과 DB 전환은 필요성이 생기면 별도 결정으로 다룹니다.
