# UI 쓰기 응답 유실 복구

날짜: 2026-09-15
상태: 0017에서 발견한 재시도 계약의 UI 누락 보완.

후속: [0019](0019-usability-design-audit.md)에 전체 요구사항 대조와 최종 검증을 기록했다.

## 변경 전후와 이유

- 변경 전: 서버는 requestId 영수증을 보존하지만 일반 UI 폼은 응답 유실 뒤 재제출 시 새 ID를 생성했다. 의견의 경우 SSE가 현재 revision을 바꿔 재시도 본문도 달라질 수 있었다.
- 변경 후: 쓰기 시작 시 전체 본문을 복사하고 성공 또는 확정 오류가 돌아올 때까지 같은 비동기 작업을 유지한다. 네트워크 단절·30초 대기 초과·깨진 응답·서버 내부/저장 오류는 결과 미확인으로 표시한다. 사용자가 재시도를 눌러야 동일 본문을 다시 전송하며 자동 반복하지 않는다.
- 확인 대기 중에는 추가 저장과 프로젝트·문서 전환을 막고 페이지 종료를 경고한다. 이미 저장됐을 가능성을 안내하며 강제 취소를 저장 취소로 오인하게 하지 않는다.
- 입력·revision 충돌 등 확정 오류는 원래 폼에 반환해 수정할 수 있게 한다. 성공 이후 기존 폼 초기화·프로젝트 진입 동작은 한 번만 수행된다.
- 읽기 실패는 쓰기 재시도 대기 대상이 아니다. 브라우저 세션을 강제로 종료한 뒤 미확인 요청 복원은 추가하지 않았다.

## 영향 문서와 코드

- 현재 설계: [08](../design/08-mcp-storage-sse.md)의 재시도 계약, [11](../design/11-collaboration-ux.md)의 대기·복구 안내.
- `src/shared/api/client.ts`: 확정 오류/결과 미확인 구분, 요청 스냅샷과 명시적 재시도.
- `src/widgets/planner-workspace/ui/workspace.tsx`: 재시도 안내·저장 직렬화·페이지 종료 경고.
- 서버 저장 포맷과 MCP 도구 계약은 변경하지 않았다. 기존 데이터는 그대로 유지한다.

## 검증

- `tests/client.test.ts`: 정상 조회, 전송 실패 후 스냅샷 유지, HTTP 500·저장 실패·깨진 JSON·결과 누락, 확정 revision 충돌, 읽기 실패 구분.
- `tests/e2e/completion.spec.ts`: 실제 서버 저장 후 응답만 폐기 → 사용자 재시도 → 프로젝트·입력·의견 각각 하나만 존재. SSE로 revision이 바뀌어도 재전송 본문이 동일하고 의견 revision은 한 번만 증가한다.
- 단위 10개 파일·97개 PASS, lint/typecheck PASS.
- `pnpm --filter planner-mcp test:e2e`: 생산 빌드와 Chromium 18개 PASS (51.9초). 전용 서버 `127.0.0.1:63776`과 임시 데이터는 종료 시 정리했다.

## 비교 상태와 스킬

0017의 한정 비교 항목 중 재시도 Partial을 보완했다. 이 기록만으로 최초 설계 전체 재감사 완료를 주장하지 않는다.

- apb-unit-test-write: 공통 요청 함수의 정상·오류·경계 테스트 추가.
- apb-playwright-e2e: 전용 서버와 임시 데이터로 응답 유실을 주입했다. 외부 Playwright MCP가 없어 CLI Chromium을 사용했으며 서버 저장·MCP 조회는 실제 구현이다.
- codebase-memory: 함수 경계 검색 및 coverage 확인. 오래된 그래프 범위는 현재 소스를 읽어 보완했다.
