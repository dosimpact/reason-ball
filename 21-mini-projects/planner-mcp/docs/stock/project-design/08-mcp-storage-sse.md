# MCP·저장·SSE 계약

상태: 구현 기준. 이 문서는 기본 계약이며 실행 수치·파일 경로는 [09](../tech-shared/planner-mcp/implementation.md), 추가 기능은 [10](10-completion.md)을 따른다.

## MCP 작업 순서

프로젝트 조회 → 카탈로그·스키마 조회 → 문서 인덱스·본문 조회 → 수정안 검증 → 저장.

- 프로젝트가 없으면 생성하며 새 문서는 본문 조회 단계를 생략할 수 있습니다.
- 문서 본문 조회와 타입별 스키마 조회를 기본 기능으로 제공합니다.
- 검증은 저장하지 않고 오류를 확인하는 동작으로 분리합니다. 저장 시에도 동일한 검증을 다시 수행합니다.
- 사전 검증 성공이 이후 저장 성공을 보장하지 않습니다. 사이에 문서가 변경되면 충돌할 수 있습니다.
- 구현 에이전트의 승인 버전 조회는 [생명주기 설계](06-design-lifecycle.md)와 연결합니다.

## Revision과 동시 수정

- 문서는 revision을 가지며 갱신 요청은 읽었던 expectedRevision을 전달합니다.
- 저장 시 현재 revision과 다르면 충돌로 거부하고 최신 revision을 반환합니다. 자동 덮어쓰기나 자동 병합은 하지 않습니다.
- 비교 → 타입·내용 검증 → 저장을 같은 문서의 직렬화 구간에서 처리합니다.
- 초기 revision은 1, 성공한 문서 갱신마다 1 증가하는 정수로 사용합니다.
- 승인 등 문서의 의미 있는 메타데이터 변경도 revision 정책에 포함하는 정책을 사용합니다.
- 상태 전이·승인 대상 revision·역사 버전 메타데이터는 [06](06-design-lifecycle.md)·[09](../tech-shared/planner-mcp/implementation.md)를 따릅니다.

## 재시도와 중복 방지

- 생성·갱신 요청에 requestId를 사용하고 동일 요청의 재시도는 원래 결과를 반환하는 방식을 사용합니다.
- 동일 requestId에 다른 payload가 오면 중복 키 충돌로 거부합니다.
- 중복 요청 확인은 expectedRevision 충돌 검사보다 먼저 수행합니다. 이미 성공한 갱신의 재시도가 이전 revision 때문에 실패하지 않게 합니다.
- 문서 저장 후 응답 전달이 끊겨도 재시도로 중복 문서나 중복 revision이 생성되면 안 됩니다.
- UI 쓰기는 전송 시 요청 본문·requestId·expectedRevision을 복사해 고정한다. 응답 유실·해석 불가·서버 내부 오류는 결과 미확인으로 표시하고 사용자가 같은 요청을 재시도한다. 확인 전 추가 저장 및 프로젝트·문서 전환은 막고, 새로고침·탭 닫기는 경고한다. 확정된 입력·충돌 오류는 재시도 대기를 끝내 수정할 수 있게 한다. 화면 세션을 강제로 종료한 뒤의 미확인 요청 자동 복원은 제공하지 않는다.
- 중복 방지 기록은 재시작 후에도 복구되어야 합니다. pending 저널 → 이력·현재 파일 → done 영수증 순으로 저장하고 재시작 시 pending을 복구합니다.
- requestId는 데이터 디렉터리 전체 범위입니다. 키 순서를 정규화한 JSON 해시로 payload를 비교하고 파일 영수증을 자동 삭제하지 않습니다. 경로는 [09](../tech-shared/planner-mcp/implementation.md)를 따릅니다.

## 여러 문서 저장

- MVP에서는 문서별 저장 결과를 반환합니다. 여러 문서를 하나의 원자적 트랜잭션으로 보장하지 않습니다.
- 결과 항목은 documentId 또는 요청 항목 ID, 성공 여부, 성공 revision 또는 오류를 포함하는 방식을 사용합니다.
- 일부 실패 시 전체 성공처럼 표시하지 않고, 성공한 문서를 유지하며 실패한 항목만 재시도할 수 있게 합니다.
- 저장은 개별 도구 호출로 수행합니다. 배치 저장 도구는 제공하지 않으며 문서별 성공·실패를 반환합니다.

## 오류 모델

공통 오류에 code, message, 위치(path 또는 nodeId), 필요 시 expectedRevision/currentRevision과 재시도 안내를 제공합니다.

| 코드                                   | 의미                              |
| -------------------------------------- | --------------------------------- |
| PROJECT_NOT_FOUND / DOCUMENT_NOT_FOUND | 대상이 없음                       |
| UNKNOWN_DOCUMENT_TYPE                  | 미등록 문서 타입                  |
| SCHEMA_INVALID                         | 타입별 내용·문법 오류             |
| REVISION_CONFLICT                      | 읽은 버전과 저장 버전 불일치      |
| REQUEST_ID_CONFLICT                    | 같은 요청 ID에 다른 내용          |
| STORAGE_WRITE_FAILED                   | 저장 실패                         |
| SOURCE_FILE_INVALID                    | 외부 변경 파일이 읽기·검증 불가능 |

MCP 도구 오류는 isError=true와 text의 공통 오류 JSON으로 반환합니다. HTTP는 출처 거부 403, 대상 없음 404, 충돌 409, 내부 오류 500, 입력 오류 400으로 반환합니다.

## 파일 배치와 인덱스

프로젝트 메타데이터와 문서별 JSON 파일을 분리합니다. 기본 경로:

```text
<data-dir>/projects/<project-id>/
  project.json
  documents/
    <document-id>.json
```

- 이름·scope 대신 검증된 ID로 경로를 결정합니다. 요청으로 임의 파일 경로를 받지 않습니다.
- 임시 파일을 작성한 뒤 교체하는 방식으로 부분 JSON 노출을 줄입니다.
- 프로젝트 인덱스는 문서에서 도출해 메모리에 캐시합니다. 별도 수정 가능한 인덱스 파일은 두지 않습니다.
- 재시작 시 디스크에서 재구축하고 저장·외부 변경 후 영향을 받은 항목을 갱신합니다.
- 손상 파일이 있으면 빈 정상 문서로 간주하지 않고 인덱스 조회에도 문제 또는 오래된 상태가 있음을 알립니다.
- 승인 버전·입력 자료·요청 중복 방지 기록의 파일 배치는 [09](../tech-shared/planner-mcp/implementation.md)를 따릅니다.

## 외부 편집 지원 경계

- 데이터 디렉터리 하위 외부 JSON 변경의 감지와 재검증을 지원합니다.
- 파일 감시는 잠금이나 충돌 해결 수단이 아닙니다. 도구 밖에서 파일을 쓰면 서버 revision 계약을 우회할 수 있습니다.
- 외부 편집은 서버 쓰기가 없는 유지보수 구간에 수행합니다. 일반 수정은 MCP를 이용합니다.
- 외부 변경이 revision을 유지한 채 내용을 바꾼 경우도 감지하도록 마지막 정상 내용 해시와 비교하는 방식을 사용합니다.
- 외부 변경은 새 revision의 draft로 읽을 수 있으며 정상 저장 이력이 없으면 갱신·승인을 거부합니다. 승인 메타데이터는 이력과 일치할 때만 신뢰합니다.
- 서버 실행 중 외부 동시 쓰기를 무손실로 지원한다고 보장하지 않습니다. 외부 변경은 조회·진단 대상이며 정상 저장 이력과 다른 문서의 쓰기는 `EXTERNAL_EDIT_CONFLICT`로 거부합니다.

## SSE와 복구

- 변경 이벤트는 projectId, documentId, 변경 종류, document revision을 포함합니다.
- eventId는 연결 이벤트 식별자이며 문서 revision과 구분합니다. ready는 초기/재연결, change는 변경 알림입니다.
- 저장 성공 후 읽기 인덱스를 갱신하고 알림을 보냅니다. 실패한 저장을 성공 변경으로 알리지 않습니다.
- 삭제 알림의 revision은 삭제 대상 마지막 버전을 나타냅니다. 현재는 외부 파일 삭제 감지를 제공하며 삭제 도구는 제공하지 않습니다.
- 손상 파일은 정상 변경 이벤트 대신 오류 상태로 표시하며 알 수 없는 revision을 만들어내지 않습니다.
- UI는 알림을 받아 인덱스와 열린 문서를 다시 조회합니다. 중복 알림은 허용하고 오래된 응답은 최신 화면을 덮지 못하게 합니다.
- 최초 연결과 재연결 시 최신 인덱스·본문을 조회합니다. 이벤트 재생 로그에 의존하지 않는 복구를 기본으로 합니다.
- SSE 연결과 독립적으로 초기 조회합니다. ready·재연결·변경 알림에도 재조회하고 요청 세대로 오래된 응답을 무시합니다.
- 마지막 정상 화면을 유지할 경우 오래된 상태임을 명시합니다. 최초 조회부터 손상된 경우는 오류 화면을 표시합니다.
- 1초 디스크 재검사, 15초 heartbeat, 연결 종료 시 구독·타이머 정리를 수행합니다.

## 운영 기본값

- 개인 로컬 단일 서버, 사용자가 선택한 승인 revision 묶음, 외부 변경 감지와 동시 쓰기 제한은 [09](../tech-shared/planner-mcp/implementation.md)를 따릅니다. 사용자 인증은 제외합니다.

## 검증 기준

- 같은 revision에서 시작한 두 갱신 중 뒤의 요청은 충돌하고 첫 저장을 덮어쓰지 않습니다.
- 저장 후 응답 유실·프로세스 재시작 상황의 재시도가 중복 문서·revision을 만들지 않습니다.
- 여러 문서 중 일부 실패 시 성공과 실패가 문서별로 구분됩니다.
- 캐시 재구축 결과가 유효한 디스크 문서 집합과 일치합니다.
- SSE 중복·연결 해제·재연결·조회 응답 순서 역전 후 UI가 최신 정상 상태로 수렴합니다.
- 외부 손상 JSON은 오류로 표시되고 마지막 정상 상태와 혼동되지 않습니다.
