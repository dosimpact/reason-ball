# 로컬 기능 완성과 Figma 연동

상태: 구현됨. 사용자 요청: 설계의 미완성 기능과 테스트를 완성하고 Figma 연동을 포함하며 사용자 인증은 제외한다.
아래 세부 계약은 이 요청을 실행하기 위한 구현 기본값이다.

## 범위와 책임

- 00~09의 기존 로컬 계약을 유지하면서 문서 관계·버전 비교·Flow 노드 편집·Figma 수집을 추가한다. 본 문서는 이 추가 기능의 계약 원본이다.
- 사용자 인증, 원격 팀 운영, 외부 코드 생성·실행, 서버와 외부 파일의 무손실 동시 쓰기는 범위 밖이다.
- 프로젝트·문서 삭제, 범용 첨부 파일, 고정 7종 문서 카탈로그의 런타임 편집, 엄밀한 실행 분기 언어는 기존 미채택 아이디어이며 이번 추가 기능에 포함하지 않는다.

## 프로젝트 목록 화면

- 프로젝트를 선택하지 않은 중앙 화면에는 전체 프로젝트의 이름·설명과 열기 버튼을 표시한다. 사이드바 목록도 유지한다.
- 프로젝트 선택 후 `전체 프로젝트` 버튼으로 목록에 복귀한다. 목록은 기존 SSE 갱신 결과를 공유하며 모바일에서도 사용할 수 있다.
- 최초 조회 중에는 로딩을 표시하고, 조회 성공 후 프로젝트가 0개일 때만 시작 안내를 표시한다. 조회 실패는 오류와 재시도 버튼으로 안내한다.

## 문서 관계와 버전 비교

- Flow Detail은 같은 프로젝트의 Overview를 선택적으로 참조한다. `overviewDocumentId`, `overviewRevision`, 선택적 `overviewNodeId`를 저장한다.
- revision이 없는 기존 참조는 다음 저장 시 현재 Overview revision으로 고정한다. 노드만 지정한 참조·자기 참조·잘못된 타입·없는 문서/버전/노드는 거부한다.
- API의 `baseDocumentId`와 `baseRevision`은 같은 프로젝트·같은 API 타입의 실제 역사 버전을 참조한다.
- 관계 조회는 나가는 참조·들어오는 참조와 기준 버전 이후 변경/손상 여부를 반환한다. 변경은 재검토 안내이며 기존 승인을 자동 취소하지 않는다.
- UI와 MCP에서 고정 버전 조회·관계 이동·JSON 경로별 추가/삭제/변경 비교를 제공한다. 역사 버전에는 수정·승인 동작을 제공하지 않는다.

## Flow 편집과 UI 상태

- 문서 ID별 접힘 상태는 워크스페이스 수명 동안 문서·탭 이동에 유지한다. 새로고침은 초기화한다. SSE 후 삭제되거나 자식이 없어진 노드는 상태에서 제거한다.
- 단계/메모 추가·이름 변경·삭제·이동은 순수 트리 함수로 처리한다. 이동은 ID를 유지하고 자기 자신/자손 이동과 잘못된 부모를 거부한다. 계층은 편집하지 않는다.
- UI와 MCP가 동일한 저장 경계, requestId 중복 방지, expectedRevision 충돌 검사를 사용한다. 편집은 새 draft를 만들고 승인 이력은 유지한다.
- 새 ID는 외부 경계에서 공급한다. 과거에 삭제된 노드 ID 재사용은 거부한다.
- 질문의 해결 여부·답변·차단 여부를 UI에 표시한다. 답변의 설계 반영은 기존 MCP 저장 흐름을 따른다.

## Figma 읽기 연동

- 서버의 `FIGMA_ACCESS_TOKEN`(개인 액세스 토큰, `file_content:read`)으로 Figma REST API를 호출한다. 토큰은 브라우저·MCP 인자·저장 데이터로 전달하지 않는다.
- `https://www.figma.com/design/<key>/...` 또는 `/file/<key>/...`과 선택적 `node-id`를 받는다. 서버는 고정 `api.figma.com`만 호출하고 리디렉션을 따르지 않는다.
- 파일 또는 선택 노드를 깊이 제한으로 가져와 응답 JSON, Figma 파일 버전·수정 시각·조회 깊이를 Project.sources 원문에 보존한다. 수집 시각과 원본 링크를 함께 보존하며 이전 입력은 덮어쓰지 않는다.
- UI `입력 자료` 및 MCP `import_figma`에서 같은 수집 서비스를 사용한다. 가져오기 결과를 AI가 해석해 Figma Requirements를 작성하며 추측한 요구사항을 자동 확정하지 않는다.
- 미설정 토큰·403·404·429·서버 오류·타임아웃·잘못된 응답·크기 초과를 구분한다. 429는 재시도 안내를 제공하고 자동 반복 호출하지 않는다.
- 같은 requestId 재시도는 재수집 없이 기존 저장 결과를 반환한다.

## 검증 기준

- 순수 함수: 비교 경로·배열 순서·입력 불변성, Flow 각 편집과 잘못된 이동·부모·크기 경계.
- 저장소: 관계의 프로젝트/타입/버전/노드 검사, 기존 데이터 호환, 편집 충돌·중복·재시작·승인 이력, 참조 변경 알림.
- Figma: 파일/노드 URL, 토큰 비노출, 오류·제한·타임아웃, 중복 수집 방지. 외부 API 응답은 결정적 모의 응답으로 검증한다.
- 브라우저: 문서/탭 왕복 접힘, SSE 상태 정리, 관계 이동·역사 버전·비교, 노드 편집·충돌, 질문 상태, Figma 가져오기 성공/실패.
- test/lint/typecheck/생산 빌드/E2E 및 문서 링크 검사를 완료한다. 실계정 Figma 검증은 토큰 가용 여부와 별도로 기록한다.
