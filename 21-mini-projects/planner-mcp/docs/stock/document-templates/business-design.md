# 문서 템플릿 비즈니스 설계

상태: 사용자 요구 채택. 원본은 [human-input/design.md](../../human-input/design.md).

## 요구사항

- TPL-001: 사용자는 프로젝트와 독립적인 공용 문서 템플릿을 생성·조회·수정·삭제한다.
- TPL-002: 템플릿마다 AI 사용 프롬프트를 편집·저장하며 AI는 조회 시 함께 받는다.
- TPL-003: Markdown 본문과 Mermaid 코드 블록을 기본 지원한다. 이름·내용을 지정해 새 종류의 템플릿을 코드 수정 없이 추가한다.
- TPL-004: 템플릿 viewer, example viewer, prompt management를 제공한다.
- TPL-005: REST와 MCP에서 목록 및 template name으로 상세를 조회한다.
- TPL-006: 향후 graph/React Flow 표시를 추가할 수 있도록 표시 형식과 템플릿을 분리한다. 두 뷰어 자체는 이번 범위가 아니다.

## 관리 규칙

이하 세부사항은 요청을 실행하기 위한 구현 기본값이다.

- 고유 이름(name)은 소문자 영문·숫자·하이픈, 최대 80자. 생성 후 식별 이름은 유지하고 제목·설명·본문·예시·프롬프트를 수정한다.
- 템플릿 본문·예시·사용 프롬프트는 필수다. 예시는 렌더링된 결과와 원문을 모두 확인한다.
- 삭제는 UI에서 대상을 확인한 뒤 수행하며 기존 프로젝트 설계 문서를 삭제하지 않는다.
- 초기 템플릿 목록은 비어 있다. 기존 고정 7종 문서 카탈로그는 구조화된 설계 문서의 호환 계약으로 유지한다.
- 템플릿 저장은 프로젝트 문서 생성이나 AI 실행을 뜻하지 않는다. AI가 템플릿·예시·프롬프트를 조회해 작성에 사용한다.
- 충돌이나 저장 결과 미확인은 사용자 입력을 유지하고 명시적으로 안내한다.

수용 시나리오는 [검증 기준](../../validation/INDEX.md)의 TPL-SC-001~006을 따른다.
