# 템플릿 관리

상태: 핵심 기능 구현. [MCP·REST 계약](../tech-shared/interfaces.md)에서 입력과 도구 목록을 확인합니다.

- 식별자: `template-management`
- 책임: 문서 양식, 기본 체크리스트, 예시, AI 작성 지침 관리·조회.
- 근거: [시스템 설계의 DEC-001](../tech-shared/system-design.md), [통합 비즈니스 설계](../project-design/business-design.md).

- 템플릿 본문·작성 예시는 `템플릿 미리보기` 버튼으로 여는 모달에서 확인합니다. 편집 화면에는 미리보기를 상시 펼쳐 두지 않습니다.

- 템플릿 라이브러리와 편집 영역을 분리하고 선택 상태·저장 결과를 표시합니다. 다른 템플릿/화면으로 이동 시 미저장 변경을 확인합니다. 미리보기·삭제는 shadcn Dialog로 제공합니다.

## 전용 설계·검증 템플릿

- 설계-검증 View: React 컴포넌트 메타 정보·Props·상태·접근성·Storybook 스토리와 AI/사람 검증 절차.
- 설계-검증 API: 서버 프레임워크·라우트·요청/응답·오류·업무 규칙·Bruno 실제 호출 검증 절차.
- 설계-검증 E2E: 사용자 여정·Given/When/Then·브라우저 환경·Playwright MCP/Chrome CDP 검증 절차.
- 각각 본문·작성 예시·AI 지침·기본 체크리스트 3개 제공. AI 결과와 사람 확인은 기존 정형 체크리스트 필드로 기록.
- 기존 공통 view/api/e2e는 보존하고 새 식별자 design-verification-view/api/e2e로 추가. 저장소별 1회 초기화하며 수정된 양식과 삭제된 양식을 재시작 때 복원하지 않음. 이미 인스턴스화한 문서는 변경하지 않음.

## 확장 목록 (REQ-012, 구현)

- 템플릿에 확장 목록(extension list)을 지원하며 첫 종류는 React Flow Diagram View입니다.
- 템플릿의 확장 초기값을 문서 생성 시 복사하고, 이후 문서 관리에서 확장을 추가할 수 있습니다.
- 기존 템플릿 인스턴스 원칙을 동일 적용합니다. 원본 확장을 수정해도 이미 생성한 문서의 확장은 바뀌지 않습니다.
- 데이터와 UI/MCP 요구는 [문서 확장 설계](../document-management/INDEX.md)를 따릅니다.

- 저장 footer와 삭제 영역은 32px 여백으로 분리합니다. 저장된 템플릿의 삭제는 붉은 테두리·배경의 별도 Danger zone에 배치하며 기존 삭제 확인 Dialog를 유지합니다.

- 템플릿 본문·작성 예시·AI 작성 지침에 문서와 같은 Notion 스타일 Markdown 편집기를 사용합니다. `/` 블록 메뉴, 서식 도구, →/← 목록 들여쓰기, 원문·미리보기 모드를 제공합니다.

## CodeWeave 확장

- 확장 영역의 CodeWeave 추가 버튼으로 여러 개를 첨부하고 제목·원문을 편집합니다. React Flow와 같은 문서에 혼합할 수 있습니다. 저장 버튼으로 확정합니다.
- 들여쓰기 트리와 변경 표시·주석을 렌더링하며 전체/가지 접기·펼치기, 라인 상세 정보를 제공합니다. 문법 오류는 해당 라인을 표시하고 저장을 거부합니다.
- 템플릿 미리보기·인스턴스 복사·revision·reopen 정책은 기존 확장과 같습니다. [core 및 어댑터 계약](../codeweave/INDEX.md)을 참고합니다.
