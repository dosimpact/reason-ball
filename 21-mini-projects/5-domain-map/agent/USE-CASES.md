# 요청별 완료 조건

| 요청 | 수행 | 완료 조건 |
| --- | --- | --- |
| 여러 레포를 처음 파악 | bootstrap: scout → modeler → 필요 audit → renderer | 모든 입력 상태, 큰 업무 블록·관계·근거·질문, 모델 등록·체크포인트 |
| 예산 종료 후 이어가기 | continue: show/resume → pending/partial | 완료 조사 재사용, 미완료 배치 진행, 다음 큐 보존 |
| 결제 실패 흐름 상세화 | deepen: auditor → modeler | 선택한 시나리오의 요청/판단/쓰기/외부 계약과 미확인 경계 |
| 지난 조사 이후 변경 확인 | refresh: change-reviewer → 필요한 역할 | 변경 검토 결과 등록. 모델이 달라지면 새 버전, unchanged면 기존 버전 유지 |
| 도메인 지도로 출력 | renderer | 등록 모델의 LikeC4 DSL·근거 보고서, 문법/빌드/브라우저 상태 |
| 접근 불가 레포 포함 | scout | inaccessible와 이유, 가능한 레포 조사 계속, 전체 완료로 오인하지 않음 |
| 지침만 수정 | 관련 문서 편집 | 실제 분석이나 기본 data 생성 없이 지침과 관련 stock/flow 동기화 |

작업 정보가 없다면 workItems=[]다. 어떤 흐름도 담당자·현재 작업·미확인 연결을 임의로 채우지 않는다. 입력 전체 초기 조사를 마친 비율은 기업 도메인의 의미적 이해도로 바꾸지 않는다.
