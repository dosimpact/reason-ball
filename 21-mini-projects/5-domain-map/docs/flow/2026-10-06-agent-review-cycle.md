# 2026-10-06 — 서브에이전트 평가와 개선 사이클

## 요청과 범위

사용자가 도메인 조사 에이전트의 서브에이전트 평가와 평가 기반 개선 사이클을 요청했다. 기존 사용자 변경을 보존하며 agent/의 지침·CLI·테스트와 관련 stock 문서만 개선한다.

## 평가 방식

1. workflow_review: 진입점부터 역할·계약·완료 조건을 독립 검토한다.
2. cli_review: 상태 전이·버전·무결성·입력 검증을 검토하고 임시 저장소에서 재현한다.
3. behavior_eval: 임시 Git 저장소 2개를 만들어 bootstrap(1개 예산) → continue → deepen을 실제 역할 지침과 CLI로 실행한다. 합성 저장소 행동 평가이며 실제 기업 분석이 아니다.

평가자는 제품 파일을 수정하지 않는다. 메인이 지적 사항을 재현하고 회귀 테스트와 수정을 적용한 뒤 같은 평가자에게 재평가를 요청한다. 기존 CLI 테스트 10개가 통과한 상태에서 시작했다.

## 결과

1. 두 독립 검토자가 clean→dirty 전환 시 과거 근거의 hash 요구와 불변 규칙이 충돌해 refresh가 막히는 문제를 재현했다(REV-01). 직전 모델로 과거/신규 근거를 구분하고 model put/doctor/독립 validate에 동일하게 적용했다.
2. CLI 검토자가 빈 path와 URL을 함께 넣어 등록 불가능한 세션을 만드는 문제를 재현했다(REV-02). 입력에 정확히 한 source 필드만 허용하도록 수정했다.
3. 변경 없는 refresh의 새 버전 요구를 제거하고 정상 완료 기준을 명시했다(REV-03). 시스템의 업무 영역 연결은 명시적인 supports 또는 미확인 질문으로 남기도록 통일했다(REV-06).
4. 행동 평가 권고에 따라 예산 집계 기준·배치 이력, 역할 결과의 delta/snapshot/derived·baseModelVersion, audit 최소 형식·반환 계약 링크를 보완했다(REV-04/05).
5. hash 형식과 문자열 배열 원소 검증을 보강했다(REV-07).

## 재검증과 판정

- 전체 CLI 회귀 테스트 **14/14 PASS**, 역할 스킬 6개 검사 PASS, 코드 구문·링크 검사 PASS.
- cli_review: 원 지적 2건의 별도 임시 CLI 재현에서 해결 확인. 과거 근거 변조/신규 dirty hash 누락은 계속 거부됨을 확인.
- workflow_review: clean→dirty→clean, dirty hash 거부, unchanged 완료 테스트 3개 독립 실행 PASS. 원 지적과 소속 표현 개선 확인.
- behavior_eval: 최초 **47회 성공/0회 실패**에서 지침 공백을 제안했고, 개선 후 새 합성 Git 저장소 2개로 **56회 성공/0회 실패**, 모델 **v1~v3**, doctor PASS를 확인했다. 6개 작업의 반환 계약, 세 배치의 읽기 범위·예산 artifact, 문서/코드 충돌과 소속 미확인 보존을 확인했다.
- [최종 평가 보고서](../../agent/evaluation/REVIEW-CYCLE.md)에 발견·수정·재평가 표와 원시 평가 요약을 저장했다.

개선 사이클 완료. 검토 범위 내 미해결 차단 결함은 발견되지 않았다. 실제 기업 분석, 대규모 입력, LikeC4 문법·빌드·브라우저는 미검증이며 예산 자동 계측/역할 결과 의미 검증은 CLI 구현 범위가 아니다. accepted 변경은 관련 stock에 반영했다.
