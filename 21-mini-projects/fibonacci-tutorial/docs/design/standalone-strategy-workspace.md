# 독립 전략 작업 공간 — SM-002 / SM-003

날짜: 2026-09-27. 상태: 구현 완료.

## 제품 계약

튜토리얼 유닛이나 수료 조건 없이 `/monitoring` → `/monitoring/new` → `/monitoring/[strategyId]`에서 전략을 작성·확정·검증한다. 기존 학습 세션 JSON과 실행 동작은 유지한다.

전략(strategyId), 불변 계획(planId/revision), 검증 실행(runId)을 분리한다. 초안 수정과 확정 원본 변경은 구분하며 원본 변경은 새 revision이다. 한 계획의 여러 실행은 각각 상태·이벤트·평가를 보존한다. 작성 상태, 실행 제어 상태, 매매 상태는 별도 필드다.

## 데이터와 시간

- BACKTEST: 과거 기준 시점까지의 데이터로 계획을 확정한다. 서버가 이후 고정 구간을 보존하고 클라이언트에는 현재 공개 범위만 전달한다. 한 봉 재생과 일괄 실행은 같은 입력·순수 상태 머신을 사용한다.
- FORWARD: 계획 확정 당시 최신 확정봉을 기준으로 이후 새 확정봉만 관측한다. 초안이 오래되어 기준봉이 바뀌면 사용자에게 재검토를 요구한다. 더미 입력은 실제 시장 관측과 구분하여 시뮬레이션으로 표시한다.
- 과거 계획을 현재 시장에 적용할 때 새 데이터 기준으로 revision을 확정한다. 다른 기간의 결과를 같은 조건으로 표현하지 않는다.
- Binance 공개 API·캐시를 재사용하고 요청 범위·봉 연속성·해시·최대 4000봉을 검증한다. 실패 시 더미로 대체하지 않는다.
- 감시 중지는 모의 청산과 다르다. 자동 감시는 상세 화면에서 시작한 동안만 동작하며 이동/닫기 뒤 저장된 마지막 관측 시점에서 명시적으로 재개한다.

## 계층과 재사용

`entities/strategy`에 독립 스키마와 순수 변환을 둔다. `server/strategies`는 데이터 로드·저장·직렬화·충돌 검증을 담당한다. `/api/strategies`가 별도 HTTP 경계다. `views/strategy-workspace`와 관련 feature는 사용자 흐름을 조합한다.

기존 `entities/strategy-monitor`의 순수 상태 머신을 재사용한다. 차트는 필요한 가격·규칙 필드만 받고 모니터링 패널은 plan ID·revision만 받도록 타입을 줄인다. 독립 전략을 표시하려고 가짜 unitId/sessionId를 만들지 않는다. 기존 튜토리얼 계약은 호환한다.

## 체결 및 결과

long 매수 스톱, 수량 1, 수수료·슬리피지 0이며 갭 시가 체결과 OHLC 순서 불명 정책은 기존 SM-001을 따른다. 구간 종료에서 미진입은 EXPIRED, 보유는 OPEN/미청산으로 남긴다. 제어 상태 COMPLETED는 반드시 청산을 의미하지 않는다.

실행별 데이터 방식·구간·정책·관측 수·진입/청산·실현/미실현 손익과 R·무효화/중단 이유·이벤트를 제공하고 JSON으로 내보낸다. 단일 결과로 승률·수익성을 주장하지 않는다.

| --- | --- | --- |
| SM-002-01 | 목록이 비어 있을 때 새 전략 작성 후 저장하면 목록과 상세에서 복원된다 | UI + API |
| SM-002-02 | 독립 초안에 파동·가격·규칙을 넣고 확정하면 가짜 학습 ID 없이 불변 계획이 저장된다 | API + 저장 스키마 |
| SM-002-03 | 같은 버전에서 동시 mutation 또는 오래된 요청을 보내면 한 요청만 반영된다 | API 경합 검사 |
| SM-002-04 | 실행 상태를 저장한 뒤 서버 재시작하면 원본·이벤트가 복원된다 | 소유 서버 재시작 검사 |
| SM-003-01 | 과거 기준 시점을 정한 초안을 조회/내보내면 이후 캔들이 노출되지 않는다 | API + UI |
| SM-003-02 | 같은 계획·스냅샷을 재생과 일괄 실행하면 매매 결과가 동일하다 | 단위 + API |
| SM-003-03 | 포워드 계획 이후 새 확정봉이 없으면 대기하고 같은 봉을 재조회해도 이벤트가 늘지 않는다 | stub API + 단위 |
| SM-003-04 | 포워드 감시를 시작/중지/재개하면 타이머가 정리되고 새 봉만 처리한다 | UI + API |
| SM-003-05 | 초안 이후 시장 기준봉이 바뀌면 확정에 재검토가 필요하다 | 단위/제어된 시장 API |
| SM-003-06 | revision·run을 추가해도 이전 계획과 실행을 덮어쓰지 않는다 | API + UI |
| SM-003-07 | 무효화·수동 중단·구간 종료에서 상태와 평가가 규칙을 따른다 | 순수 함수 + API |
| SM-003-08 | 데이터 누락·오류·범위 초과이면 명시적으로 오류를 표시한다 | API + Storybook |
| SM-003-09 | 라이트·다크·모바일에서 목록/작성/상세를 조작할 수 있다 | 브라우저 + Storybook |

실행 증거와 최종 판정은 [독립 전략 검증](../validation/standalone-strategy.md)에 기록한다.
