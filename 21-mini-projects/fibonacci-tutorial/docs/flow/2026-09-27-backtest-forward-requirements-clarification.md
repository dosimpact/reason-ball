# 계획 이후 두 검증 흐름의 요구사항 명확화

날짜: 2026-09-27. 결정 ID: SM-003. 상태: 문서 반영 완료.

## 맥락과 변경

사용자가 독립 전략 페이지에서 계획 이후 백테스팅과 포워드 테스팅을 모두 지원하도록 요청했다. 기존 SM-003의 데이터·실행 정책을 유지하면서 두 사용자 흐름을 명시하고, 백테스트 완료가 포워드의 선행 조건이 아님을 확정했다. 백테스트 후 포워드로 전환하면 현재 공개 데이터로 새 계획 revision을 확정하고 별도 실행으로 보존한다.

## 이유

과거 구간 재생과 계획 확정 이후 관측을 명확히 구분하면서, 사용자가 필요한 검증 방식으로 직접 진입할 수 있게 한다. 서로 다른 시점의 결과를 같은 조건의 실험으로 표현하지 않는다.

- [시스템 설계](../stock/system-design.md)의 실행·시간·데이터 계약

## 검증과 후속

문서 간 두 흐름, 선택 시점, revision/run 분리와 상대 링크를 점검했다. 이번 변경은 요구사항 문서에 한정하며 런타임 검증 결과를 새로 주장하지 않는다. 구현 검증에서는 백테스트 이력 없이 포워드로 직접 진입하는 시나리오도 확인한다. 기존 완료된 변경 기록은 보존했다.
