## 파동·Fibonacci

6점 상승 Impulse는 시간순 지점, 상승·조정 구조와 세 규칙을 검증합니다. Wave 2는 시작 가격과 같을 수 있지만 더 낮을 수 없습니다. Wave 3이 1파·5파보다 **엄격히 짧을 때** 실패합니다. Wave 4 저가가 Wave 1 고가에 닿으면 일반 Impulse의 겹침으로 실패합니다. 균등·교대는 힌트이며 판정 규칙은 아닙니다. 이 연습의 표준 상승 구조에서 Truncated Wave 5와 Diagonal은 다루지 않습니다.

3점 매매 기준은 시작점·1파 고점·2파 저점의 유효한 상승과 반등을 요구합니다. Fibonacci 38.2%·50%·61.8% 되돌림과 1.618 확장은 선택한 기준점의 **후보 가격**으로 보여주며 예측 확정값이 아닙니다. 상세 예시는 [유닛 시나리오](../tutorials/07-unit-scenarios.md)에 둡니다.

## 계획·관찰·회고

- Replay 전에 Entry, Stop Loss, Target, 판단 이유를 입력합니다. 서버는 공개 범위, 0–2파 관계, `0 < Stop Loss < Entry < Target`을 검증합니다. 카운팅 무효화 가격과 사용자 손절가는 서로 다른 개념입니다.
- 확정 계획은 판단 시각, 당시 공개 캔들 스냅샷, Fibonacci 근거, 평가 정책과 함께 보존됩니다. 확정 기록을 바꾸지 않고 새 revision을 이전 계획에 연결할 수 있습니다. 이력과 JSON 내보내기로 원본 계획·평가를 다시 살펴볼 수 있습니다.
- Replay는 고정 시나리오를 한 봉씩 공개하고 계획 이후 봉만 평가합니다. `market-lab`의 Binance 선택 시 새 확정봉으로 나중 시장 평가를 추가할 수 있습니다. 새 평가는 이전 평가를 덮어쓰지 않습니다.
- `touch-v1`은 상승 매수 스톱 진입, 갭의 시가 체결, 수수료·슬리피지 0을 가정합니다. OHLC만으로 진입·청산 또는 손절·목표 순서를 알 수 없으면 `판정 불가`입니다. 미진입은 `대기` 또는 시나리오 종료 시 `expired`, 미청산 보유는 `open`으로 표시하며 종료 종가로 강제 청산하지 않습니다. 진입·청산이 정해지면 R과 수익률을 보여줍니다.
- Replay 종료 뒤 `close` 또는 `hold`와 이유를 기록해 5파 이후 조정 가능성을 회고합니다. 회고는 과거 모의 체결 결과를 바꾸지 않습니다. 이 입문 흐름에서는 ABC 카운팅을 요구하지 않습니다. 심화 챕터에서 조정파를 별도로 다루며, 5파 끝 자동 익절과 실제 주문은 구현하지 않습니다.

## 데이터와 제품 경계

재현 가능한 더미 시나리오와 `market-lab`의 공개 Binance Spot(`BTCUSDT`·`ETHUSDT`, `1h`·`4h`·`1d`)을 지원합니다. 세션 시작 시 데이터와 공개 범위를 고정하고 미래 캔들·예시는 허용 시점 전에 전달하지 않습니다. Binance 오류 시 조용히 더미로 전환하지 않습니다. 평가 조회는 현재 한 번에 최대 4000봉으로 제한되며, 그보다 긴 기간은 후속 확장 과제입니다.

앱은 인증·공유 계정·실거래 주문이 없는 로컬 단일 서버와 JSON 저장 범위입니다. 세션 ID를 가진 사람이 해당 기록을 열 수 있습니다. 다중 서버 동기화, 백업, 장기 운영용 데이터 이전은 제품 범위에 포함되지 않습니다.


## 선택 즉시 피드백과 완료 기록

6점 선택이 끝나면 공개 캔들 기반 규칙 결과를 즉시 표시합니다. Check Answer는 서버에서 다시 검증하고 저장합니다. 완료 목록은 기존 브라우저 기록과 새 완료 유닛을 합쳐 유지하며 재방문으로 이전 완료를 지우지 않습니다. [원본 계획 완료 감사](../validation/completion-audit.md)를 참조합니다.


## 확정된 콘텐츠 확장 방향 — CUR-EW-001

서비스의 학습 주제는 **엘리엇 파동이론 기술적 분석 단일 과정**입니다. 일반 기술적 지표·투자·자동매매 과정으로 확장하지 않습니다. Fibonacci·채널·계획·평가는 파동 해석과 검증에 필요한 범위에서 다룹니다.

[전체 커리큘럼](../tutorials/elliott-wave/curriculum.md)은10챕터44유닛으로 확정했습니다. 기존 C01–C03의9유닛과 C04–C10의35유닛을 모두 제공합니다. 심화 범위는 파동 측정, Impulse 변형, ABC, Triangle/복합 조정, Diagonal, 차수·대안 카운팅, 분석 계획·재평가입니다. 기존 입문 validator의 의미를 보존하면서 심화 분석 과제와 별도 규칙 정책을 추가했습니다.

신규 유닛의 데이터 프로필·과제·완료 증거는 챕터 명세와 공통 학습 계약을 따릅니다. 실전 카운팅은 단일 정답을 강제하지 않고 객관 규칙과 해석 근거를 분리합니다. 과정 수료는 분석·평가·회고를 요구하며 수익률을 기준으로 삼지 않습니다.

## 심화 학습과 완료

신규 이론13개는 5단계 설명·차트와 확인 질문3개를 제공합니다. 마지막 단계에서 2개 이상 정답이어야 완료됩니다. 신규 연습22개는 기본·반례·평가 변형을 제공하며 Impulse 감사·Flat·Diagonal 비교에는 추가 사례가 있습니다. 총69개 사례에서 객관 검증과 자기 점검을 분리합니다. 분석 과제의 자기 점검은 5항목 각0–2점, 합계8점 이상이고 0점이 없어야 통과합니다. 전문가가 해석의 정확성을 인증하는 점수가 아닙니다.

과거 데이터·Replay 과제는 사례마다 분석 원본 확정, 이후 봉의 관측, 평가와 회고가 있어야 유닛 완료가 됩니다. 확정 이후 수정은 새 revision으로 남깁니다. 실전 후속 유닛은 실제로 새 확정봉이 생길 때까지 대기합니다. 최종 포트폴리오는 서로 다른 세 과거 구간을 자유롭게 오가며 각 구간의 분석·평가·회고를 모읍니다. 모든 유닛의 완료 이력으로 과정 진행률을 표시합니다.

H/HR은 Binance의 세 과거 구간을 고정 원본으로 보존하고 M은 같은 UTC20일의 1h480·4h120·1d20봉을 사용합니다. 초기 공개는 각각80/120, M240/60/10봉입니다. 실전 자료에서 특정 파동 패턴이나 단일 정답을 보장하지 않습니다.

## 전략 실행 모니터링

매매 계획을 확정하면 해당 JSON의 진입·손절·목표와 별도 파동 무효화 조건을 매 봉 확인한다. 기본 자동 중단은 미진입 주문을 취소하거나 보유 포지션을 모의 청산한다. 학습자는 경고 전용 정책을 선택하거나 이유를 기록해 수동으로 중단할 수도 있다. 4파 겹침 규칙은 공개된 3파 끝점을 명시한 경우에만 설정한다.

차트의 보라색 무효화선과 실행 이벤트, 패널의 정상/경계 접근/파동 전제 훼손 상태를 함께 본다. 현재가는 마지막 확정봉 종가이며 관측 UTC 시각을 표시한다. Binance 자동 감시는60초마다 새 확정봉을 확인하고 사용자가 중지할 수 있다.

실행 모니터링의 조기 청산 손익과 가격 조건만 적용한 기존 비교 평가는 구분한다. 동일 봉 내부의 선후를 알 수 없으면 임의 체결 결과를 만들지 않는다. 원본 계획·실행 이력·사후 평가를 JSON으로 내보낼 수 있으며 실제 주문은 보내지 않는다.

## 독립 전략 작업 공간 — SM-002

튜토리얼 없이 `/monitoring`에서 전략 목록을 열고 `/monitoring/new`에서 시장·검증 방식을 선택한다. `/monitoring/[strategyId]`에서 공개 차트의 파동점, 진입·손절·목표·무효화 조건과 판단 이유를 작성·저장·확정한다. 일부 선택과 빈 근거도 초안으로 저장해 다시 작성할 수 있다. 튜토리얼 진도·정답·수료와 독립적이다.

확정 원본은 수정하지 않으며 새 revision을 만든다. 이전 계획과 실행별 평가·이벤트는 이력에서 확인하고 JSON으로 내보낸다. 감시 일시정지와 미진입 취소·모의 청산을 구분한다. 무효화 기본 동작은 자동 중단이며 경고 전용도 지원한다. Primer 라이트·다크와 모바일 화면을 공통 사용한다.

## 독립 전략 백테스트·포워드 — SM-003

확정된 제품 요구는 **계획 → 백테스팅 → 평가**와 **계획 → 포워드 테스팅 → 평가**를 모두 독립적으로 지원하는 것이다. 백테스트 완료 없이 포워드 계획을 작성할 수 있다. 검증 방식은 계획 작성 시 선택하고, 확정 후 방식 변경은 해당 데이터 기준으로 검토한 새 revision으로 남긴다. 백테스트 후 포워드를 수행할 때도 두 실행의 방식·시점·계획 변경점을 구분한다.

백테스트는 과거 기준 봉까지의 정보로 계획을 확정한 뒤 고정된 이후 구간을 한 봉·자동 재생·일괄 실행한다. Binance는 과거 기준 봉 시작 시각과 1–4000개 관측 봉을 선택한다. 더미 화면은 8번째 기준 봉과 이후 4봉을 기본값으로 제공하고, 다른 기준 봉과 남은 범위 안의 관측 봉 수를 선택할 수 있다. 구간이 부족하거나 아직 확정되지 않았으면 오류로 알린다. 계획 확정 전 미래 OHLC는 전달하지 않는다.

포워드는 확정 당시 최신 Binance 봉을 기준으로 이후 새로 마감된 봉만 관측한다. 초안 이후 새 기준 봉이 생기면 확정을 거절하고 최신 데이터로 초안을 갱신해 다시 검토한다. 더미 포워드는 순차 입력 시뮬레이션으로 표시한다. 상세 화면에서 시작한 자동 감시는 60초마다 새 봉을 조회하며, 이동하거나 닫으면 멈춘다. 재방문 후 사용자가 재개한다.

전략 → 계획 revision → 실행(runId)별로 기록을 보존한다. 오류는 실행에 저장되어 재방문 후 원인을 확인하고 재개할 수 있다. 기존 경제적 상태·관측 봉은 실패한 조회 때문에 진행되지 않는다. 백테스트 구간 종료 시 미진입은 EXPIRED, 보유는 OPEN/미청산 손익이며 강제 청산하지 않는다. 실현·미실현 손익과 R, 기간·봉 수, 체결 가정과 판정 불가를 함께 표시한다. 단일 실행 결과를 승률·수익성으로 일반화하지 않는다.

실제 주문 없이 long 매수 스톱, 수량 1, 수수료·슬리피지 0의 모의매매다. 저장은 로컬 단일 서버 범위이며 서버 상시 감시는 제공하지 않는다. [설계·수락 기준](../design/standalone-strategy-workspace.md)에 상세 계약을 기록한다.
